# 音频素材入库 Spec

## 背景

当前音频入库设计误把需求建模为 ASR 转写入库，主流程围绕 transcript、utterances、LAS ASR 任务和解析重试展开。但 V0.1.1 的真实需求不是识别人声内容，而是把可用于短剧生产的音色参考和背景音乐素材进入素材库，让用户可以上传、登记、检索和后续引用。

音频入库的主对象是“音频资产”。音频资产的正式事实来自用户提交的名称、描述、业务分类和音频专属结构化字段；系统第一版不自动识别音色、不自动识别音乐、不执行 ASR。

## 目标

- 让用户可以把音色参考和背景音乐文件作为个人音频资产入库。
- 入库成功后立即创建音频资产和音频媒体，资产可在素材库展示和检索。
- 用名称、分类、通用描述和音频专属结构化字段生成资产级检索文本。
- 新增音频资产遵守统一资产分类口径，不制造 `voice`、`music` 等新的资产大类脏值。
- 保持音频入库为非付费、非生成动作，不触发 ASR、自动音乐识别、自动音色识别或任何生成任务。

## 功能需求

- F1: 系统提供音频入库入口，支持登记已有对象存储音频。
- F2: 系统提供音频上传入口，一次只接收一个音频文件。
- F3: 系统只接受 `wav`、`mp3`、`ogg`、`opus` 四种音频格式。
- F4: 系统不做音频转码，不接收其他格式后再转换。
- F5: 音频入库成功后创建音频资产和音频媒体，不创建异步解析任务。
- F6: 新增音频资产固定属于“音频”大类，媒体类型固定为音频。
- F7: 新增音频资产的业务子类只能是“音色”或“背景音乐”。
- F8: 普通音频入库不自动写生成引用角色或引用用途。
- F9: 音色资产接收音频专属结构化字段：`voice_traits` 和 `speaking_style`。
- F10: 背景音乐资产接收音频专属结构化字段：`music_traits`、`tempo` 和 `usage_scene`。
- F11: 通用描述继续使用资产已有描述字段，不在 metadata 中重复保存。
- F12: 音频专属结构化字段保存到资产和媒体 metadata，并参与资产级检索文本生成。
- F13: 入库成功后触发资产级向量同步；向量同步失败不回滚 PostgreSQL 创建结果。
- F14: 用户只能创建和查看自己有权限访问的个人音频资产。
- F15: 入库接口返回创建完成结果，包含资产 ID、媒体 ID 和对象存储信息，不返回任务 ID 或队列状态。

## 非功能需求

- N1: PostgreSQL 是音频资产、媒体、metadata 和入库结果的正式事实源。
- N2: Milvus 只保存可重建的资产级检索投影。
- N3: 日志不得泄漏 API key、预签名音频 URL 或供应商原始响应全文。
- N4: 新增写入必须收敛到新分类口径；历史 PostgreSQL 脏数据允许继续读取和混跑。
- N5: 音频入库不得触发任何付费生成动作。
- N6: 音频入库不得触发 ASR、自动音色识别、自动音乐识别或其他自动分析任务。
- N7: 第一版只写个人资产，`visibility` 为 `personal`，创建后状态为 `approved`。

## 不做的事

- 不做 ASR，不保存 transcript 或 utterances。
- 不接入 LAS 音频 ASR，不创建音频解析 worker。
- 不做自动音色识别、自动音乐识别、自动打标或自动字段回填。
- 不提供音频入库任务列表、任务详情或重试端点。
- 不接收 `m4a`、`aac`、`flac`、`pcm`。
- 不做转码。
- 不复用生成音频候选生命周期。
- 不建立音频片段独立表。
- 不做片段级向量检索。
- 不做额外 LLM 丰富。
- 不清洗历史 PostgreSQL 脏分类。
- 不在本任务里修正视频分类落库。
- 不在第一版提供公共资产写入路径。

## 验收标准

- AC1: 提交已有 `wav/mp3/ogg/opus` 音频后，系统创建音频资产和音频媒体，并返回 `201`、资产 ID、媒体 ID 和对象存储信息。
- AC2: 上传单个 `wav/mp3/ogg/opus` 文件后，系统写入对象存储，创建音频资产和音频媒体，并返回 `201`、资产 ID、媒体 ID 和对象存储信息。
- AC3: 提交非法格式时，系统拒绝请求，且不创建资产和媒体。
- AC4: 新增音频资产落库为“音频”大类，业务子类只能为“音色”或“背景音乐”。
- AC5: 普通音频入库的生成引用角色和引用用途为空。
- AC6: 音色资产 metadata 只保存音频专属结构化字段 `voice_traits` 和 `speaking_style`，不重复保存通用描述。
- AC7: 背景音乐资产 metadata 只保存音频专属结构化字段 `music_traits`、`tempo` 和 `usage_scene`，不重复保存通用描述。
- AC8: 入库成功后资产可被素材库展示和检索，检索文本包含名称、分类、通用描述和音频专属结构化字段。
- AC9: 向量同步失败不会回滚已经成功创建的 PostgreSQL 资产和媒体。
- AC10: 音频入库不会创建 `audio_ingest_tasks`、不会提交 LAS ASR、不会启动音频解析 worker。
- AC11: 用户只能通过音频入库创建自己的个人资产，不能通过该入口创建公共资产。
