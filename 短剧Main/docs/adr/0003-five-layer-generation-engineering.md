# ADR-0003:多模态生成按五层工程做,借鉴 LLM coding 的演进但不照搬

- 日期:2026-07-29
- 状态:已接受(DC 拍板)
- 决策人:DC;架构:Fable

## 背景

DC 2026-07-29 提出:

> 「生图生视频生音频都是生成式模型,而关于如何让生成式模型提升性能,在 LLM 这里依次发展了
> prompt → context → harness → loop → graph engineering。所以,多模态生成的工程和产品原则,
> 可以借鉴 LLM coding 的最新实践和思想。」

这条与 V-11(2026-07-24,DC 说过两次而一直没进任何原则文档)是同一件事的两次表达:

> 「生图生视频你当做一个 context engineering 就行,我们平台就是要**简化人脑对于 context 的
> 思考难度和管控难度**,尽量让使用者舒服、高效。」

## 决策

**平台按五层组织生成能力,每层有独立的产品形态与验收判据;版本计划的每张生成类卡必须能说清自己在哪一层。**

| 层 | 解决什么 | 我们的对应物 |
| --- | --- | --- |
| **prompt** | 一次调用怎么说清楚 | 自动填充段 + 人的补充段(V-10);提示词模板化 |
| **context** | 给模型带什么材料 | 参考控制包:角色/场景/道具/光影/色卡/镜头(六组词表) |
| **harness** | 出来的东西对不对 | 机器判据 + 人判分层(见下「三条不照搬」第 1 条) |
| **loop** | 不对怎么收敛 | 廉价代理先行、按判据自动重试、失败原因回传 |
| **graph** | 多步骤多镜头怎么编排 | 画布与流水线(ADR-0001);跨镜头一致性 |

**当前实况(2026-07-29 自评)**:context 层最成熟,prompt 层有设计缺实现,
**harness 与 loop 两层接近空白**,graph 层在建。**空白的两层是眼下杠杆最高的地方**。

## 三条不能照搬(每条都决定产品形态)

### 1. 多模态没有编译器 —— harness 必须分层

LLM coding 的验证便宜且客观(编译器、测试、类型检查),多模态没有等价物:
「这张图好不好」不存在自动判据。

**因此我们的 harness 分两层**:
- **可算的自动挡**:人脸/角色一致性、色板偏离、构图规则、分辨率与画幅、
  音画时长对齐、AIGC 标识完整性、未过审资产混入(V-19,同时是钱的安全);
- **不可算的交给人**:美感、戏感、表演、节奏。

**产品设计的核心动作是:把可算的自动挡掉,让人的注意力只投给不可算的部分。**
harness 不是「加个审核按钮」,是「让人少看 90% 的废片」。

### 2. 迭代经济学反过来 —— loop 要用廉价代理

LLM 试十次选最好是常规操作;视频生成一次几分钟、几块钱,试十次就是烧钱。

**因此 loop 的正确形态不是「多试几次」,而是「用廉价代理构建 loop」**:
低分辨率/低帧数先出运镜与构图,人确认后再用贵模型出成片(V-09,DC 2026-07-22 已提)。
**V-09 因此从一张普通卡升格为 loop 层的地基。**

推论:**每个生成动作都要能回答「这一步的代理是什么」**。没有廉价代理的能力,loop 就退化成抽卡。

### 3. context 是选择不是堆砌 —— 上下文窗口的差异

LLM 上下文能塞几十万 token;seedream 只收有限几张参考图,视频模型更少。

**因此多模态的 context engineering 核心动作是压缩与取舍**:
同一角色的十张参考里选哪三张、光影与色卡如何合并成一条描述、哪些控制包本次不带。

这正是 V-11「简化人脑对 context 的思考难度和管控难度」的技术含义:
**不是让人少填,是替人先选好**,并把「为什么选这三张」说清楚(可解释、可覆盖)。

## 后果

**得到的**:
- 版本计划有了一把统一的尺子:每张生成类卡必须说清在哪一层,层内判据一致;
- 空白层暴露得早——harness 与 loop 的空白正对应总目标里最贵的人时(抽卡);
- 与 ADR-0001(画布引擎)咬合:画布是 graph 层的形态,流水线是它的模板。

**付出的**:
- 五层是分析框架不是目录结构,不许照着建五个模块——**这会造出为架构服务的产品**;
- 每层都要独立验收判据,写卡成本上升。

**约束(后续包必须遵守)**:
1. 生成类卡在卡文里写明所属层;跨层的拆开;
2. harness 类能力必须区分「机器判据」与「人判」,不许把不可算的伪装成自动;
3. 新增生成能力必须回答「它的廉价代理是什么」,答不上来要在卡里写明为什么没有;
4. context 类能力必须可解释可覆盖(告诉用户带了什么、为什么、能改)。
