## 发布前硬闸门

1. `app.schema_migrations` 的 `001`--`013` 与当前 SQL 校验和一致。若 `013` 仍未写入，使用具备目标库 DDL 权限的受控迁移账号执行；**只读审计账号不可代替**。
2. KMS `shortdrama/test/runtime` 检查五个启动必需键均存在且非空：`ARK_API_KEY`、`TOS_ACCESS_KEY`、`TOS_SECRET_KEY`、`MILVUS_PASSWORD`、`POSTGRES_PASSWORD`；启用音频能力的测试站还必须有可选键 `SEED_AUDIO_API_KEY`。只核对键名与非空状态，不输出值。
3. 更新 `deploy/k8s/base/deployment.yaml` 的两个镜像 tag/digest 与两处 release-commit annotation；不得使用浮动 tag。
4. 核对 `deploy/k8s/base/configmap.yaml` 中的 RDS 私网地址、数据库用户及 Milvus 地址/用户与环境实值一致。`POSTGRES_SCHEMA=app` 不得改回退。`POSTGRES_SSL_MODE` 在 base 是 `disable`——2026-08-11 实测集群里那个消费本 ConfigMap 的 Deployment `shortdrama-main` 没挂 CA 卷,填 verify-full 即断库(issue #239)。整包发布路径必须是 `verify-full`(`secret-init/main.go` 读到别的值直接退出),所以发布前要么先把 `rds-ca-configmap.yaml` 与卷挂载真做进集群、再把 base 改回 verify-full,要么就不走整包 apply。dev/prod overlay 已各自钉死 verify-full。
5. 在 `rds-ca-configmap.yaml` 灌入当前 RDS CA（公共证书材料）；部署前确认 CA 未过期。
6. VKE `shortdrama` 集群的 `vci-virtual-kubelet` 与 `alb-ingress-controller` 必须为 `Running`。

## Day-0 管理员

生产注册保持关闭。先在部署配置中把首位管理员的**用户名**写入 `ADMIN_USERNAMES`，然后由具备数据库写权限的受控终端执行：

```bash
node --import tsx scripts/bootstrap-production-admin.ts \
  --apply --confirm CREATE_INITIAL_PRODUCTION_ADMIN \
  --username <lowercase-admin> \
  --display-name <display-name> \
  --password-file /var/lib/shortdrama/day0-admin-password
```

脚本只在用户名已列入 `ADMIN_USERNAMES`、用户尚不存在、且指定绝对路径时写入；随机密码只落到本机 `0600` 文件，不输出、不进数据库明文、不进日志。DC 首次登录后立即改密，并删除该受限文件。**本次上线前置包未执行这一步。**

KMS 凭据 `shortdrama/production-admin`(username=admin,密码已生成入库;与运行时

## 部署

### 流水线

1. 选择 `v0.1.2` 的不可变 commit / image digest。
2. 运行构建与 `deploy/k8s/verify-rendered.sh` 门禁。
3. 用 `deploy/k8s/overlays/test` 的 kustomize 产物部署到 `shortdrama`。
4. 等待 Deployment 就绪；禁止以探针失败时的强制重启替代根因排查。

### 手动路径

仅在已批准的维护窗口、且上述硬闸门全绿时：

```bash
kubectl -n shortdrama apply -f /restricted/release/v0.1.2-rendered.yaml
kubectl -n shortdrama rollout status deployment/shortdrama --timeout=5m
kubectl -n shortdrama get pods,svc,ingress
```

`/restricted/release/v0.1.2-rendered.yaml` 必须是同一份已经通过
`deploy/k8s/verify-rendered.sh` 的最终清单；不可直接把仍含占位符的仓库基础清单 apply 到集群。

## 部署后冒烟

1. 健康端点返回正常，且探针连续通过。
2. 在 `app` schema 查询迁移账本（`app.schema_migrations`），确认 `001`--`013` 校验和匹配。
3. Day-0 管理员能登录；注册接口仍拒绝未邀请用户。
4. 完成一条免费链路：登录 → 项目/资产列表 → 结构化检索降级或语义检索（根据 Milvus 勘察结论）。
5. 图片、视频、音频等任何付费生成均需另获 DC 的逐次「估价→确认→提交」授权；本次默认不测。

## 回滚

1. 应用故障：将 Deployment 回退到上一条**已验证 image digest**，等待 rollout 完成。
2. 数据库：迁移一律前进，不执行自动 down migration；013 若导致问题，暂停应用、保留现场，由数据库负责人拟定显式修复 migration。
3. 回滚后复跑健康、登录、迁移账本和免费链路。
