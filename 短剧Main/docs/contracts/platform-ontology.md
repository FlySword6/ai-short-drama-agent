# 平台本体论(对象·关系·动作·约束,2026-07-23 首版)

背景:DC 7-23 指令(台账条 39)——"功能、选项、页面等,彼此的对象、关系、
动作和约束,必须要有本体论的超图来承载"。直接诱因=「新建人设」类型里能选
场景/道具:动作承诺了对象类型,选项集却开放全集。这类失配靠逐页救火治不完,
根治=平台本体显式化:**新功能对着本体长,走查对着本体验,合同引用本体**。

本文件是全部交互合同的上位真源。地位:①各版本合同(v0.1.1/v0.2.0/v0.3.0)
的对象与关系定义与本文冲突时,以修订后的本文为准并回改合同;②Kimi/Sol 工作
包涉及新对象/新动作时,goal 必须引用本文对应节;③全站走查(#30)按本文
第五节违例清单销项、按第四节规则扫新增。

## 一、对象(节点)

每个对象=身份(表/主键)+生命周期(状态机)+归属(所有权链)。

**叙事域**(作品结构,树状):
- 项目 project(题材/负责人/团队归属→运营底座合同)
- 集 episode(短剧交付单位,必须;剧本集/空白集两来源)
- 场景 scene(可空——短剧按集交付,场景是可选中间层)
- 分镜 shot(生产最小编排单位)
- 粗剪素材(shot 下的生产工位:1/2/3 序列,产物容器)

**资产域**(可复用参考,图书馆):
- 资产实体 asset_entity,**13 类两族**(实体参考族:character/scene/prop/
  costume/animal…管画面里有什么;抽象参考族(0.3.0 补全):lighting/camera/
  色卡/负面约束集…管怎么拍什么味;媒介类:video/sound/music/keyword/
  reference/model_3d)。类型枚举全站同源(ASSET_KIND_DEFS,后端为准)。
- 资产变体 variant(0.3.0 升格「角色×造型」二级:变体继承角色身份,
  差异在服装/状态)· 资产媒体 asset_media(版本序列,主图)
- 归属两级:项目资产(本剧)/通用资产(全局资产中心);互为引用不混同

**生产域**(一次生成的因果链,严格有向):
- 控制包 control_package(工作台就绪引用凝固而成,**参考控制的唯一来源**)
- 能力档 tier(pricing_rules.metadata 投影,选档不调参)
- 报价 quote(时效,一次性消费)→ 生成请求 request → 尝试 attempt →
  媒体产物 media_result(回挂粗剪素材/分镜)
- AI 调用 ai_call(0.2.0 网关,逐笔记账)

**运营域**(人与钱):
- 用户 user(平台角色)· 团队 team · 用户分组 group(标签,不鉴权)
- 项目成员 project_member(owner/editor/viewer)
- 成本条目 cost_entry(任务记录即账本,视图聚合)
- 审核策略 review_policy / 审核动作 review_action(四态)
- 回收站条目(三分组:项目/个人资产/项目内单删,30 天 TTL)

## 二、关系(超边)

1. **包含链**:project ⊃ episode ⊃ (scene?) ⊃ shot ⊃ 粗剪素材 ⊃ 产物。
   界面上每一层必须可见其上级路径(素材上下文=哪集哪镜哪场景)。
2. **引用关系**(资产→生产):已匹配/推荐资产=**草稿候选**;工作台就绪
   引用=控制包成员(职责分组+确认凝固)。**候选≠成员**是铁律(台账条 38):
   任何"参考集"展示与提交,取数源只能是控制包,不能是候选池。
3. **生产因果**:产物 = f(控制包, 提示词, 档位)。界面必须表达输入→输出
   流向(生成输入组→产物区),不许平铺。
4. **账务归属**:每笔 request/ai_call → user × project × model × tier;
   三处成本消费面(项目概览/成员排行/后台列表)同源一个视图。
5. **版本关系**:媒体/变体/声音(0.2.0)都是"对象×用途"下的版本序列,
   状态机=候选→已选→锁定(→转资产)/废弃;按对象管版本,不按散文件。
6. **审核关系**:资产/产物状态迁移必经审核动作留痕;临时使用可直通,
   锁定/转资产/入通用库必送审。

## 三、动作(带类型签名)

动作=动词×对象类型×前置状态→后置状态。**动作的文案是它的类型签名**:
名字里承诺了什么对象/类型/状态,交互就必须锁定到那个子集。

例:「新建人设」=create(asset_entity, kind=character)——kind 已被动作名
绑定,不得再给全类型选择器;「创建道具」同理;自由选类型的动作只能叫
「新建资产」。「生成视频」=generate(video, 素材上下文)——生成方式(按图/
纯文字)是参数不是入口,入口按对象任务长,不按技术能力长(条 18)。

## 四、约束通则(走查与新功能的检查表)

R1 **动作-类型锁定**:动作名点名了对象类型/状态,选项集即锁定该子集。
R2 **候选≠成员**:参考集/提交链取数源=控制包;候选池只进选择流程。
R3 **入口意图分化**:不同意图(浏览挑选 vs 智能推荐)不得复用同一界面;
   同一事物也不得有两处割裂表达(数字条 vs 左栏)。
R4 **列表必分页**:一切列表类界面必须分页/虚拟滚动+类型过滤(槽位感知:
   角色槽只列角色)。
R5 **死胡同动作显式化**:流程未接的动作,要么不出现,要么明确标注缺口
   并给替代路径;禁止假可用(mock 红线同源)。
R6 **命名同源**:同一对象全站一个名(项目内「本剧资产」vs 全局「资产
   中心」);开发词(基线/定版/mock)不进用户文案。
R7 **配方服务端化**:提示词组装/参数推导/档位规则/权限矩阵在服务端,
   前端入口显隐≠鉴权(条 30)。
R8 **上下文可见**:任何对象详情必须展示其包含链位置与被引用计数
   (引用追踪:被 N 个控制包引用,改动提示重检)。
R9 **创作词表不冻结**(2026-07-24 DC 拍板):枚举只冻结系统不变量
   (状态机/钱/权限/协议);创作词汇(参考栏 lane、资产 role、题材等
   "参考物是什么/给谁用")一律词表化为数据,新词条零迁移可增;模型
   相关扩展走能力档。判据与全库分类:docs/design/creative-vocabulary-openness.md。
   **补充(2026-07-26)**:关系(谁能指向谁)与 jsonb 契约结构**属于不变量**,
   要受控且可自动校验;被关联对象的**分类名称不属于**不变量。也就是说"硬"的
   不是分类树,是关系和契约。此前只写了"枚举",漏了关系这一维——
   于是出现了 clearance 这类只有类型声明、写入路径无强制校验的字段。
R10 **关系先行**(2026-07-24,依据真实生产资料):生产对象间关系
   (角色-场景-服装-集-镜-控制包)由人在前期设计建立,是生产输入不是
   系统输出;「匹配」=按设计关系引用+候选推荐,**系统绝不自动绑定**
   (条 38 同源);导入必须解析并落库关系,不确定的进候选区人工裁决。
   详:docs/design/pre-production-design-workflow.md。

## 六、治理机制

1. 新工作包 goal 涉及对象/动作的,引用本文节号;验收按 R1-R8 抽查。
2. 本体变更(新对象/新关系/新约束)=修订本文+受影响合同,同 commit。
3. 违例修复的回执,在第五节表格标状态(修复 commit/回执链接)。
