# 测试与验收合同

## 测试层级

- 单元测试：业务规则、状态机、权限、费用、提示词结构和转换函数。
- 合同测试：API schema、模型适配器、Pi 工具、TOS/Milvus 边界和错误映射。
- 集成测试：Fastify + 测试数据库，覆盖认证、写入、幂等、恢复和降级。
- 端到端测试：真实构建后的浏览器，从登录走到资产、导演台、人工生成和任务结果。
- 真实验收：公网部署、真实账号、真实供应商和 TOS；它不能由本地测试替代。

## V0.1.1 主验收路径

1. 登录后按角色看到对应工作入口。
2. 创建/打开项目，进入生产首页而不是管理后台。
3. 上传图片或 Excel，看到解析状态；Milvus 不可用时仍可完成入库和基础检索。
4. 自然语言检索资产并加入项目。
5. 打开 3D 导演台，摆放对象/镜头，保存场景并生成快照，快照进入素材引用。
6. Pi 能读取当前项目和导演台上下文，完成检索或安全操作，并生成结构化图片/视频草稿。
7. 只有用户点击后才创建一条图片或视频任务；刷新页面后任务仍可恢复。
8. 成功结果持久化到 TOS 并成为候选版本；失败显示可执行的原因和人工重试入口。
9. 人选择主版本并完成交付判定；系统记录责任人和时间。

## 必测非理想状态

未登录、无权限、空项目、文件不支持、解析部分失败、TOS 失败、Milvus 不可用、模型不可用、预算阻止、重复点击、任务超时、刷新恢复、版本冲突和回收站恢复。

审核与测试域还必须覆盖：图片/视频策略互不串用、缺省待审、重复批量资产、拒绝缺原因、终态冲突、测试更新版本冲突、无权参考素材、来源任务与结果不一致、结果尚未持久化、重复挂接，以及“保存测试/设默认均不创建任务”。

反馈后端还必须在真实 PostgreSQL 覆盖：同一用户并发复制同一通用资产只产生一个个人副本、变体与媒体引用完整、TOS 对象 key 不变化、来源追溯可查；事件由登录用户绑定、UTC 跨日聚合正确、非管理员不能读取聚合。

## 企业微信登录追加验收

- 单元/合同测试覆盖授权 URL、服务端开关与配置 fail-closed、token 缓存单飞与超时、供应商错误映射、站内 `return_to`、state/nonce/result 的 hash、TTL 和单次消费，以及敏感值扫描。
- 真 PostgreSQL 覆盖并发首次登录只创建一个用户和一个身份、身份冲突不迁移绑定、事务回滚不残留有效 session、禁用用户拒绝 exchange、nullable password 用户不能密码登录，并回归邮箱/密码、CLI、Agent 凭据与生产单活 session。
- 新增的 `test:wecom-auth-db` 必须进入 `npm test`，在 `pull_request` 上拥有实际运行且失败会标红的独立 PostgreSQL job，并进入 dev-push 汇合检查；`npm run check:ci-db-coverage` 必须通过。只在 push 后的 `verify-postgres` 运行不构成 PR 闸。
- 前端覆盖能力读取中/关闭/失败、跳转中、用户取消、state/result 过期、应用不可见、供应商不可用、账号禁用、重复 exchange，以及 Full/Lite 按服务端 `ui_mode` 进入；保留邮箱注册登录、logout 与 401 重登回归。
- CI 只使用 fake provider 和固定合同响应，不连接真实企业微信。测试环境人工冒烟使用专用自建应用和少量内部成员，覆盖桌面端、移动端工作台、普通浏览器、首次开户、已有身份、Lite 用户、取消授权、移出可见范围、关闭开关；证据只保存日期、脱敏 request ID、结果和无敏感参数截图。
- 上线前必须核实目标企业的官方授权 URL、回调域、应用可见范围、`userid` 返回形态与成员资料权限；未取得可理解显示名时即时开户验收失败，不能用 `userid` 充当显示名。
