# 数据建模规约(v1,2026-07-28 Fable 立)

**适用范围**:所有新增/修改 PostgreSQL 表结构、词表、跨存储投影的任务包。
**判据来源**:2026-07-28 两份实况盘点(`outputs/opus-db-inventory-20260728.md`、
`outputs/opus-storage-ontology-audit-20260728.md`)——本规约每一条都对应一个已经踩到的坑,
不是凭空立的规矩。

---

## 一、什么该冻结,什么该开放(第一原则)

DC 范式(R9,长期有效):**只冻不变量,创作词汇全部词表化。**

| 类别 | 处置 | 例 |
| --- | --- | --- |
| 钱、权限、状态机 | **冻结**:库级 CHECK + TS 联合类型,改动必须走迁移与评审 | 报价状态、账目类型、审核态、用户角色 |
| 创作词汇 | **词表化**:落表 + 别名 + canonical,运营可加,不发版 | 资产类型、标签、角色域、参考通道、景别、焦段、姿态、画幅、模板类目、音色 |
| 供应商能力 | **配置化**:落档位表/配置表,不进代码常量 | 模型、分辨率、时长、参考槽位上限 |

**词表化的验收标准是"端到端可用",不是"建了表"**:

1. 库:词表主表 + 别名(自指 canonical) + 业务表 FK;
2. 接口:**入参校验必须查词表,禁止 `z.enum` 复述词表内容**——这是当前最大批量的违规
   (`assets/routes.ts:45-52` 的 role 枚举导致新登记的词一用就 422);
3. 查询:检索/过滤路径必须走别名解析;
4. 前端:选项从接口取,不本地硬编码;
5. **一条测试**:新增一个词 → 不改代码即可创建、检索、展示。

违反其一即视为"没做完",不得标 DONE。

## 二、每张新表的最小要求

必须有:
- `id`:uuid 主键(与现役一致);
- `created_at` / `updated_at`:**带时区**(`timestamptz`)。现役资产域 8 列是无时区类型,属历史欠账,
  新表不许再犯;
- **归属列**:`owner_user_id` 或 `project_id` 至少其一,除非明确是全局配置表——权限与隔离全靠它;
- 真外键:引用别的表**必须建 FK**。禁止"用字符串软引用"(资产三层零外键已导致真库孤儿);
- FK 列建索引(现役 87 个 FK 列无前导索引);
- 需要软删的写 `deleted_at`,不需要就明确不写,不要留半套。

约束写在**库级**,不要只写在应用层:枚举用 CHECK 或 FK,唯一性用 UNIQUE,金额非负用 CHECK。
理由:ETL、脚本、DBA 手工操作都绕过应用层。

## 三、JSONB 的边界

JSONB 只放**不参与判定的附属信息**(供应商原始响应、扩展备注)。

**下列一律不许放进 JSONB**:决定价格的字段、决定权限的字段、需要唯一约束的字段、需要索引查询的字段、
需要外键的字段。现役反例:档位 ID 藏在 `pricing_rules.metadata->'capability_tier'->>'tier_id'`,
同一模型 6 条同时 active、价格 30/30/30/60/60/60,无唯一约束无索引——**价格靠一个 JSON 路径决定**。

## 四、金额与单位

- 对外与界面口径:**积分**(1 积分 = 0.01 元,R31);
- 库内存储:整数最小单位,列名带单位后缀(`_points` / `_fen` / `_usd_micros`);
- **禁止跨单位别名**:视图不许把 `cost_fen` 别名成 `charged_points`(现役 `cost_entries` 正在这么干),
  服务层不许把 points 输出成 `...CostFen`;
- 新增金额列必须同时登记单位与换算出处;涉及多币种时先加 `currency` 列再谈。

## 五、血缘与元信息

- **血缘是一等公民,不是 metadata 里的一句话**:资产/产物的来源必须是可查询的边
  (`parent_id` + `relation_type`,或独立的关系表),能递归到源头;
- 外来素材与自产产物必须在库里可区分,且**不可被下游加工洗掉**;
- 元信息的真源唯一:同一事实(标签、审核态、供应商 ID)只有一处权威,其余是投影;
  **投影必须带 `synced_at` 或校验和,并有对账手段**——没有对账就等于不知道自己是不是错的。

## 六、跨存储

- PostgreSQL 是唯一真源;向量库与分析库是**可重建投影**;对象存储是**内容载体**;
- 投影同步:失败必须可重试、可补偿(outbox 或任务表),**不许 `.catch(console.error)` 了事**;
- 键构造必须是**单一导出函数**,重建脚本、运行时同步、删除三处共用;
- 环境相关的名字(collection、桶前缀)取自配置且启动期校验一致,不许写死字面量;
- 删除任何共享对象前必须确认引用计数;删除路径统一,不许"看起来删了其实没删"。

## 七、迁移

- 前向单向 + 编号连续 + checksum 台账(现役纪律良好,保持);
- **迁移号由 Fable 统一分配**,任务包里写"暂定 NNN,以合流时为准";
- 无 down 是明确选择,但每个破坏性迁移必须在注释里写清回滚步骤(备份点 + 人工操作);
- **合流带迁移的包,必须同时说明三个环境谁负责升级**(今晚"代码新库旧"导致登录中断,就是没人定这件事);
- 漂移检查要检**真实库**,不能只比"schema.ts ↔ 迁移重放"(现役检查方向错误,真漂移永远绿)。

## 八、评审关

新增或修改表结构的任务包,回执必须包含一节「建模自查」,逐条回答本规约一至七;
Fable 验收时对照本文件,任一条未答或违反,整包退回。
