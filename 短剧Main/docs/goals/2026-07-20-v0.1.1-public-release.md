# V0.1.1 公网可用版实施目标

> **已被替代，不再是执行真源。** 2026-07-21 批准的新版五项目标已将生产部署改为
> VKE/VCI + HTTPS ALB Ingress + 私网 RDS + KMS/IRSA initContainer。本文以下 ECS/Compose、
> 公网 IP、G7 和发布步骤只保留为历史记录；当前执行以 `superseded_by` 指向的合同索引为准。

## 1. 目标

交付同一产品的三层入口，并部署前端工作台到火山云公网地址：

1. 前端工作台：统一的 React/Vite、Fastify、Drizzle/PostgreSQL 模块化单体。
2. CLI + Skill：调用 main OpenAPI 的薄客户端和可安装技能，不保存第二套业务事实。
3. Agent：main 内运行 Pi Agent；agent 仓保存可安装资源和合同，不运行第二套生产服务。

用户登录后必须能够完成真实的资产入库与检索、进入 3D 导演台、让 Pi 助手检索资产和操作导演台、手动发起已配置的图片或视频生成任务，并在刷新后继续查看结果。同一项目、资产、任务和权限在三层入口中必须一致。

完成不是“页面画出来”或“本地构建通过”。只有代码、数据、权限、任务、Docker 和公网真实操作都有证据，才能把状态改为 `done`。

## 2. 执行真源

发生冲突时按以下顺序处理：

1. 本目标和仓库根目录 `AGENTS.md`。
2. `PRODUCT.md`、`DESIGN.md` 与 `docs/contracts/v0.1.1/README.md` 指向的开发合同。
3. context 仓 V0.1.1 PRD、统一架构、多仓迁移合同和工作包。
4. 当前代码、丽芬 V0.1.1 原型和迁入代码。

集成线必须包含 `ef1483c`。旧仓、远端 NestJS 分支和其他代理的实现只能作为能力来源，不能改变目标技术栈或建立第二套业务事实。

## 3. 角色与责任

- DC：产品 Owner（负责人），批准范围、付费、破坏性操作和最终验收。
- Codex 主代理：架构与集成、后端核心工作包、冲突处理、完整验证、发布回执。
- Fable-5：深色登录与生产界面、资产前端和公共交互工作包。
- Kimi K3：3D 导演台迁移与适配工作包。
- Fable-5（EasyRouter，经 OpenCode CLI）：只读后台审查；不修改代码，不替 DC 决定产品范围。
- 子代理：只修改明确分配且互不冲突的模块，提交结构化回执；不能自行改变合同。

AI 可以实现、测试和建议，但不能替 DC 承担产品验收责任。

## 4. 范围内

1. 建立唯一 `integration/v011`，统一代码、数据库和部署配置。
2. 全站深色主题、新登录页、项目和工作区导航，不保留假按钮与假状态。
3. 复用并完善资产上传、解析、TOS 入库、PostgreSQL 正式事实、Milvus 语义检索投影和 PostgreSQL 降级检索。
4. 接入 3D 导演台：场景保存与恢复、结构化命令、撤销、截图入项目待审资产。
5. 统一图片模型接口：GPT Image 2、Gemini 图像模型、Seedream 5 Pro；实际供应商模型 ID 以运行时配置为准。
6. 统一视频模型接口：Seedance 2.0、HappyHorse 1.1。
7. Pi Agent Core 与资产、项目、导演台、生成准备、任务查询工具；每次工具调用有权限检查与回执。
8. 生图、生视频只允许人明确点击一次创建一次付费任务；前台不强迫逐次估价，后台执行预算、幂等和记账。
9. 单 ECS、Docker Compose、AMD64 镜像、公网 IP、强制登录。
10. 重构 `zhongwen-shortdrama-cli`：生产命令默认失败即停，统一调用 main OpenAPI；mock（模拟）只在显式离线模式。
11. 重构 `zhongwen-shortdrama-agent`：版本化 Pi Skill、工具合同、prompt 和安装清单；默认禁止启动 AgentKit/A2A 生产服务。
12. 补全 `zhongwen-shortdrama-eval`：无网络本地 runner、评分器、registry、最小评测集和四仓提交来源。

## 5. 本版不做

- 微服务、第二套 Python Web 服务、AgentKit、Supabase 或另一套认证/项目/任务系统。
- Seedance 2.5 的 30～180 秒长片自动生产。
- 生音频、自动剪辑、发布、夜间付费生成、自动重试付费任务和无人值守批量抽卡。
- V1.0 的完整本体、记忆、知识、智能调度和工厂化生产闭环；只保留可扩展接口。
- 以模拟响应、静态截图或当前旧公网版本冒充 V0.1.1 验收。
- CLI 直连数据库、TOS 或模型供应商；Agent 仓独立持有生产事实、生产密钥或对外运行 Web 服务。

## 7. 成功关口

### G0：基线与合同

- `git merge-base --is-ancestor ef1483c integration/v011` 返回成功。
- `npm run check:architecture`、`npm run typecheck`、`npm test`、`npm run build` 全部通过。
- 只有一套认证、项目、资产、任务和生成服务。

### G1：外壳、登录与权限

- 登录、退出、401 恢复、项目整卡进入、返回栈和按角色显示功能均可操作。
- 无权限、空、加载和失败状态都有真实行为，不显示无法使用的企业微信入口。

### G2：资产生产入口

- 用户可上传目标多模态资产，完成解析、TOS 入库、PostgreSQL 记录和项目引用。
- Milvus 可用时完成语义检索；关闭 Milvus 后，PostgreSQL 降级检索仍返回明确结果。
- 从导演台或生成工作区打开资产选择，加入后返回原工作位置。

### G3：3D 导演台

- 项目内可打开导演台，编辑并保存场景；刷新后恢复。
- Pi 的结构化 DirectorCommand 可执行、拒绝越权命令并支持撤销。
- 截图经后端进入当前项目待审资产，不以内存或本地假地址代替。

### G4：模型适配与付费任务

- 统一适配器合同、假适配器、输入限制和供应商错误映射测试通过。
- 每个已配置供应商至少完成一次最小真实调用，结果转存 TOS 并绑定项目资产；未配置供应商必须显示不可用，不能假装成功。
- Pi 只能准备提示词、参考素材、模型和参数；必须由用户点击后才创建一次任务。
- 重复点击、刷新、服务重启和供应商失败不会造成重复扣费或丢失任务状态。

### G5：Pi 生产工作区

- 自然语言可以检索资产、加入项目、查询任务、操作导演台和准备生成确认卡。
- 工具参数结构化，权限和项目边界测试通过，每次调用有可查询回执。
- 自动提交、自动付费重试和夜间付费生成测试必须被拒绝。

### G6：三层入口和独立评测

- CLI 无 main API 地址或认证时明确失败，绝不伪造成功；项目、资产、任务和生成准备命令均使用 main OpenAPI。
- CLI Skill 可安装、可列出版本和依赖，默认不触发付费动作。
- Agent 仓存在资源清单、Pi 兼容包和禁止第二生产运行时的门禁；默认启动 AgentKit/A2A 必须失败。
- Eval runner 可在无网络、无密钥、无付费环境运行，receipt 同时记录 main/cli/agent/eval 提交。
- V0.1.1 只要求资产检索、加入项目、任务查询、导演台命令和生成准备这五条主链能力；其他 CLI 命令、Agent 资源和评测覆盖后置。
- 主链工具至少有成功、失败和越权样本，静态 validator 不能替代 runner 结果。

### G7：Docker 与公网

- AMD64 Docker 镜像和 Docker Compose 冷启动成功，数据库迁移可重复执行。

- 用 Chrome 在公网地址完成同一条真实路径，并记录部署提交、时间、截图和失败项。

## 10. 停止条件

出现以下任一情况，暂停受影响的工作包并汇报，不用无关工作填时间：

1. 需要破坏未提交工作、正式数据或执行不可逆迁移。
2. 发现明文密钥、越权、跨项目数据泄露或生成任务可能重复扣费。
3. 迁入代码要求引入第二套生产技术栈或与合同冲突。
4. 下一次真实调用未获授权、费用无法估算或可能超过批准额度。
5. 公网部署无法确定目标提交或没有可行回滚点。
6. 同一公共文件被多个代理同时修改且无法安全合并。

一个工作包受阻不等于全目标停止；主代理继续推进其他独立工作包并记录阻塞。
