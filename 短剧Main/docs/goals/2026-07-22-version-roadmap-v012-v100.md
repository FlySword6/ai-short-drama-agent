# 版本路线图：0.2.0 → 0.3.0 → 1.0.0（semver）

命名遵循语义化版本（semver）：MINOR 承载新功能，PATCH 只留给缺陷修复。
因此 **0.1.x 系列 = 0.1.1 上线后的 hotfix 通道**（不排新功能）；控制资产类型化是新功能
＝ **0.2.0**；控制板三层模型＝ **0.3.0**；首个对内商用稳定版＝ **1.0.0**（此后接口兼容性
开始受版本约束）。git tag 采用 `v0.2.0` 形制，UI 版本徽章（登录页「V0.1.1 · 内部生产
工作台」）随版本发布同步。

状态：DC 已拍板（2026-07-22）：路线图整体照此执行；0.2.0 控制字段任务不等上线完成即开工；
1.0.0 商用口径＝对内优先、预留对外。控制包提案中的「V0.2」→ 0.3.0，「V1.0」→ 1.0.0。

（快照+维护窗）、付费验收的人工确认红线。以下排期均为「无外部阻塞的净工作日」。

## 3. 1.0.0「AI 片场全形态」——净 2–3 周，两个里程碑

### M1 智能生产（约 1.5 周）
1. 分段编排+失败隔离：段长按模型能力档自适应（2.0=4s 档/2.5=30s 档），交接状态衔接、
   失败只重做失败段（Sol 大件；2.5 的 30s 原生改变分段边界，隔离与成本控制价值不变）
2. 两道验收门实装：资产门+视频门，检查项由契约渲染，不做笼统验收（Sol+Kimi）
3. **Pi 组包**：Agent 直接 authoring IR——对话式把控制材料组装为控制包（IR），编译提交
   全程走 0.3.0 编译器；这是「Agent 接管」的落点（Sol 后端+Kimi 前端+Fable 编排设计）
4. 能力档位标注：真实视频/可执行资产包/静态运镜降级三档 UI 标签（Kimi）
5. 参考视频库规模化：批量入库、片段切取、动作打点（入库与随包生成 0.2.0/0.3.0 已通，
   此处只做规模化运营工具）（Sol）
6. 生成队列优先级+预算池（多人抢产能的调度）（Sol）

### M2 商用底座（约 1.5 周）——对内优先，预留对外（DC 拍板）

3. 跨项目风格记忆：风格包沉淀+embedding 检索复用（接控制包 role=style_env）（Sol）
4. 资产库规模化：分页虚拟化、检索缓存、TOS CDN（Kimi+Sol）
5. 安全加固：渗透面复查、限流、审计告警（Sol+Fable）
6. 公网商用验收：多用户并发真跑一部完整短剧（全员）
