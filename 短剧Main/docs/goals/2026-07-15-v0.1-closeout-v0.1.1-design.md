## 一句话目标

把现有 V0.1 从“能调用生成接口的工具”升级为自己团队可以持续使用的短剧生产系统：人负责主编、导演和最终判断，AI 负责准备草稿、组织剧组任务、后台执行和提醒人做决定。

本轮同时完成三条线：

1. 修复 V0.1 冷启动走查发现的阻断问题，锁定可回退基线。
2. 先冻结完整产品旅程和关键产品决策，再完成 V0.1.1 的设计系统与页面迁移。
3. 接入已经部署成功的火山持续交付环境，在真实部署地址完成安全、恢复和产品验收。

最终验收地址以 `http://shortdrama-main-test.col.com/` 为当前入口；HTTPS 证书完成后切换为 HTTPS。产品不对公众发布，只供受控团队使用。

## 产品定位与五个支柱

### 产品定位

这个产品不是“生成工具”，而是一个生产系统。人是主编和导演，AI 是剧组。

### 五个必须进入产品合同的支柱

1. **委托谱系**：PRD 中每项功能必须标注以下一档，不能只写功能名。
   - AI 全自动：索引、重试、记账、一致性检查。
   - AI 先做、人审：提示词草稿、分镜画面首版、批量候选。
   - 人主、AI 辅：选版、节奏、造型定版。
   - 人独占：交付判定、预算、发布。
2. **先有草稿**：核心生产步骤不把空白输入框丢给用户。系统根据项目、分镜和资产先准备草稿，人主要做修改和批准。
3. **前台心流，后台剧组**：批量生成、轮询、重试、记账和巡检在后台运行；前台只在需要人判断时提醒。
4. **判定收件箱**：主工作入口要能集中显示“等你拍板”的草稿、候选、冲突和失败，不把仪表盘当作主要工作界面。
5. **品味沉淀**：选版、提示词修改和打回理由应成为项目风格信号，使后续草稿更接近用户偏好。

五个支柱的方向已经确认；V0.1.1 做多深必须先写进 PRD 与 `journey.md`，由 Dario 批准后再改代码。特别是“判定收件箱”和“品味沉淀”可能新增数据模型，不允许以页面换肤名义偷偷扩大。

按顺序执行：

1. 修复 F-2：右上角导入动作在同页打开浮窗；跨页触发时进入分镜页并打开浮窗；关闭后清除界面意图参数且不污染返回栈。
2. 补足同页打开、跨页打开、关闭后返回、查询参数保留的测试，运行基础检查。
3. 用最新构建更新本地服务，请 Dario 复验 F-2。其余七条不阻塞回滚标签。
4. 复验通过后提交 `PRODUCT.md`、`DESIGN.md` 和设计系统合同。
5. 创建本地标签 `pre-v011-ui`，从该标签建立 `design/v011-p1`。
6. 建立 `docs/contracts/v0.1/journey.md`，覆盖 11 步旅程、唯一主动作、成功反馈、下一步、空状态、全站词汇和导航契约。
7. 在 context 仓建立 V0.1.1 产品范围与决策补充；先处理工作树归属，不能覆盖他人改动。
8. 核实 02 决策表、Excel XML 文件大小限制与测试、会议反馈、旧 Fable 分支归属。删除任何分支前另行确认。

### M1：产品范围与设计底座

- D8 至 D12 与五个支柱先形成可选择的范围提案，由 Dario 批准。
- 设计 token、字体、层级、焦点、状态色和减少动效规则落盘。

- 先迁应用壳、顶栏、生产进度、AI 助手工作区容器、提示和弹窗。

### M2：组件与状态

- 建立基础组件与业务组件，主操作、次级操作、禁用、加载、成功、失败、焦点状态统一。
- 主操作保留清楚文字；次级常用动作可用图标，但必须有悬浮说明、键盘焦点和无障碍名称。
- Storybook 覆盖合同状态和减少动效。
- 组件独立验证后再迁页面。

### M3：页面旅程与产品能力

按真实工作顺序迁移：

1. 登录、项目列表和判定入口。
2. 分镜总览：Excel 批量导入与手动建立的最终批准范围。
3. 资产：个人资产生成与参考资产试验的最终批准范围。
4. 分镜工作台：结构化提示词、图片、视频、选版与后台任务。
5. 视频库、主版本、连播和交付。
6. AI 助手工作区：上下文、任务、产物、待确认事项和历史。
7. 消耗看板与回收站。

必须同时完成：

- 导航顺序为分镜、资产、消耗。
- 交付清单始终可见，缺主版本时说明缺口。
- 禁用按钮说明开放条件；不保留无作用控件。
- 删除被五步生产进度替代的静态状态图。
- 每页只有一个主操作，且由当前生产状态决定。
- 每页先设计空状态和第一步；用户 3 秒内能说出自己在哪一步。
- 页面跳转用于切换长期工作上下文；浮窗用于短任务；抽屉用于不打断当前页面的辅助工作。返回必须回到真实上一工作位置。

### M4：回归与产品验收

- 固定产物：`frontend/shortdrama-rag-demo/e2e/v011-regression.spec.ts`、三分镜无私人信息样本、`npm run test:e2e:v011`、`docs/validation/v0.1.1/e2e-11-step.md`。

## 本轮不做

- 对公众发布产品。
- 微服务、多副本、高可用、大规模并发和完整企业权限体系。
- 自建第二套 ECS 或重复替换已经可用的持续交付平台。
- 真实部署 Milvus；V0.1.1 只证明无 Milvus 时可降级。
- 未经范围批准就实现 D8 至 D14。
- 与 11 步生产旅程和五个产品支柱无关的功能扩张。

## 每个里程碑的检查点

每完成 M0 至 M6 的一个里程碑，在 `docs/validation/` 记录：

- 代码提交、标签、部署运行号或制品标识。
- 执行过的检查与结果。
- 用户真实走过的页面和操作。
- 已通过、未通过和未验证。
- 本阶段费用。
- 风险、回滚点和下一步。

## 完成条件

只有以下条件同时满足，目标才能标记完成：

- G0 至 G7 都有直接证据。
- D8 至 D14 均有明确范围决定，已纳入本轮或明确进入后续版本。
- Dario 在真实部署地址通过最终产品验收。
- 产品不再以“报价后调用生成”为中心，而能清楚体现人做判断、AI 准备和执行、后台持续工作。
- 剩余风险、费用、回滚与后续路线已经写入检查点。

文件存在、代码能构建、单元测试通过、健康接口返回 200、部署按钮显示成功或单次生成成功，都不能单独代表目标完成。
