# V0.1 模块化单体实施目标

> 本目标已由 `docs/goals/2026-07-15-v0.1-closeout-v0.1.1-design.md` 接替。这里保留最初的范围和验收依据，不再作为当前执行目标。

## 目标

在 `zhongwen-shortdrama-main` 中完成一个可真实使用的 V0.1。网页、业务接口、生成任务和小龙虾助手放在同一个 Node 服务和同一个 Docker 镜像中。

V0.1 必须让至少一位一线生产同事能够独立完成以下真实任务：登录、创建项目、导入资产和分镜、生成三条分镜的图片与视频、查看任务状态、选择主版本、连续播放、下载媒体与交付清单，并通过右侧助手完成至少一次资产检索或生成操作。

## 唯一范围依据

- `zhongwen-shortdrama-context/docs/handoffs/2026-07-15-v0.1-review-pack/23-Fable-5-V0.1实施前审计Prompt.md` 中的“已经确认的 V0.1 决策”和“正式验收标准”。
- Fable-5 审计结果用于确定风险、顺序和验证方式，不替代已经确认的产品范围。
- 丽芬最终原型目录：`zhongwen-shortdrama-context/docs/design/all-prototype-png-v2/`。

## 已确认决定

1. 只在本仓新分支开发，采用模块化单体，不拆微服务。
2. `main` 是唯一业务后端，网页和 CLI 共用同一套接口。
3. 复用本仓资产入库、TOS、PostgreSQL、Milvus、语义检索和分镜 Excel 解析能力。
4. 复用旧仓已经验证的方舟 Seedream、Seedance 和任务查询实现，但不在旧仓开发。
5. 通用资产对所有登录用户可见，并可引用到项目；个人资产只属于当前用户。
6. 回收站属于 V0.1，允许排在演示后、正式验收前完成，不从范围删除。
7. 费用看板只显示可追溯的预估费用，并明确标注不是云平台实际账单。
8. 小龙虾在本仓中使用 Pi Agent 新建，只开放资产检索、项目资产引用、图片或视频生成、任务查询四类工具，不复用 `test-agent`。
9. 本次只做本机和局域网运行，不公开部署。

## 范围内

- 简单账号登录和会话。
- 项目、集、场、分镜，以及分镜 Excel 上传、预览、确认导入。
- 个人资产、通用资产、项目资产引用，角色、场景、道具，详情、版本和主版本。
- 真实图片和视频生成，任务进度、失败原因、重试、刷新恢复和服务重启恢复。
- 生成结果及时持久化到 TOS，不能长期依赖方舟临时地址。
- 三镜头连续播放、媒体下载和交付清单。
- 回收站查看、恢复、永久删除及引用安全检查。
- 数据看板、预估费用看板和可配置单价。
- 右侧小龙虾助手及受限工具。
- 单一 Docker 镜像。

## 范围外

- 微服务、公开云部署、企业级高可用和大规模并发。
- 文本生成、音频生成、复杂权限、审批流和团队角色体系。
- 全局风格、提示词管理后台、AI 日志页和完整画布工作区。
- 把模拟结果包装成真实生成结果。

## 产物

1. 分支 `codex/v0.1-modular-monolith` 上的可构建代码。
2. 编号数据库迁移、数据表说明、接口合同和任务状态机。
3. 按最终原型实现并可操作的核心页面。
4. 可运行的 Docker 镜像。
5. `docs/validation/v0.1/` 下的构建、接口、重启恢复、界面对照和真实生成验收证据。
6. 最终验收说明，包括已通过项、未通过项、费用使用和剩余风险。

## 验收关口

### G0 基线

- `npm run typecheck` 通过。
- `npm run build` 通过。
- 工作分支从最新 `origin/main` 建立。

### G1 公共合同冻结

- 数据库迁移可重复执行。
- API 的路径、请求、响应和错误格式确定。
- 任务状态统一为 `pending/running/succeeded/failed/cancelled`，每次重新提交生成新的 `attempt`。
- 登录、TOS 路径、预估费用和删除规则确定。

### G2 无付费链路

- 付费开关关闭时，生成请求被明确拒绝，不产生远端任务。
- 除真实生成外的核心流程可在本地完成。
- 任务持久化、幂等、失败和重启恢复有自动检查或可重复验证步骤。

### G3 界面与交互

- 核心页面按丽芬最终原型实现。
- 登录、建项目、资产、分镜导入、生成、任务、选主版本、连播、下载和助手主流程可操作。
- 使用同一视口对照原型和实际页面，修复影响使用和明显偏差的问题。

### G4 Docker 与局域网

- `docker build` 成功。
- 单一容器提供网页、API、小龙虾和任务处理。
- 第二台设备能通过局域网打开并走查已实现的核心流程。

### G5 真实付费验收

- 先完成一次低成本真实图片生成，确认任务落库且结果已转存 TOS。
- 再完成一次真实视频生成，确认长轮询、失败区分和重启恢复。
- 前两步通过且预算足够后，才执行三镜头完整验收。
- 真实生成结果、任务记录、预估费用和下载文件一致。

## 费用和安全边界

- 本次真实付费验收总上限为 5000 元；图片和视频调用都计入总额。
- 5000 元是绝对上限，不是应花金额或自动放行额度。先做一次最低成本真实图片验收；只有图片结果已转存 TOS 且可访问，才决定是否做一次 4 秒视频。
- 达到 5000 元立即停止所有付费调用；每次调用仍要逐笔报价和明确确认。
- 每次付费调用前记录模型、参数、预估费用和对应验收目的。
- 不读取或输出不必要的密钥值，不把密钥写入代码、文档、日志或 Git。
- 不复用 `zhongwen-shortdrama-agent/test-agent` 中的配置或凭据。
- 不执行公开部署、push 或生产环境修改，除非用户另行明确授权。

## 停止条件

出现以下任一情况时暂停相关动作并汇报：

1. 需要破坏现有数据或执行不可逆数据库迁移。
2. 发现新的明文凭据、越权路径或会扩大泄露范围的安全问题。
3. 预计会超过 5000 元预算，或无法可靠估算下一次付费调用费用。
4. 方舟、TOS、PostgreSQL 或 Milvus 的真实状态与本地合同明显不符。
5. 核心范围发生互相冲突的新决定。

## 检查点

每个阶段结束后更新本文件或对应验证记录：

- 当前状态。
- 已产生的证据。
- 已通过和未通过的关口。
- 已使用费用。
- 风险和阻塞。
- 下一步继续或暂停。

## 完成条件

只有在范围内产物存在、核心验收路径完成、最接近真实行为的检查通过、费用和风险如实记录后，状态才能改为 `done`。仅有页面、静态构建或模拟演示不能视为完成。
