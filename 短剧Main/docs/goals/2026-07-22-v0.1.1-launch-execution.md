## 1. 目标

在已集成五工作流的基础上，补齐两个产品后端缺口与控制资产类型化，并把云 RDS 只读盘点、
VKE 发布、Pi wrapper 真机切换整理成可以按步骤执行、可审计、可停止的上线执行链。

本阶段的本地终点是：A/B/C/D/E 五轨都有独立提交、验证证据、回执和授权门；不把执行册、
静态门禁或本地测试冒充真实云盘点、真实部署、真实 Pi host 或公网验收。

## 2. 固定边界

- PostgreSQL 是唯一业务事实源；TOS 保存媒体；Milvus 是可重建的检索投影。
- 生产目标为 VKE + VCI + 私网 RDS + KMS initContainer；Compose 只用于 dev/test。
- P1 数据真源方案状态按 Fable 书面批准记为 `PLAN_APPROVED`；目标 schema 默认 `v011`。
  `APPROVED_FOR_EXECUTION` 只在第 4.A 写前硬闸门全部通过后由 Fable 改写。
- 云上任何写动作、真实部署、token 轮换和付费调用必须另有当前动作授权。
- 云 RDS 只读盘点也必须记录执行时刻与目标指纹；授权前仅准备执行册。
- 付费动作保持“估价 → 人工确认 → 提交”，本 goal 不代点。
- 本地交付不 push；共享接线文件和 migration 编号由集成人最终落位。

## 3. 工作轨

### A · 两个产品端点

1. `POST /api/v1/assets/import-personal`
   - 把可访问的通用资产导入为当前用户个人资产；
   - 同源、同人重复导入返回既有记录；
   - 复用媒体引用，不复制 TOS 对象；
   - 初始审核状态为 `pending_review`。
2. 宫格切分产物“存为分镜图”
   - 先在 `docs/contracts/v0.1.1/api-and-data.md` 冻结请求与响应；
   - 输入为已登记的 `asset_media_id` 与 `shot_id`；
   - 服务端将资产媒体幂等登记为现有 `media_result`，并写入现有 shot-media 主版本语义，
     不建立第二套事实表、不伪造生成任务。

完成门：路由测试、PG-gated 真库测试、架构检查、类型检查、全量测试、构建通过；与当前
前端降级点的数据形状对齐；回执明确权限、幂等和未验证项。

### B · 云 RDS 只读盘点

授权前交付 runbook、gitignored 证据目录规则、去敏摘要模板和数据上云实册模板。

取得 DC 对“生产 RDS 只读盘点”授权后才执行：

```bash
npx --no-install tsx scripts/audit-cloud-rds-readonly.ts --scope cloud
```

必须证明 PostgreSQL/实例指纹、全部 schema/表、`common` 与 `public` 精确行数、migration
账本差异，以及“259 件既有云资产”的来源表、主键和精确计数。只读结果不得触发 migration、
import、Milvus 重建或任何写入。

### C · VKE 发布执行册

交付从现有持续交付流水线到 linux/amd64 镜像、CR `shortdrama-prod`、渲染门禁、
`kustomize` 发布的逐步说明；列出 KMS `shortdrama/v011/production` 五个键名和格式，
不记录值；提供健康、登录、资产列表、同 VPC Milvus 真语义检索的 smoke 清单。

最小付费 smoke 只提供申请话术；实际估价、确认和提交必须由 DC 另行授权。

### D · Pi wrapper 真 host 执行册

前置条件：agent 仓 `integration/v011` 已获 push 授权并可从目标机安全取得 wheel。

执行册覆盖 101.126.45.91 上 wheel 安装、systemd 单元、旧 `server.py` 停用、
`PI_REMOTE_API_TOKEN` 轮换、主仓 remote provider 真协议验收、降级锁定和审计真值断言。
允许的业务 skill 仅：

- `seedance2-all-reference-multishot-drama`
- `cinematic-portrait-softness`

安装前由 DC 目视确认。执行册准备不等于真机部署完成。

### E · 控制资产类型化

1. 在当前未上云的 migration `012` 中给现有唯一资产事实表 `asset_entities` 增加两个可空字段：
   - `role`：`character_identity`、`scene`、`prop`、`motion`、
     `camera_storyboard`、`style_env`；
   - `usage_mode`：`reference`、`first_frame`、`last_frame`。
   字段合同来自 `docs/proposals/control-package-model.md` 第二节；最终 migration 编号由 Fable
   集成人落位。可空是 V0.1.1 的零破坏兼容策略，旧 `null` 在生成校验中按 `reference` 解释。
2. 生成管线按资产事实校验：
   - `reference` 是主模式，参考集合允许图片和视频（动作/运镜）；
   - `first_frame` / `last_frame` 仅允许图片，只作可选高级锚帧；
   - reference 不得冒充首尾帧，首尾帧不得混进 reference 数组；
   - 3D 素模不得直接成为生成输入；
   - 违规返回 `422` 和简短中文提示，不进入报价确认或供应商调用。
3. 验证 provider 层对视频参考资产的组包和 `reference_media_ids` 透传；只准备最小付费
   smoke 的调用路径，实际估价、确认、提交仍由 DC/Fable 另行发起。

人工复验入口，以及是否发生 push、云写、部署或付费调用。

- A 轨两个端点及真库测试完成；
- E 轨控制资产字段、输入校验和视频参考透传测试完成；
- B/C/D 执行册和模板完成；
- 所有提交从 `e5f8aec` 可确定性集成；
- 仍保持无 push、无云连接、无部署、无付费调用。

### Checkpoint 2：云只读结果可审

- 仅在 DC 另行明确授权目标生产 RDS 只读盘点后进入本检查点；当前仍停在授权门前；
- 审计输出仅进入 gitignored 证据目录；
- 去敏摘要给出时间、目标指纹、259 定谳和 migration 差异；
- 任一指纹或 schema 与批准方案不一致即停止，不进入写窗口。

### Checkpoint 3：上线执行

- Fable 将数据计划改为 `APPROVED_FOR_EXECUTION`；
- VKE、KMS、RDS、agent 仓 push 与真 host 各自取得当前动作授权；
- 最小付费 smoke 另有人工确认；
- 执行后形成部署、协议与公网产品验收回执。

立即停止并汇报：需要云写、push、部署、token 变更、付费调用；生产指纹不符；259 来源无法
定谳；旧服务或旧 wrapper 无安全回滚锚点；需要覆盖他人未提交工作。
