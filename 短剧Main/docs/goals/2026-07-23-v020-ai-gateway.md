# V0.2.0 AI 网关与首批真实触点

状态：ready_for_fable_integration

Owner：Sol（后端工作包）；集成与验收：Fable；产品决策：DC

分支：`feature/v020-ai-gateway`（基线 `integration/v011@7707318`）

## 目标

交付服务端统一 AI 网关 `/api/v1/ai/*`，让提示词草稿和资产匹配两条产品触点使用真实 Ark
LLM 能力，同时留下可审计调用记录和每日调用护栏。

## 范围

- `ai_calls` 前向迁移和 Drizzle 真源：用途、模型、输入/输出 token、耗时、调用者、关联对象、
  状态与错误码；不保存提示词、完整输出或供应商原始响应。
- `POST /api/v1/ai/prompt-draft`：五层提示词草稿。
- `POST /api/v1/ai/asset-match`：现有受权限约束的语义/结构化召回初筛，LLM 仅从候选白名单
  中结构化重排并给一句理由；空库/无命中如实返回空态。
- AI 网关环境开关和按用户、按 UTC 日的调用上限；超限返回 429 人话错误。

## 不在本包

- 前端接线、任何媒体生成、自动提交、自动重试、实际付费 LLM 冒烟。
- 既有 Excel、视觉、Pi 等遗留直连 LLM 调用的全面迁移；其清单必须写入回执，后续统一迁入
  网关，不将其误报为已完成。
- 将未知 LLM 价格伪造为积分；本包记录 token 与可空费用状态，正式积分换算待价格合同。

## 成功门禁

1. 迁移 `014_ai_calls.sql` 可在本地 PostgreSQL 前向执行，schema 与仓储一致。
2. 两接口均要求登录；网关关闭返回 503，日限额返回 429；新增 `/api/v1/ai/*` 网关路径的每次
   实际模型或 embedding 尝试均写一条 `ai_calls`。
3. 草稿输出严格包含画面元素、光照、色彩、摄影质感、负面约束五层。
4. 资产匹配不返回假候选、未知候选、已删除资产或无权限资产；Milvus/embedding 故障必须沿既有
   PostgreSQL 降级路径。
5. 通过架构门禁、类型检查、相关单元/路由/真库测试、全仓测试与构建；失败项在回执如实说明。

## 风险与停止条件

- ARK key 只从环境读取，不写入代码、回执或测试夹具。
- 不触发任何真实模型调用；若需要真实调用、云写入、push 或部署，先停下并请求 DC 授权。
- 若 30 分钟没有新证据，切换排查假设或记录缺口，不用 mock 掩盖链路问题。
