# 第一性原理功能反思(2026-07-24,依据 DC 全天真实使用)

第一性:用户是短剧剧组(导演/美术/剪辑),要在 12 人时内做出一集能上线
的短剧。**每个界面、每个功能的存在理由,必须回答:它把哪个生产环节的
人时降下来了。**回答不了的,就是我们的自嗨。

## 一、今天的实测暴露了什么(证据链)

DC 以真实用户身份做了一场戏的备料:做道具参考图、做光影参考图、试生成
视频、建人设、建变体。每一步都撞墙:

| 他做了什么 | 撞了什么 | 病根定性 |
| --- | --- | --- |
| 做参考图后回工作台 | 任务去哪了?成没成?看不到 | 可观测性缺失:活儿没有"下落" |
| 从道具栏做的图 | 变成"关键帧"类型,道具栏空着"还没有道具参考" | 对象关系断裂:产物不回家 |
| 生成视频 | 道具图被擅自当首帧 | 系统替用户做错误决定 |
| 看资产详情 | "缺口已报 Sol" | 工程内部视角泄漏到片场 |
| 新建人设/变体 | 不能用/断头 | 能力型完成,不是走得通的完成 |
| 本剧资产待审核 | 工作台照样能用 | 关口形同虚设 |
| 写提示词 | 要自己从头写 | 平台该干的活推给了用户 |

## 二、四条病根(第一性反思)

1. **以数据模型为中心组织界面,不是以生产流为中心。**
   用户脑子里的流程是剧组工作流:备戏→拍→审→交。我们的界面是数据库表
   的 CRUD 投影:资产、项目、任务、版本。两个模型的断裂处,就是用户
   "迷茫"的位置。资产不是"一行记录",是"这场戏的一把刀"——它属于
   哪场戏、给哪个镜头用、审没审过、下一步谁碰它,这才是用户眼里的资产。
2. **合同实现了"能力",没实现"完成感"。**
   每个功能做到 API 通、测试绿就算交付。但用户要的是走得通:做了→看得到
   →回到该在的地方→知道下一步。产物不回栏、任务无下落、断头路,全是
   "能力有了、走不通"。**走得通才是功能的完成态,API 只是半成品。**
3. **把选择权错当成了体验。**
   用户不想选资产类型、不想挑提交模式、不想写论文级提示词。平台的定位
   (DC 拍板)是**降低人对 context 的管控负担**——正确姿势是把默认做对
   (来源栏决定资产类型、参考集默认多模态、提示词自动编译),把自定义
   做成逃生门,而不是把每个决定摆到用户面前。
4. **债务管理的工程视角泄漏到用户空间。**
   fail-closed 是工程美德,但"缺口已报 Sol"是把工程站会贴到了片场墙上。
   债务台账属于 repo,用户空间只允许两种状态:能用,或者用用户语言说
   "即将上线/联系管理员"。

## 三、优化主轴(即刻生效的排包原则)

1. **走通优先于新功能**:0.2.x 剩余包全部对准把断头补上(S16/S17/k3 b2
   已在打),断头补完之前不开新功能面(上线流程除外)。
2. **全流程剧本=最高验收标准**:定义「一集戏的一天」全流程——
   建项目→导入剧本→拆分镜→备参考(实体/风格/媒介)→做参考图→回栏
   →标就绪→生成粗剪→审核→交付。**每个版本发布前,用这个剧本从头走
   到尾,任何断点=P0。**此剧本同时进 Eval 线(离线断言版)和 DC 验收
   (真栈实走版)。
3. **默认智能、选择兜底**:每个交互设计先问"平台能不能替用户把这个
   决定做对";能,就做成默认+可改;不能,才暴露选择。已经做出来的实例:
   两段式提示词编译、参考集默认多模态、来源栏定资产类型(S16 修复中)。
4. **对象关系是产品骨架**:R8(上下文可见)从"违例清单一条"升为
   0.2.x 收口主题——每个对象页面回答三问:我从哪来/我被谁用/下一步
   干什么。后端明细接口(k3 包 3)+前端上下文条(S18)。

## 四、谁做什么

- S17(已立项):断头路回收+新建流修复+文案清扫,是主轴 1 的第一铲;
- k3 b2(在跑):默认多模态+提示词编译,是主轴 3 的后端底座;
- k3 包 3(增补):变体写入端点+分镜级使用明细接口(主轴 4 的数据面)
  +待审资产挂栏校验(关口闭合);
- Eval 线包 2(增补):全流程离线剧本;
- Fable:全流程剧本正文(独立文档,近日出)+每次收包验收含"走通三问"
  (做了→看得到→回得去)。
