# 0.3.0 工作台画布:三条设计原则(2026-07-23,DC 提供外部参考,Fable 消化)

来源:DC 转的无限画布应用提示词(Tauri 本地应用),技术栈不照搬(我们是 Web),
吸收其架构原则:

1. **单一文档真相源**:画布状态(节点/连线/嵌套)一个 store 管(项目内现用
   Zustand 同族方案即可),渲染层不持有第二份真相;
2. **几何与结构操作纯函数化**:平移/缩放/吸附/分组/嵌套全部纯函数,
   便于测试与撤销重做;
3. **UI 与自动化共用同一领域操作层**:抽一层 canvas-ops(读树/查找/受限写入/
   导出),用户交互和 Pi 组包(0.3.0)都走它——Pi 操作画布不单写一套逻辑,
   权限边界(受限写入)也在这层统一收口。

另记:分镜深度图(灰度景深)作为空间关系参考层的玩法已在 S6 做出来
(导演台白模深度通道直出,零成本);对生成的控制力按能力档解锁流程实测后定,
不预先承诺。

## 追加(R97,2026-07-30):零 chrome 候选路线

DC 转 Spatial(macOS 画布笔记)参考:「一块无限画布,空到不像个画布——无缩放比例、无小地图、无 toolbar」。
落到我们画布(v0.3.0)的候选原则:**画布默认零 chrome**——工具收进 ⌘K、右键与选中态浮层,
画布应读作「片场桌面」,不是「软件窗口」。与节点三段式通行语法不冲突:chrome 是壳,节点是内容。
实施时按「走通优先」再定取舍;手感层(拖拽物理感/动画曲线)与铺全站包的手感统一条同源。
