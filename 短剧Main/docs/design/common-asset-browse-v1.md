# 通用资产浏览:排序与筛选 v1(裁决稿)

- 日期:2026-07-31;裁决人:Fable(R130,DC 可驳)
- 来源:DC「通用资产筛选与排序设计输入」(2026-07-31,原文见附录)
- 范围:测试站「资产中心 → 通用资产」;后端参数与排序 + 前端控件与状态模型
- 地基事实:测试库约 955 个通用资产(其中 519 个为新导入的 3D 导演台资产,数字按 DC 输入采信,待核);
  服务端分页每页 24;现行顺序 `updated_at DESC, name ASC, id ASC` 是工程默认,本稿予以替换

## 0. 一句话

默认排序服务**复用效率**——让「能直接用」的资产先被看到;所有排序筛选**服务端执行**,
条件写进 URL,每种排序末位 `id ASC` 保证分页稳定。这与主轴一致:更丰富更高质量的资产库、
更全面的参考控制,带来更高的抽卡成功率——资产先被找到,才谈得上被引用。

## 1. 默认排序:「综合」

**产品目标**:用户打开通用资产库,第一屏应该是「最可能被直接引用到项目」的资产,
不是「最后被写库」的资产。

**定义**(ORDER BY 自上而下,全部服务端):

1. 有合格预览优先(合格预览的判据见 §5)
2. `use_count DESC`(采用次数,口径见 §2)
3. `updated_at DESC`
4. `id ASC`(终极 tie-breaker,所有排序共用)

**冷启动回落(如实声明)**:上线时无运营标注、`use_count` 全零,「综合」实际退化为
「已过审 + 有预览 + 新鲜」。这是诚实的降级——v1 的质量第一道闸是**超管审核**
(普通用户只见已过审,见 §4),不是算法。采用计数接上后第 2 层自动生效,不用改排序定义。

**运营精选不进 v1**:`curated_at` 字段需要迁移(039 实证 DDL 要手工执行件)+ 超管标注
界面 + 运营流程,三者都没有,现在加就是死列。列入 v1.1 增补,届时作为「综合」的第 0 层。

## 2. 「使用」口径(防第二套真源)

- **`use_count` = 采用次数**:「引用到项目」「导入为个人资产」两个动作各 +1。
  它是复用的**代理指标**,用于排序。
- **真实生产引用**(控制包引用/镜头/生成请求)由 `src/modules/assets/usage.ts` 的
  AssetUsageReport 现算,是**分析真相**,用于报表。
- 两者名分不同,不许混用:排序看 `use_count`,分析看 usage 报表。两边数字不同是设计使然,
  不是 bug。
- **累加是本卡验收项,不是配套可选**:两个动作接上累加之前,「使用最多」排序不得开放。

## 3. 用户可选排序(v1 = 2 个)

| 显示名 | 排序键 | 方向 |
| --- | --- | --- |
| 综合(默认) | §1 定义 | 固定 |
| 最新入库 | `created_at DESC, id ASC` | 固定 |

- 每档方向固定,**不提供升降序切换**(与 V-46「一参数一档」同一克制原则)。
- **暂不上的与理由**:「使用最多」——`use_count` 现在全库只有初始化为 0 的写入、无累加方
  (copyRepository.ts:83 / directorManifestImport.ts:249 / seedance-assets repository.ts:118),
  上了就是全零假数据;累加接上、数据非零后随小版本开。「最近更新」——只读库里与入库时间
  高度重合,无独立决策价值。「名称」——找已知资产走搜索。

## 4. 筛选模型

**常驻(首屏)**:

- 大类切换(已有):全部/角色/场景/道具…,带命中数徽标(语义见 §5)
- 媒体:全部 / 有图片 / 有 3D 模型——按 `asset_media.media_kind` EXISTS 判断。
  同一资产的图片与 3D 是**不同媒体不是两个资产**,筛选只影响命中不拆资产
- 搜索框(已有,`filters.query`)

**高级(展开面板)**:

- 细类 `category`(下拉,值取自数据)
- 风格标签(多选,同维度内部 OR)
- 来源资产库(`source_project`)
- **角色因子:性别 / 年龄段——仅当大类=角色时出现**。值域以资产因子字典 v0.2 为准
  (卡 asset-factor-dictionary),本稿不另造第二套。
  **已知限制**:因子筛选仅覆盖已标注资产;存量大量未标注(实证:剧本拆解产出的角色
  表单性别/年龄/描述全空,见 agent-pipeline-gaps 卡问题二)。界面上因子筛选要带一句
  说明「仅覆盖已标注资产」,否则导演筛「女」出 3 个会以为库里只有 3 个女角色。
- **审核状态:admin 专属**。普通用户服务端强制只见已过审,界面不出现状态筛选。
  判据组合:V-38(通用资产只有超管能审,权属)+ V-19(未过审进生成是钱的洞)+
  V-53(导演不该面对 pending/rejected 这类内部状态)。
- 「有无预览」不做用户筛选(「综合」已把无预览沉底);admin 侧保留,用于找待补图资产。

## 5. 字段级口径(拆任务判据,前后端共用)

| 口径 | 判据 |
| --- | --- |
| 已过审 | `asset_entities.status = 'approved'`(状态机列,reviews 域负责迁移;`approved` 布尔是导入时写下的影子,**不作判据**) |
| 合格预览 | EXISTS `asset_media`(`media_kind = 'image'`)——至少一张图片媒体 |
| 有 3D | EXISTS `asset_media`(`media_kind` 为 3D 模型类值) |
| 徽标 kind_counts | 当前搜索+媒体+高级筛选下各大类命中数(**排除大类维度自身**);现实现为 scope 级总数,要改 |
| 角色因子值域 | 资产因子字典 v0.2(卡 asset-factor-dictionary),`gender` / `age_band` 的档位与显示名从字典取 |

## 6. 组合与状态规则

- 跨维度 AND;同维度多选内部 OR;**搜索词与所有筛选 AND,无例外**(搜索在已筛选结果内检索)
- 任何条件变化(搜索/筛选/排序)→ 回第 1 页 + 滚回顶部。排序切换**不保留滚动位置**——
  结果集变了,保留位置没有意义
- 「清空筛选」清筛选**不清搜索词**;搜索框自带 ×
- **全部条件写 URL query**(`kind/media/category/tags/source/gender/age_band/sort/q/page`):
  返回页面保留、链接可分享
- 结果数:「共 N 个」用 `total`;空结果用业务语言:「没有匹配的资产。清掉筛选试试,
  或换个说法搜索」+「清空筛选」按钮
- 窄屏:高级筛选收进「筛选」抽屉,按钮带生效条数徽标;大类切换保留横滑。
  原型按 1440 桌面优先,窄屏形态随走查后细化

## 7. API v1(`GET /api/v1/assets`,`scope=common`)

| 参数 | 取值 | 状态 |
| --- | --- | --- |
| `q` | string,模糊搜索 | 已有 |
| `asset_kind` | 大类枚举 | 已有 |
| `media` | `image` \| `model3d` | 新增,EXISTS 筛选 |
| `category` | string | 新增 |
| `tags` | CSV 多值,内部 OR | 现 `tag` 单值,扩多值;旧参兼容保留 |
| `source` | uuid(source_project_id) | 新增 |
| `gender` / `age_band` | 仅 `asset_kind=character` 时有效,值域引字典 | 新增 |
| `sort` | `composite` \| `newest`,默认 `composite` | 新增,替换工程默认排序 |
| `page` | ≥1 | 已有 |
| `page_size` | 新客户端固定传 24;服务端旧默认 500 为兼容保留,调用端全迁后收紧 | 已有 |
| `status` | **admin 专属**;非 admin 请求服务端强制 `approved`,传了也覆盖 | 收口 |

返回:`items / total / page / page_size / has_more / kind_counts`(徽标语义见 §5)。

**稳定性要求**:同一条件同一顺序;每种排序末位 `id ASC`;条件变化客户端回 `page=1`;
不出现翻页重复、漏项、顺序跳动(这是性能分支已定的分页地基,本稿只定其上的产品语义)。

## 8. 最小上线版(不依赖未来数据)

- 新增字段:**0**(纯现有列 + EXISTS 子查询;955 量级无性能顾虑,后续量级上来再考虑物化)
- 依赖:无算法、无行为数据、无运营标注
- 顺延项:`curated_at`(v1.1)、「使用最多」(累加接上后)、窄屏细化(走查后)

## 附录:DC 设计输入原文(2026-07-31)

> 通用资产已经有搜索、资产类型切换和分页性能修复,但产品层尚未明确:
> 首次打开时默认按什么排序,以及这个默认值服务什么目标;用户可以选择哪些排序方式;
> 支持哪些筛选维度、组合规则和清空/回退方式;搜索、筛选、排序、分页之间如何保持稳定,
> 不出现翻页重复、漏项或顺序跳动;超管导入冷启动资产后,如何让优质资产被优先发现,
> 而不是只按写入时间堆叠。
>
> 已观察事实与工程约束:测试库当前通用资产约 955 个,其中新增 519 个 3D 导演台资产。
> 性能修复把首屏从一次拉取大量资产改为服务端分页,每页 24 个;筛选和排序必须由服务端
> 执行。现行临时顺序是 `updated_at DESC, name ASC, id ASC`,只是稳定分页所需的工程默认,
> 不代表产品设计结论。搜索、筛选或排序变化后应回到第 1 页;同一条件下必须有稳定的最终
> tie-breaker。3D 模型和图片预览是同一资产的不同媒体,不应被误当成两个可筛选资产。
> 通用资产只读,但存在「引用到项目」和「导入为个人资产」两种下游动作;排序设计应考虑
> 复用效率,而不只是浏览美观。
>
> 验收要求:输出一份可供前端、后端直接拆任务的裁决稿,至少包含默认排序、可选排序、
> 首期筛选项、组合规则、状态保持、空态以及 API 参数。当前性能修复在裁决前只保留稳定
> 分页,不擅自把临时顺序固化成产品规则。
