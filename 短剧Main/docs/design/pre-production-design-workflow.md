## 一、真实工作流(从资料反推,DC 确认口径)

**第一阶段:前期设计(设计圣经)**——开拍前,对象和关系已经设计完:
- 角色设计表:角色/年龄/介绍/服装/**设计交付/编辑确认**(两个人工
  确认状态位!)+全局风格约束(如"中世纪风格""男女主体型差");
- 场景设计表:全部场景清单/**对应服装**(场景×角色×服装关系)/设计
  交付/编辑确认;
- 隐含关系:人设→变体→出现的集;场景从描述→选参考图→**定稿**→
  多视图。
**第二阶段:分镜表**——每集一张,列:集数/场景/镜号/画面描述/运镜/
景别·视角/台词/音效/参考图/分镜图(+生图师=每镜的负责人)。每一行
= 一个镜头,通过「场景」列**引用**第一阶段设计好的场景对象。

## 二、对我们对象模型的对照结论

| 资料事实 | 平台现状 | 结论 |
| --- | --- | --- |
| 设计交付/编辑确认两个状态位 | 资产审核域是"审核"单轴 | 设计资产的生命周期=设计中→交付→确认(定稿),定稿才可被分镜引用——与审核域对齐或映射,不发明第三套 |
| 场景×角色×服装关系表 | 无此关系对象 | 关系是一等公民:出场关系(角色@场景)与穿着关系(角色@场景→服装)要能落库(0.2.x 至少 JSON 承载,0.3.0 关系表) |
| 人设→变体→出现集 | 变体写入端点缺(k3 包 3) | 变体是人设的子对象,带「出现集数」关系 |
| 分镜行经「场景」列引用场景对象 | 导入后**自动绑定全部匹配资产**(bug C) | **匹配≠绑定**:导入时按名称把分镜关联到已定稿场景/角色=「按设计引用」;模糊命中只能进候选区待人工确认 |
| 每镜有生图师 | 无镜头负责人概念 | 镜头可指派负责人(轻字段,进人时口径的活跃段归属) |
| 参考图/分镜图列 | 参考控制包 | 分镜表的这两列=控制包的输入雏形,导入时建空控制包并挂候选 |

## 三、本体论修订(R10,随本文件生效)

R10 **关系先行**:生产对象间的关系(角色-场景-服装-集-镜-控制包)在
前期设计阶段由人建立,是生产的**输入**不是系统的输出;「匹配」的语义
=按既有设计关系**引用**+相似度**候选推荐**,系统绝不自动绑定(条 38
同源);导入剧本/分镜表/设计圣经时,必须解析并落库这些关系,解析不确定
的进候选区人工裁决。
