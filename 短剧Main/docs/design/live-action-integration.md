# 真人剧接入方案(2026-07-23,DC 提出,Fable 映射,待排期拍板)

结论:不建平行系统。平台核心抽象(项目/集/粗剪素材/资产/参考/生成/审核)对真人剧
全部成立,接入=四个扩展点。

## 环节映射(对 DC 的四环节图)

| 图上环节 | 现有模块 | 真缺口 |
| --- | --- | --- |
| 生产指挥台(拆解·缺口·预算) | 剧本导入+集/素材拆解+消耗页 | 粗剪素材加「生产方式」字段:实拍/AI 生成/实拍+AI 补;预算与消耗按方式分列 |
| 资产工作台(实物↔数字·授权) | 资产中心全套 | ①资产加来源(实拍采集/AI 生成/外部导入)与授权字段(主体/范围/期限/凭证);②角色资产支持「真人分身」类型(演员定妆多角度+授权绑定);③实物转 3D 数字孪生=远期不承诺 |
| 创作画布(全参补拍·批量生成) | 参考清单+控制包+全能参考 | 几乎零成本:实拍剧照/片段当参考生成同风格镜头,流程无区别。唯一缺口:**粗剪素材支持直接上传实拍片段**(media_results 增 uploaded 来源),实拍与 AI 镜头同时间线混排交付 |
| 审片交付(机审初筛·人审定稿) | 资产审核域(四态/审核人/理由留痕) | 审核扩到成片级——media_results.review_status 死字段救活(原拍板「产物审核排 V0.1.2」);机审初筛接火山内容安全,结果进人审队列 |
| IP 资产回库 | 资产中心+「转为通用资产」占位 | 占位实装+授权约束检查(跨剧复用要在授权范围内) |

## 分期

- **0.2.x·最小能走通的一版**:生产方式字段+实拍片段上传混排——真人剧组立刻能用平台
  管理粗剪与交付,AI 只补高成本镜头;
- **0.3.0**:资产授权字段+实拍采集入库流+成片审核(机审后置,先人审);
- **0.3.x**:真人分身管理、机审接入、IP 回库实装;
- 远期:实物 3D 数字孪生(依赖建模能力,不在承诺内)。

## 定位一句话

真人剧与 AI 剧在平台上是同一条生产线的两种镜头来源,差异收敛在
「素材从哪来、授权归谁、审核到哪层」,不在生产流程本身。
