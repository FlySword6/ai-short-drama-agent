# deepseek 系文本能力路由策略(v1.1 预定稿——冒烟数据已回填)

> R142(DC 2026-08-01):「除了需要多模态理解能力的,其他可以搭配 deepseek-v4-flash 使用……基于 flash 的能力全面升级各种智能化的功能。」渠道事实:col/newapi(api.chineseall.com/v1)已配 flash,key 在 kimi 配置内(不落文档)。

## 一、平台文本 AI 调用面盘点(按现有代码接线)

| 调用面 | 现役接线 | 特征 |
|---|---|---|
| Pi 助理对话(assistant/runtime) | remotePi 或 Ark 文本模型 | 高频、延迟敏感、多轮 |
| 剧本拆解(script-breakdown/service) | Ark 文本模型 | 低频、单次长输出、质量敏感(scenes/shots 入库) |
| 编译稿组装建议/提示词整理 | 前端组装+后端透传 | 中频、短输出 |
| 检索 query 改写/标签/摘要(资产检索、看板) | 部分未接模型(规则实现) | 高频、短输出、错了可重试 |
| 多模态理解(画面分析、视觉 QC) | 多模态模型 | **不切**(R142 明示排除) |
| 图/视频/音频生成 | Ark 生成模型(modelProviderRegistry) | **不切**(生成不是文本推理) |

## 二、路由原则(三条)

1. **按能力面路由,不按调用点硬编码**:后端加一个 OPENAI 兼容文本 provider(baseUrl/key/model 走 env),调用面通过能力键(assistant_chat / script_breakdown / text_util)选 provider;换模型改配置不改代码。
2. **质量敏感面先 A/B 后全切**:剧本拆解直接影响 scenes/shots 入库,flash 与现役各跑同一批样本(≥3 集真实剧本),对比结构完整率+人工抽读,赢了再切。
3. **dev/test 先行,生产跟发版走**:env 键先进 dev/test,冒烟绿后随下次发版直写线上 env(老规矩:发版后到运行环境实测键值)。

## 三、分批切换方案(推荐)

- **第一批(低风险,直接切)**:Pi 助理对话+检索/标签/摘要类文本工具。flash 快,对话体验直接受益;错了影响面小。
- **第二批(A/B 一轮)**:剧本拆解、分镜候选。样本对比通过后切,保留一键回退(env 换回即回)。
- **不切**:多模态理解、图/视频/音频生成。
- **顺手升级项(flash 解锁的新智能化面,进 v0.3.0 备选池)**:资产语义标签自动化、剧本一致性检查(角色/道具前后矛盾提示)、看板周报自动摘要。做不做、排哪版,DC 拍。

## 四、冒烟实测(2026-08-02,deepseek-v4-pro 走 col/newapi;flash 待 DC 加白名单后补速度与质量数)
