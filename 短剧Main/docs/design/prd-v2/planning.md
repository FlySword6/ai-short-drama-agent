# 统筹(新增章,2026-08-06 起草)

> 本章由产品主线推出(`docs/design/prd-spine.md`):我们做的是"让 AI 生成不返工的统筹工具",而返工 40-50% 的根因是角色、服装、场景跨镜不一致——**病根是缺一个统筹阶段**。此前八章没有这一章,统筹信息散在备戏与控制包里、且从分镜倒推,顺序是反的。

## 一、这一章解决什么问题

潘导的原话是判据:

> 「是因为你们少了一个统筹的阶段……我们会有一个阶段叫统筹,就是统筹这部片子要用到的所有演员,所有道具所有场景,这个一定要统筹,而不是盲目的拿到本子我就开始做了……不停的返工是可以避免的。」

一线的工序铁序是:**风格定调 → 角色/场景资产 → 分镜设计 → 视频生成 → 剪辑**,"顺序错了片场就炸"。统筹发生在第二步,**在分镜之前**。

现在产品的做法是:先拆分镜,再从分镜倒推出"这一场缺哪些素材"(备戏)。**这等于把统筹变成了查漏补缺,而不是事先定盘。** 查漏补缺只能发现"这一场少了什么",发现不了"同一个角色在第 3 集和第 17 集穿的不是一套衣服"——**而后者正是返工的头号来源**。

## 二、统筹阶段做什么

**输入**:一集(或一部剧)的剧本。
**输出**:一份"这部片子要用到的全部角色、服装、道具、场景"的清单,每一项都指向资产库里一个确定的条目或一个明确的待办。

三个动作,顺序固定:

**1. 穷举。** 把剧本里出现的角色、服装、道具、场景全部列出来,不做判断、不做取舍——先求全。一线的做法就是穷举,潘导说得很明确:先穷尽,再人为做减法。

**2. 做减法。** 按重要程度砍到能做的量,**主角优先**。判据来自一线:主角约 10 套服装,配角 2-3 套;会特写或有交互的关键道具必须有参考图,其余可留空。**减法是人做的判断,产品只提供依据(出场次数、是否特写、是否跨集复用),不替人砍。**

**3. 定盘。** 留下的每一项要么绑定资产库里已有的条目,要么标成"待生成/待上传"。**定盘之后进分镜,分镜引用的是定好的资产,不是临时新造的。**

## 三、和现有功能的关系(不是新造轮子)

- **资产库**:统筹结果存放的地方。清单里每一项最终都指向资产库条目——这也是跨集一致性的唯一真相来源。
- **控制包**:统筹结果在单个镜头上的投影。控制包解决"这一镜用哪些参考",统筹解决"整部片子有哪些参考",**前者是后者的切片**。
- **备戏**:现有的备戏是从分镜倒推的查漏动作,统筹阶段成立后,**备戏降级为统筹的补充**(拍到一半发现漏了才用),不再是主路径。
- **Excel 导入**:一线现在就是用 Excel 做统筹(角色场景对照表)。**导入即统筹的起点**——把他们已有的表接住,比让他们在我们这里重新录一遍强得多。

## 四、一致性检查(本章的价值兑现处)

统筹定盘之后,产品才有能力回答这类问题:

- 这个角色在本集所有镜头里用的是同一张定妆图吗?
- 这套服装在第 3 集和第 17 集是同一套吗?
- 这个场景的日戏和夜戏用了不同的参考图吗(应该)?还是混用了同一张(可能出错)?

**这是外部工具做不到的事**——它们不知道"这个角色"是谁。我们有资产库,所以我们知道。

### 4.1 强度三选项已撤回(2026-08-06)

原先这里挂着"只提示 / 提交前拦截 / 自动带入"三选一,请产品负责人拍板。**这三个选项已撤回,不作数了。**

撤回理由:它们只在"拦得狠不狠"这一个维度上分档,而产品负责人当场追问的是另外六件事——

> 什么的一致性?怎么检查?什么评估指标?怎么保证拦截对?拦截错了怎么办?用户需求是这个吗?用户体验怎么样?

**这六问里,只有第一问我们答得上来**(角色/服装/场景跨镜不一致,来自返工 40-50% 的归因),其余五问都缺依据。在缺依据的情况下让人选强度,是把责任推给拍板的人。

### 4.2 补齐这六问需要什么(未完成,不许跳过直接做功能)

| 要答的问题 | 现在有什么 | 还缺什么 | 从哪儿拿 |
|---|---|---|---|
| 什么算不一致 | 只有大类(角色/服装/场景) | 具体是哪几种穿帮、各占多少 | 潘导那批返工案例的实物 |
| 怎么检查 | 无 | 是比对资产 ID(确定性判断),还是比对画面(需要判图能力)——两者成本差一个数量级 | 案例里看是否存在"用对了 ID 但画面仍穿帮" |
| 什么指标算判定成功 | 无 | 漏报率与误报率各自能接受到多少 | 需要先有一批标好答案的真实镜头 |
| 怎么保证拦对 | 无 | 同上,没有指标就谈不上"拦对" | — |
| 拦错了怎么办 | 无 | 逃生路径怎么设计(一键放行?记住这次判断?) | 取决于误报率高低 |
| 用户是不是真要这个 | 无 | 一线现在靠什么发现穿帮、发现得早不早、他们愿不愿意被挡 | 直接问一线,或 8/17 试点现场观察 |

**结论口径**:这一节的功能定义暂缺,**不是遗漏,是证据不足**。在拿到上表右两列之前,不重新出选项、不画界面、不派开发。资产库作为一致性真相来源的能力照常建设(它不依赖这些答案),**"检查"这个动作本身待定**。

## 五、统筹是必经还是可跳过 —— 已拍板:**推荐但可跳过**(2026-08-06,产品负责人)

**定论:统筹做成推荐步骤,不是必经关卡。** 入口要显眼、默认引导用户先走这一步,但**给"跳过"这条路,不挡任何人开工**。

配套三条,用来补回"可跳过"丢掉的防返工能力:

1. **跳过要留痕**:跳过统筹的项目做个标记,后续出现跨镜不一致时,提示里带上"这个项目当初跳过了统筹",让人知道病根在哪。
2. **随时可以补**:统筹不是一次性关卡,做到一半发现缺料,能回头补统筹清单,不必推倒重来。
3. **跳过不等于没有资产真源**:跳过的只是"事先穷举"这个动作,资产库仍然是一致性的唯一真相来源;查一致性的能力不随跳过而关闭。

> 与 `prd-spine.md` §五之 1 的关系:主线原把这条列为待拍板,现已由产品负责人定为"推荐但可跳过"。**主线该条目已于 2026-08-06 销号**,两处口径一致。

## 六、本章不做什么

- 不做排期与人力分配(那是制片的活,不是本产品当前范围);
- 不做成本预估(计费章负责);
- 不替用户做减法判断——**产品给依据,人做决定**。
