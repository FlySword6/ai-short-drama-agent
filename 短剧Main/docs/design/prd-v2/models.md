# 模型与能力矩阵(新增章,2026-08-06 起草)

> 平台第一性原则是「模型是核心——平台价值=充分、方便、高效地发挥各模型的能力,其他都是手段」。但此前八章里,**「模型」不是一个域**:接入被压在代理章一句话里,参数矩阵的责任在生产章,计价规则在后台章,音频档位在增量表里——同一条链跨三章四处,**没有一个地方对它负责**。这一章立这个 owner。

## 一、这一章管什么

**三件套,合起来是模型能力的唯一真源:**

1. **注册表**:平台接了哪些模型、各自属于哪个供应商、当前是什么状态。
2. **参数矩阵**:每个模型原生支持哪些参数、各自的取值范围——**以供应商官方文档为准,不许凭记忆或类比填**。
3. **档位**:把"模型 + 一组参数取值"映射成一个**可计价单元**。任务落账时引用档位,不直接引用模型编号。

**判据**:界面上能给用户选的东西,必须能在参数矩阵里找到出处;矩阵里没有的,界面上不许出现;矩阵里有而界面上没有,就是欠账,要记。

### 一处必须分清的歧义(2026-08-06 裁决,起因=sol 在实现时发现本章前后打架)

本章第 3 条说档位是"模型+一组参数组合",第二节规矩一又说"禁止复合档位、参数各自独立"——**这两句看起来矛盾,实际说的是两层东西。就近说清,不许再混用**:

| 层 | 叫什么 | 是什么 | 谁看得见 |
|---|---|---|---|
| **用户面** | **参数选项** | 画幅、清晰度、时长、数量……**各自是一列独立的选项,用户分开选**。这一层不存在"组合" | 用户 |
| **计费面** | **档位** | 用户选完之后,后端把这一组取值解析成**一个可计价单元**——因为供应商本来就是按组合报价的(1K 一个价、2K 另一个价),这一层的"组合"是**记账的必然**,不是产品设计 | 用户不直接感知,只看到最终价格 |

**判定规则**:
- **"禁止复合档位"这条规矩,约束的是用户面**——不许把"16:9 + 2K + 1 张"打包成一个不可拆的选项塞给用户;
- **计费面允许而且必须有组合**——否则算不出钱。但它是后端解析出来的结果,**不是用户要面对的选择单位**;
- 因此:**前台与接口按参数独立开放,后端内部解析到唯一计价单元**。这是 sol 2026-08-06 提的方案,采纳。
- 代码里现有的 `capability tier` 对应的是**计费面**的档位,不改名(4 天窗口不做大范围重命名);**文档与界面文案里,面向用户的地方一律说"参数选项",不说"档位"**。

## 二、不阉割模型:三条硬规矩

产品负责人的原话是本章的第一约束:**「尽量不要阉割接入的模型。例如限制生图大小等等」**「不要搞成复合档位,很反人性,档位指的是每个参数自己的档位」。

**规矩一:逐参数独立成档,禁止复合叉乘。**
画幅、清晰度、时长、数量各自是独立的一档,用户分开选。**不许把"16:9 + 2K + 1 张"打包成一个不可拆的档位**——那是把三个选择压成一个,用户想改其中一项就得整体换。

**规矩二:接口支持什么就开什么,默认值不等于上限。**
参数的取值范围来自模型原生能力,**我们不设人为上限**。可以有默认值(为了上手简单),但默认值必须可以被显式覆盖。**"默认 720p"不等于"最高 720p"**——这两件事在界面上要区分得开。

**规矩三:留一个专家逃生口。**
高级区给一个「我自己写、原样发送,不走平台整理」的开关,用了就提示效果自负。理由:平台替用户整理上下文是对的默认行为,**但不该把懂行的人一起管住**,也不该浪费掉那些擅长长指令的模型。

## 三、档位的生命周期(治"无限期联系管理员")

一个档位从登记到能用,必须走完整流程,**并且用户始终看得见它处在哪一步**:

| 状态 | 用户看到什么 | 判据 |
|---|---|---|
| **可用** | 正常可选,带价格 | 已定价、已冒烟、已核账 |
| **待开通** | 可见但不可选,**必须写明预计开通时间和卡在哪一步**(缺定价 / 供应商未开通 / 待评估) | 不许只写"联系管理员" |
| **已下架** | 不再出现在选择列表,历史任务仍可追溯 | 供应商停售或我方主动停用 |

**两条红线**:
- **不许无限期停在"待开通"**。每个待开通档位必须有一个负责人和一个时限;到期未开通就要给出新时限或降级为下架,不能就这么挂着。
- **未定价不等于不可用**。缺定价时给一个兜底规则(例如按同族档位价格暂估并标注"暂估"),而不是直接封锁能力。

## 四、供应商口径(已拍板,本章只做记录)

- **能力取向不设限,资金通道只认公司账户。** 需要什么模型都可以接,但真实调用只走公司账户。**这一条是底线,下面白名单怎么变都不改它。**
- 私人账号下的服务**一律不做真实调用**,物理上拒绝而不是靠自觉。
- 尚未接入的模型先以"占位"状态登记,公司凭据到位才激活——**登记不等于可用,界面上要分得清**。

## 五、界面怎么呈现(给设计与前端的约束)

- **模型选择器不是价格表**:除了价格,还要让用户感知到"这个模型擅长什么"——不懂供应商的人也要能选对。
- **控件由能力矩阵渲染,不硬编码**:新增一个参数,应该是矩阵里加一行,而不是前端改一次代码。
- **一句大白话说清每一档**:例如"竖屏、高清、4 秒——适合对话戏"。不要只给参数串。
- **灰掉的档位要给理由**:用户看到不能选的东西时,要知道是"还没开通"还是"这个模型不支持",而不是只看到一个灰色方块。

- 生图实际可用 **1 档**、生视频 **1 档**;档位表里 **28 档处于冻结状态**;9 个模型中 7 个未配置。**首批解冻已合入主线**(按官方牌价逐档校验的护栏同批),其余待续。
- 生成对话框里的参数**是印死的文字、零可选项**——规矩一与规矩二均未兑现。
- 专家逃生口**尚未实现**。
- 音频能力**后端已就绪且可用(含 89 个真实音色与完整参数表),前端一次都没调用过、界面上没有任何入口**——这是本章欠账里投入产出比最高的一项。
- **图像处理类能力(局部重绘 / 扩图 / 换背景一类)在注册表里没有条目——但已查清:不需要接新供应商。**(2026-08-06 实测,`outputs/five-capabilities-audit-20260806.md`)
  - **现状**:后端零实现且**显式拒收**——参数白名单只认 `size / resolution / ratio / watermark / sequentialImageGeneration` 五个键(`src/modules/generation/v01Contract.ts` `normalizeImageParameters`),mask / region / edit 一类参数进不来。AI 助手嘴上说的"改图"实际是拿原图当参考**整张重生成**。
  - **官方口径**:火山方舟**没有** mask 参数、**没有** edits 端点;mask 级涂抹类接口(seededit 一族)官方正在下线,**此路不应走**。
  - **可走的路**:现有模型 **Seedream 5.0 Pro 支持「交互编辑」**——框选区域或坐标写进提示词做局部精准修改,**走的就是我们已经在调的同一个 `/images/generations` 接口**。也就是说:不接新供应商、不等开通,**缺的是参数矩阵加一类条目 + 后端白名单放行 + 前端入口**。
  - 结论改写:生产章 §9.3 的 L3 层**不再受"没有模型"阻塞**,成本从"接新供应商"降为"接线"。原先写的"先查清再决定做不做"已经查完,该决定的是排期不是可行性。

## 七、本章不做什么

- 不做模型效果评测(那是选型调研的事,不是产品定义);
- 不替用户选模型——**给足信息与默认值,选择权在用户**;
- 不承诺具体供应商的接入时间(受外部流程约束的部分只记状态与负责人)。
