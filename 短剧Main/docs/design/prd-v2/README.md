# PRD v2 写作标准与目录(R149/R153;DC 2026-08-02:「完整详细,专业标准,agent 友好」)

## 章结构模板(每章九节,缺节要写「不适用+原因」)
1. **域定义与边界**:管什么/不管什么/与相邻域的接缝(引 SEAM 合同)
2. **用户故事**:角色(导演/制片/管理员/Agent)× 场景 × 期望,GIVEN/WHEN/THEN 式
3. **功能规格**:字段级——每功能:输入(字段/类型/校验/默认)、行为(状态转换)、输出(响应/副作用)、异常(每条错误路径的业务话文案)
4. **API 合同**:端点表(method/path/请求 schema/响应 schema/错误码);与 CLI/Agent 共用同一合同(R28)
5. **状态机**:实体状态枚举+转换表(事件→前态→后态→守卫条件)
6. **数据与词表**:引用 fieldLabels/lane 词表/因子字典,不复制;新词先入词表再引用
7. **文案接口**:该域用户可见文案清单(键→中文→触发时机),遵文案章三法则
8. **验收断言**:可执行判据——E2E 步骤(动线级)+单测断言点+守卫锚;每条能翻译成测试代码
9. **排期归属**:功能→版本卡映射(与 version-plan 互链)

## agent 友好细则
- 每节带稳定锚点 ID(`<!-- prd:production.gears -->`),外部文档/goal 引用锚点不引行号;
- schema 用 TypeScript 类型或 JSON Schema 块,不用散文描述字段;
- 枚举值全列,禁「等」「之类」;
- 判据禁形容词(「流畅」「合理」),只写可测谓词(时长阈值/元素存在/状态相等);
- 词表/合同用引用指针,同一事实不写两处;
- 每章头部:法源(R/V 号)+视觉真源(Figma 帧 id)+实现现状(已实现/施工中/未实现)三行速览。
