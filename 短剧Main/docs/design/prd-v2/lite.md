# 精简版(新增章,2026-08-10 起草)

> **为什么现在有这一章**:精简版(界面上叫「精简版」,内部代号 lite)2026-08-07 起搭建,此前没有一份产品定义——它长什么样、给谁用、简到什么程度全靠施工现场自定,结果生视频建在已作废的首帧方案上(#186)、审核被闸住却无处可审(#187)。本章把产品负责人 2026-08-10 验收现场的拍板落成字据。

## 一、设计总纲(产品负责人 2026-08-10 原话)

「lite 就是要简单易用。操作界面看上去简洁易上手、制作流程简单,符合创作逻辑,但功能齐全,可控性功能能够不断深挖。能够把复杂的各种制作功能,具有逻辑性地合理地归纳在工具中。」

## 二、总纲拆成可执行的三条

1. **简洁不等于简陋**:默认界面只呈现当前一步需要的东西,但每个环节都留可见的深挖入口——点开能看到全部可控参数,不点开不打扰。精简的是「归纳方式」,不是「能力面」。
2. **不阉割模型**:分辨率、画幅、单次张数等参数以模型能力矩阵的真实值域为准放开,不做人为收窄(如限制生图大小)。默认值给创作者最顺手的,全部档位在深挖入口里。与模型章「不阉割模型」三条硬规矩同源。
3. **流程符合创作逻辑**:页面顺序与操作动线跟着「剧本→素材→分镜→图→视频→下载」的创作次序走,不让用户为了系统概念绕路。

## 三、已拍板的具体口径

- **审核就地合并(2026-08-10 拍板,#187 选 A)**:候选图上「通过并选用」一键完成,有审核权限的人一个动作走完;不把用户引去别的页面找审核入口。
- **生视频=全能参考(#186)**:文字提示词+参考素材注入,页面文案与状态机不得出现「首帧」语义;参考控制在生图与生视频动作旁可见、可增减。
- **「时长」归视频**:生图动作不出现时长概念;镜头时长标注清楚属于生视频。
- **项目弹窗:新建/编辑统一入口(2026-08-10 拍板)**:精简版项目列表的「新建」与卡片上的「编辑」共用一个弹窗,对齐本章「精简版不是阉割版」总纲。新建模式收剧名+说明+成员预填,建完进剧本页;编辑模式所有字段(含剧名)均可改、成员可管、可删除项目(移入回收站)。成员管理只做三件事:搜索系统用户、添加、删除——不在精简版暴露「可编辑/仅查看」角色区分(后端统一落 editor,角色调整留到完整版);同样不设前端权限分层,入口对所有人放开,后端权限不通的接口如实返回错误(前端人话提示)。新建入口本身复用完整版同一把 `canCreateProject` 锁、同一后端接口,不另开口子;普通 member 无权限时空态引导「找管理员开通」。
- **成员搜索框交互(2026-08-10 拍板)**:搜索框聚焦即展示全部可加用户(服务端目录前 20 条,按显示名排序),输入做模糊过滤;点选用户即加入成员,不再设单独「添加」按钮。
- **多集管理(2026-08-10 拍板)**:Lite 剧本页顶部剧集条管理本项目所有集(第1集、第2集…),可新建、切换、逐集录入剧本。当前选中集是全局上下文(URL 携带),切集后素材/分镜/图/视频页自动跟随。集的增改复用完整版 episodes API,不引入第二套集管理。已有成片的集受成片保护不可重新解析(R1)。
- **剧本文本从文件导入(2026-08-10 拍板,08-11 调整)**:剧本页粘贴框旁提供「从文件导入」入口,支持 .txt、.md、.docx、.pdf;系统只提取纯文字填进粘贴框。不支持 .xlsx(与完整版 Excel 分镜素材导入语义不同)、不支持 .doc(请转 .docx)。提取后用户须核对、手动点「一键生成本集」,不自动提交。PDF 提取质量不稳定(页眉页脚可能混入),提示中告知用户核对。
- **整部剧本自动分集导入(2026-08-10 拍板,08-11 调整)**:剧本页剧集条旁提供「导入整部剧本」入口,上传一个文件(.txt/.md/.docx/.pdf),系统按中文「第N集/话」或英文「Episode/Ep N」标题自动拆分、建集并为每集创建剧本版本。集标签只保存原文集标题,不拼接项目剧名;剧本框只保存该标题之后的原文正文,不重复添加集标题。拆分逻辑复用 `episodeParser.ts`(零 LLM 依赖,规则匹配)。**导入是覆盖不是追加**:导入成功后项目既有集全部软删(R1 可逆操作),按文件内容重建,保证重新导入后与文件严格一致、不叠出重复集;项目已有集时前端先弹覆盖确认,导入结果 toast 带「已覆盖原来的 N 集」。**无集数标题的文件不拒绝**——整个文件作为一集导入(覆盖语义下集号恒为 1),前端 toast 提示「文件没有集标题,已作为一集导入」。导入只负责把文本放进对应剧本页，不自动触发解析 run，后续由用户在具体集里显式点击「一键生成本集」。
- **剧本编辑锁(2026-08-10 拍板,08-11 调整)**:集的剧本经解析确认后,文本框变为只读。点「编辑剧本」才解锁,提示「修改后重新生成,已有分镜和素材将失效」。改完点「一键生成本集」提交;点「取消」还原并锁定。
- **一键生成本集(2026-08-10 拍板,08-11 调整)**:每集只提供「一键生成本集」按钮,不再并列提供「解析剧本」。点击后提交剧本 → AI 拆解 → **自动确认**(创建正式分镜 + 物化资产)→ 跳转分镜页。此功能显式覆盖此前「禁止自动确认」约束——用户选择一键即选择跳过草稿审查。解析失败时保留原文并允许重新生成。

## 四、边界

- 精简版与完整版同一后端、同一数据、同一账号体系——精简版做的一切在完整版可见,反之亦然;
- 精简版不是功能子集的「阉割版」,是同一能力面的另一种归纳;完整版承载团队协作、审核队列、交付管理等重流程,精简版面向一线创作者的高频生产动线。

### 5.1 界面骨架:两屏两轴

<!-- prd:lite.redesign.shape -->

精简版全部界面是**两屏 + 三层**,没有第三个地址:

| 编号 | 名称 | 职责 |
|---|---|---|
| **S1 片单** | 入口 | 看手上有哪些项目、建项目、进某个项目;有终审权的人还看「等你过的图」 |
| **S2 片场** | 主界面,95% 时间 | 剧本、拆解、备料、出图、定图、出片、定片、交片,全在这一屏 |

三层是瞬态覆盖,不进地址:项目规矩抽屉、剧本原文栏、影院态(候选图放大连看)。

S2 内部由**两根正交的轴**导航,取代原先按物料类型切的六个页签(剧本／素材／分镜／图／视频／下载):

- **缩放轴**(互斥三档):`整集` / `一场` / `一镜` —— 决定中区装什么,默认落在「一场」;
- **图层开关**(可多选):`剧本` `参考` `图` `片` —— 决定看哪一层,作用于当前缩放档。

理由:创作者脑子里没有「图片页」,只有「这一集」「这一场」「这一镜」。
页签是互斥的,两根轴是正交的——同样的东西,后者能表达的组合多一个数量级。

**可寻址是硬性前提**:缩放档、场、镜、图层、滚动锚点全部进地址,刷新回到原位,链接可分享。
从贴本子到定成片全程只有 query 段变化,**没有一次整页跳转**。

### 5.2 五条收敛后的硬口径(逐条都是审计阻断项的结论)

<!-- prd:lite.redesign.invariants -->

#### 口径 1 · 一个项目就是一集

后端 `project.lite_episode_id` 是**单指针**,一个项目对应一个集容器。
精简版不做「一部戏挂好几集」的界面:没有集列表、没有集号胶囊、没有〔＋ 新一集〕。

- 集号写进项目名(如《雨夜不打伞》第 04 集);同一部戏的下一集是**另一个项目**;
- 缩放轴的「整集」指的就是这个项目的那一集,不是若干集的汇总;
- 地址里不出现集标识——集由后端从项目带出,不在路径里重复一遍;
- 全局汇总(在锅上的活、交片)的跨度是**跨项目**——项目之上没有第二层集合。

**为什么不做**:一个项目挂好几集,是后端不存在的能力。界面先画出来,等于让施工现场去发明数据模型,
或者做一个点了之后什么都没有的壳。判据:精简版目录里搜不到任何集选择器或建集请求。

#### 口径 2 · 人员与权限不在精简版办

`AGENTS.md` R1 明写 Lite **禁止写团队、权限、计费、词表等结构表**。
建号、把人派进项目、给终审权都是权限结构表的写操作,精简版**一律不做**,包括不做只能看的空壳页。

精简版对人员与权限只有两个行为:

1. **读**:要显示「谁能过这张」时,读得到成员表就显示具名;读不到就用「项目审核人」通称,**不编造名字**
   (依据 `frontend/shortdrama-rag-demo/src/pages/lite/lite-review.ts` 文件头注释);
2. **带路**:用户提出加人或给权限时,给一句实话和一个去处 —— `加人和给权限在完整版办,这儿只管拍。〔去完整版〕`

**为什么不做**:精简版与完整版共用一套数据。在同一套权限表上开第二个写入口,两边规则一旦漂移,
坏掉的是完整版的授权判定——这是「共用一套数据」必须支付的保险费,不是可以省的一步。

#### 口径 3 · 一次人的点击,只创建一个付费任务

<!-- prd:lite.redesign.one-click-one-task -->

`AGENTS.md` §4:生图、生视频、生音频都是付费动作,**必须由人明确点击一次,才创建一次任务**;
Agent 不得自动提交、自动重试、批量扩张。精简版把这条落成三个具体约束:

1. **没有一键出多个的控件。** 所有带「一起」「全部」「批量」语义的入口一律改成**逐镜确认器**:
   点开就地展开清单,一镜一行、一行一个按钮、一行一份价格;点几下就出几个任务,
   光标自动落到下一行**但不替用户按下去**。合计价格只用来算总账,**不是一个能按下去的总开关**。
2. **多选只决定列谁,不决定提交。** 整集档勾选若干镜,得到的是一张清单,不是一次提交。
3. **助手拿得到报价,拿不到提交。** 报价与提交在后端本来就是两步;精简版把这条缝用死——
   助手工具表里**不注册任何能提交付费任务的工具**,最多做到把单子摆到人面前、把价钱算好。
   这样即使模型被诱导或被提示词注入,也不可能替人花钱。

助手对「你直接帮我全出了」的标准回应:
> `出图这一下要花钱,得你自己按。清单我摆好了,价格也算好了:#03 是 30 分。〔就在这儿按〕`

**判据(可测)**:任意入口下,`POST /generations` 的调用次数**恒等于**人的点击次数;
助手会话的工具表断言里不存在提交类工具。两条都进 CI。

#### 口径 4 · 不承诺产品没有的能力

<!-- prd:lite.redesign.no-fiction -->

界面只说产品真有的事。三处虚构文案已删除,并给出真话版本:

| 虚构的 | 事实 | 界面改说 |
|---|---|---|
| 自助加额度按钮 | 没有自助入口;额度由管理员在后台人工调账 | `分不够了:这一镜要 30 分,账上还剩 20 分。少出一张就够,或者先去找管理员加额度。` |
| 「已报去核销,一般当天退回」 | 后端没有这条流程;数据库里那一项是待人工处理的补偿输入,不是自动退回 | `这一条片没出成:模型那边中途断了。这次扣了 320 分,这笔账我们记下了。` |
| 各类时限承诺 | 没有对外承诺过时限 | 删除。只在有历史数据支撑时给耗时预估,估不出来就写「已经等了 X 分 Y 秒」 |

**通则**:钱、权限、时限三类话,产品没有的能力一个字都不许写。
额度不够时按钮就地置灰并写明差多少,不让用户点了才发现。

#### 口径 5 · 台账与失败记录从数据库读

<!-- prd:lite.redesign.ledger-from-db -->

在途任务、已完成任务、**失败记录**的事实源是后端生成任务表,不是浏览器本地存储。
失败记录必须能查出四件事:哪一镜、什么原因、**扣没扣费**、当时用的什么参数和时间。

本地存储只允许缓存「这一次会话里刚发生的事」用于秒回,**任何时候以服务端返回为准**。

**判据(可测)**:换一台设备用同一账号登录看得到同样的清单;清掉浏览器存储再刷新,清单不变;
断言测试直接打后端端点,不打 localStorage。

**为什么这条是硬的**:失败卡活在标签页内存里,等于用户刷新一次就永远看不到自己那次白花的钱。
「不知道钱花在哪儿」是产品缺陷,不是细节。

### 5.4 交付分包与验收门禁

<!-- prd:lite.redesign.packages -->

四包,每包可独立交付、独立验收,**每一包交付后产品都仍然可用**:

| 包 | 内容 | 依赖 |
|---|---|---|
| **P0 地基** | 抽共享件、全线接业务语言映射、视频改走站内鉴权路径、**台账与失败记录改从数据库读**、参数矩阵补分组与白话字段、组件单一来源门禁、删孤儿样式 | 无 |
| **P1 镜头工作面** | 镜头卡三密度、参考条继承三态、深挖入口四层、就地定图、出片产物四态、出图侧补备料呈现 | P0 |
| **P2 壳层与两根轴** | 新壳、可寻址、三个缩放档、剧本层、拆解进行时、交片面板、宽度四档降级、**资产工作面同包**(先有替代品才删素材页) | P0 |
| **P3 入口与项目规矩** | S1 片单、在精简版里就能把项目建起来、项目规矩抽屉、人员权限的带路态 | P2 |
| **P4 助手** | 通栏三态、执行单(免费块与付费块分列、付费项逐镜一按)、**在拆解那套 agent 循环上扩助手工具表**(**不含提交类**,见 5.5)、工具调用事件上屏、界面联动、带路态 | P1+P2+P3,且包 A 的循环与事件流已合流 |

**每一包的验收门禁一致,四条命令全部退出码 0,实际输出进回执**:

```
npm run check:architecture
npm run typecheck
npm test
npm run build
```

外加**真实渲染走查**:在跑着真后端的环境里走完本包受影响的动线并留截图。
「组件存在」「类型检查过」不算交付(`AGENTS.md` §6);报进度时说到哪一层就是哪一层。

**禁用词门禁的作用域**:禁用词表(过程稿 6.7 节)查的是**用户看得见的地方与代码**——
文案常量、`title`、`aria-label`、提示条、状态机名。**不查产品文档里"点名说这个词不许用"的句子**:
本章 5.2 口径 4 那张表左列就是被禁的原话,把它列出来正是为了禁掉它,不是在用它。
拿 grep 验收时,精简版源码目录零命中即通过;本章只看新增小节零命中。

**排包纪律**:删掉一个页面与交付它的替代品必须在**同一包**。
原骨架把素材页删在 P2、替代品排在 P3,会留下一个「旧的没了、新的还没有」的不可用中间态——这条已收敛。

### 5.5 助手:与拆解共用一套「agent 调工具」(2026-08-10 产品负责人定架构)

<!-- prd:lite.redesign.assistant -->

> **这一节替换过程稿第五章那套自造的助手设计。** 骨架把助手当成一件要单独设计的东西——自己一套动作枚举、
> 自己一套确认时序。现在助手与拆解是**同一件事的两个工具集**:循环相同、事件流相同,只有工具表不同。
> 骨架第五章里与本节相抵的部分一律作废。

#### 范式:动作即工具

产品负责人 2026-08-10 原话(对拆解说的,同样适用于助手):
「**工具不就是 input schema 标准的吗**?……这是一个**在用户注视下慢慢填充的过程**。」

一句话讲清:**模型不写一段 JSON 给我们解析,模型调工具。**
工具的入参 schema 就是我们的数据模型,一份定义两处受益——模型只能在 schema 允许的范围内动作;
界面拿到的每一次调用,都是一件可展示、可独立校验、可独立重试的事。

于是拆解与助手长成同一个形状:

| | 拆解 | 助手 |
|---|---|---|

#### 助手的工具集(动作表)

助手能做的每一件事,界面上都有对应控件;**没有任何功能只能靠助手完成**——助手延期交付,产品仍然完整可用。

| 类 | 工具做什么 | 谁按下最后一步 |
|---|---|---|
| **看** | 跳到某场／某镜、切缩放档、开关图层、唤起影院态、查「哪几镜还没定片」「这一镜为什么没成」 | 助手 |
| **改** | 改画面描述／台词／提示词、加减这一镜的参考、改这一镜的参数(值域从能力矩阵读)、改这个项目的规矩 | 助手,可撤回 |
| **备** | 把一次生成备好:算价、拼参数、摆到人面前 | 助手做到这里为止 |
| **交** | 提交付费生成、通过并选用、定片、删任何东西、加人给权限 | **不注册成工具** |

前三类不花钱、可逆,助手直接做。第四类**不是「助手被拦住」,是工具表里根本没有这个工具**——
从根上不给它这个能力,即使模型被诱导或被提示词注入,也调不出一个不存在的工具。
助手对「你直接帮我全出了」的回应见口径 3。

#### 过程可见:一次工具调用就是一条事件

每次工具调用产生一条带人话描述的事件(`已经认出角色 阿霁` / `正在拆第 2 场` /
`#03 的参考换成了这三张`)。这条对拆解与助手同时生效:

- **拆解**:等待期不再是骨架屏,用户看着剧本被填充;
- **助手**:不在自己的栏里假装干活——中区自动滚到受影响的对象并描一圈虚线,改文字时新旧两行对照。

失败只影响那一次调用:**重试只重那一次,已经填好的不重做。**

#### 这一套顺手解决的三件事

| 旧做法的毛病 | 在这一套里 |
|---|---|
| 模型吐的 JSON 偶尔裹一层代码围栏,解析就炸 | 没有解析这一步,入参由 schema 强约束 |
| 等待期一片空白,用户不知道在干什么 | 每次调用一条事件,过程天然可见 |
| 一步失败,整轮判死 | 只重那一次 |

#### 两条硬约束(不因共用范式而放松)

1. **工具表就是权限边界。** 精简版助手的工具表里不存在提交类工具、不存在人员与权限类工具(口径 2、口径 3)。
   断言直接打工具表,进 CI。
2. **不许编数字,不许静默换参数。** 参考上限、价格、可选值域一律从能力矩阵读,读不到就说读不到;
   用户要的组合没有,就说「这个组合现在没有」,不许自己挑个相近的提交。
   配套欠账:后端工具 `prepare_generation_card` 的 `reference_media_ids` 写死 `maxItems: 8`
   (已核 `src/modules/assistant/tools.ts:39`),既低于模型能力,也与后端校验的 20 不一致——
   改成从合同常量读,这是助手包(P4)的硬性前提。
