# 项目(新增章,2026-08-06 起草)

> **为什么现在才有这一章**:项目是平台里最基础的容器——集、片段、资产、生成任务全挂在它下面。但此前八章里**没有一章对它负责**:创建项目只被当作既有起点反复引用(生产章画动线时写"项目→集→片段"),谁能进项目、项目怎么配置则完全没写。2026-08-06 核查下周一验收范围时发现这个洞,本章补上。
>
> **本章由产品负责人 2026-08-06 的验收清单直接推出**,其中两处口径由他当场拍板,已在对应小节标注日期。

## 一、这一章管什么

| 管 | 不管 |
|---|---|
| 项目的创建、字段、状态 | 集与片段的结构(生产章) |
| 谁能进这个项目、能干什么(项目级授权) | 平台级角色与账号状态(后台章) |
| 项目级的生成默认值(风格、清晰度、画幅) | 模型注册表与参数矩阵(模型章) |
| 项目级的提示词模板 | 单次生成时的提示词组装(生产章 §四) |

**一条判据**:凡是"这个项目里的所有生成都应该遵守"的东西,归本章;凡是"这一次生成才决定"的东西,归生产章。

## 二、创建项目

### 2.1 必填与选填

| 字段 | 必填 | 说明 |
|---|---|---|
| 项目名称 | 是 | 同一个人名下不允许重名——重名会让后面所有"这是哪个项目"的判断都变模糊 |
| 画幅 | 是 | **默认竖屏 9:16**(短剧主场景)。横屏 16:9、方形 1:1 也要给,不许只有竖屏 |
| 清晰度 | 是 | **图片与视频各存一个默认值,不共用一个字段**——两边的清晰度根本不是同一套刻度(图片是 1K / 2K,视频是 720p / 1080p)。默认:**图片 1K、视频 720p**。可选项由模型章的参数矩阵渲染,本章不写死 |
| 风格设定 | 否 | 见 §四。不填不挡创建,但要在项目页显眼处提示"还没定风格" |
| 简介 | 否 | 给人看的一句话,不参与生成 |

**创建后的状态**:项目建好即可用,**不需要任何审批**。空项目就是空项目,不摆"初始化中"这类假状态。

### 2.2 创建的人自动成为项目所有者

建项目的人默认是这个项目的**所有者**,拥有全部权限,包括邀请别人和删除项目。这一条不可配置——**项目必须始终有且只有一个明确的所有者**,否则出事没人负责。

所有者可以转让给项目内的其他成员,转让后自己降为编辑者。

## 三、项目成员(谁能进这个项目)

> **来源**:产品负责人 2026-08-06 验收清单第 3 项「项目分配用户」。此前 PRD 四章通读下来没有任何一处定义过项目级授权——平台级角色管的是"这个人是不是平台管理员",管不了"这个人能不能看到这个项目"。

### 3.1 三种角色

| 角色 | 能干什么 | 不能干什么 |
|---|---|---|
| **所有者** | 全部 | —— |
| **编辑者** | 建集、建片段、传资产、生成、改剧本、下载 | 加人踢人、改项目配置、删项目 |
| **查看者** | 看、下载 | 任何产生数据或花钱的动作 |

**为什么只有三种**:再细分就得给每个动作配一个开关,那是后台系统的做法,不是内容团队的做法。**一线的真实分工是"这部剧谁负责"**,不是"这个人有没有第 17 号权限"。

### 3.2 加人怎么加

- 项目所有者在项目设置里点「添加成员」,**从平台已有用户里选**,选完指定角色。
- **不能通过这里创建新账号**——新账号是平台级的事,归后台章。想加的人还没有账号,先去后台开号,再回来加进项目。
- 加人、改角色、移出,**三个动作都入审计**:谁、什么时候、把谁怎么了。

### 3.3 看不到就是看不到

不是这个项目的成员,**在项目列表里根本看不到这个项目**,不是"看得到但点不进去"。理由:短剧项目常涉及未公开的内容,列表里露出名字本身就是泄露。

平台管理员例外——管理员能看到全部项目,但**看到即留痕**,进入他人项目要在审计里记一笔。

## 四、项目配置

> **产品负责人 2026-08-06 拍板(两处)**:①**项目里定的是默认值,单次生成能改**;②**风格配置 = 一段风格描述 + 可选参考图**。

### 4.1 默认值不是上限(推翻旧裁决)

**旧口径作废**:此前生产章 §三·4 写的「720p 默认 / 服务端硬约束 / 前端只显不改」——**"硬约束、只显不改"这半句在 2026-08-06 被推翻**。

**新口径**:
- 项目配置里定的清晰度与画幅,是**这个项目所有生成任务的默认值**;
- **单次生成时可以改**,改了只影响这一次,不回写项目默认值;
- 可选范围来自模型章的参数矩阵——**矩阵里模型支持什么就给什么,平台不设人为上限**(模型章规矩二)。

> **清晰度必须图片视频分开存(2026-08-06 裁决,起因=sol 实现时发现对不上)**:图片的刻度是 1K / 2K,视频的刻度是 720p / 1080p,**根本不是同一套东西**。本章初稿笼统写"默认 720p",把视频的说法套到了图片上——图片矩阵里压根没有 720p 这一档。**改法:项目存两个字段,图片默认 1K、视频默认 720p。不许在代码里做 720p→1K 这类映射**,那是把两套刻度硬掰成一套,以后每加一个模型都要再掰一次。
>
> **画幅可以共用一个默认值**(9:16 对图片和视频是同一个意思),清晰度不行。

界面上要能看出来"这次用的是项目默认,还是我改过了"——改过的地方要有痕迹,否则用户不知道自己什么时候偏离了默认。

### 4.2 风格设定

**一个项目两套风格,图片一套、视频一套。** 理由:图像和视频的描述习惯不一样(图像讲构图光线质感,视频还要讲运动和节奏),混成一套会互相干扰。

每一套包含:

| 部分 | 必填 | 说明 |
|---|---|---|
| 风格描述 | 是 | 一段话,例:"港风黑帮、霓虹夜景、胶片颗粒、低饱和" |
| 参考图 | 否 | 几张定调用的图。**从项目资产或资产中心选,不在这里另起一套上传**——避免同一张图在系统里存两份 |

**怎么用**:每次生成时,风格描述**自动拼进提示词**,参考图自动带上。用户能在生成面板上看到"这次带了项目风格",**也能一键取消掉这一次**(取消只影响这一次)。

**不做的事**:不做风格的自动识别、不做风格评分、不替用户判断"你这段描述好不好"。**产品给通道,审美归人。**

### 4.3 提示词模板

> **来源**:验收清单第 5 项「项目提示词配置(图片/视频)」。核查发现这个概念此前只在排期账本里躺着且标注"零实现",从未进入任何一章产品需求文档。

**和风格设定的区别**:风格设定管"长什么样",提示词模板管"提示词怎么组织"。

- 图片、视频各一套模板;
- 模板是一段带占位符的文本,占位符由系统在生成时填入——**至少要支持**:片段内容、角色、场景、风格描述;
- 不填模板时走平台默认模板,**默认模板要能看见、能复制走改**,不是黑盒;
- 模板改动只影响之后的生成,**不追溯重写历史任务的提示词**。

**和「专家逃生口」的关系**(模型章 §二规矩三):专家逃生口是"这一次我自己写、原样发送";提示词模板是"这个项目以后都按这个格式组织"。两者不冲突,逃生口优先级更高——用了逃生口,模板不生效。

## 五、和其他章的边界

- **后台章**:创建平台账号、平台级角色、封禁——本章只管"已有账号怎么进项目";
- **模型章**:哪些清晰度画幅可选、各自什么价——本章只管"这个项目默认选哪个";
- **生产章**:单次生成时提示词怎么最终组装、生成面板长什么样——本章只管"项目级默认值和模板是什么";
- **资产章**:资产本身怎么管——本章只管"风格参考图从资产里选,不另起一套"。

## 六、本章不做什么

- 不做项目模板(建新项目时复制另一个项目的配置)——**下周一范围之外**,想做另开;
- 不做项目归档与回收站——同上;
- 不做跨项目的资产同步——资产章的引用制已经解决了这件事,不重复造。
