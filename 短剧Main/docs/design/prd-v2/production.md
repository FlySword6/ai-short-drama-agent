## 一、生产域动线(唯一主链)

```
项目 → 「生产」页签(集视图 P-02b)→ 场卡 → 段落工作台(P-04)→ 开拍 → 队列(P-10)→ 交付(集视图操作区)
           ↑ 时间线带速览                ↑ 备戏台送入(P-03b)     ↓ 失败→改参考重试(队列行内)
```
- 集视图=指挥部:看全集状态、进下一步、审核交付;**不做生成**。
- 段落工作台=唯一生成场所:参考控制包+编译稿+整段开拍/逐镜重生成;**生成永远发生在这里**。
- 队列=等待与并行的锚点:任务四态,失败行必给下一步动作。
- 旧 StoryboardPage/旧 workbench 退役,redirect 见重构靶单。

## 一之补、集的产生(v1.1 回填——v1 通章无「0 集态与集从哪来」的表述,UX 基线 T1 实证为断头 R1)

- 0 集项目的生产页(集视图)空态:唯一 primary=「建第一集」(调 `POST /api/v1/projects/:project_id/episodes`),建成即入常规集视图动线;剧本页 0 集空态同款入口(两处空态不再互相指路)。
- 有集之后:建集入口收进集切换位(形态随 Figma 定稿;P-02b 的 0 集空态帧欠账记 Figma 补帧清单)。
- 集的产生是生产域动作(容器先于内容),不归剧本域;剧本域只负责往集里灌剧本与拆解。

## 二、备与拍的状态机(场级)

未拆解 → 已拆解(P-06 确认写 scenes/shots)→ 备戏中(P-03b 拉件)→ 就位(控制包 x/8 达标)→ 生成中(整段任务)→ 有样片/有成片 → 已交付(主版本入交付清单)
- 「备好再拍」软引导不硬闸:就位不足可开拍,但确认区亮「还缺 N 类参考,通过率会低」(V-29 语义+杠杆话术)。
- 集状态=场状态聚合;集视图下一步条据此给唯一 primary。

## 三、档位与参数(四条铁律)

1. **逐参数独立选**(R90/V-36/V-46):比例、清晰度、时长、数量各自成档,禁复合档位;行业惯例命名(用户有肌肉记忆,R90b)。
2. **API 支持什么就开什么**(V-08/R98③):每模型一张参数矩阵(官方文档为源),平台不阉割;未定价组合置灰并标「联系管理员开通」,不静默失效(V-07 之鉴)。
3. **每档一句大白话**(R126):档位选项内写人话+能力边界;「档位是计价单位,不是能力天花板」口径文案全站一致。
4. **默认层**:720p 默认 / 只音效不 BGM / 时间码不进提示词。
   > **2026-08-06 更正**:原文这里写的是「服务端硬约束,前端只显不改」——**"硬约束、只显不改"已被产品负责人当场推翻**。现口径:清晰度与画幅在项目里定默认值,**单次生成可以改**,可选范围由模型章参数矩阵给,平台不设人为上限。完整定义见 `project.md` §4.1。"只音效不 BGM""时间码不进提示词"两条不受影响,仍然有效。

## 四、编译稿(生成的唯一提示词通道)

- 两层:包级(自动,参考即语义只写增量)+镜头结构(逐镜,导演可改)。
- 禁小作文;引用语法按 Readme「官方语法速记」(图片N/主体先定义后引用/分镜时序/特殊符号词表/固定尾注)。
- 提示词优化/翻译=ai 网关 purpose,可选档(quality/fast),真调模型(V-13 之鉴)。

## 五、开拍与重生成

- **整段开拍**=一次创建 N 镜任务:报价→人工确认(超阈值二次确认)→batch 提交;幂等(client_idempotency_key)。
- **样片先行**=0.6× 计价低档快抽,定稿再放大(Topaz 4K 链排 v0.3.x)。
- **逐镜重生成**=页内确认区,真相行(参考统计+档位档价)+该镜依据;一次一任务闸门。
- 计费三处同源:确认区报价=队列扣账=消耗页明细,数字必对平(S83 账)。

## 六、验收判据(动线级)

从「新建项目」起完整走到「交付本集」,每步:①界面形态=对应 Figma 帧;②状态转换=本章状态机;③文案=文案章三法则;④体验=R139 三阈值。E2E 覆盖主链+失败重试支线;档位矩阵逐模型抽验「选项=官方文档值域」。

## 九、段落工作台重构(2026-08-06 落章)

> **来源**:丽芬 Figma 评论 `1872339874`(2026-08-05 17:08,钉在 P-04b 675:310 的原线程上),另含 `1872493486`(导演台按钮跳转)、`1872083595`(旧版 P-04 能否删)三条同源追问。
> **与主线的关系**:符合 `prd-spine.md` §三之 1「生成面板常驻可用,骨架不是生成的许可证」——本节把工作台从"必须先有分镜才能干活"改成"进来就能改本、就能生成"。
> **状态**:动线与语义在本节定稿;**做到哪一层需产品负责人拍板**(见 9.6)。

### 9.1 她指出的两个真问题

1. **进不去导演台**:P-04b 上没有任何一个可点的地方能去导演台。此前已裁"导演台入口=段落工作台运镜行进入"(D-3),但帧上只有一行文字注记,不是入口。
2. **换不了分镜**:P-04b 一次只能看一个片段,没有在片段之间切换的手段。用户要看第 3 个片段,只能退回集视图再进来。

### 9.2 目标结构(自上而下四层)

```
[顶部] 分镜切换条:按现有素材片段顺序 1 / 2 / 3 … 点击即切换,切换后下方全部内容跟着换
[第二层] 剧情片段:显示并可编辑当前片段已切分好的剧情内容
         右侧常驻「重新生成」——用户改完文字点它,重新生成提示词并重新匹配控制包与视频提示词
[第三层] 三个页签:工作台 / 参考图 / 生成视频
[第四层] 页签内容区
```

**「重新生成」的语义**:它重算的是**派生物**(提示词、控制包匹配、视频提示词),不是重跑付费生成。**付费生成仍然必须由人再点一次**(AGENTS.md 第 4 节红线不动)。

### 9.3 三个页签各管什么

**页签一 · 工作台**(即现有的参考控制包)
- 控制包内每一项可删除,也可从项目资产或资产中心引入;
- 新增「+ 新增参考」——加一项控制包条目;
- 该项可跳到「参考图」页签去生成或调整这张参考图;
- 控制包里已有的图也能点进「参考图」页签调整。

**页签二 · 参考图**(新增,本次重构的重心)
- 从工作台点进来的图在这里形成一条记录;
- 对图做处理(参照 LibLib 那类图像处理能力:局部重绘/扩图/换背景一类),**处理结果作为新数据存在本页签下,可二次、多次处理**;
- 本页签下所有记录都可删除,也可回填到工作台的某一项控制包——**回填到哪一项由用户自己填或选,产品不替他猜**;
- 除了处理已有图,还能**生成分镜**。一个按钮给三个出口:
  - **9 宫格分镜图**:按当前片段剧本内容 + 已有资产,出一张 9 格图;
  - **25 宫格分镜图**:同上,25 格;
  - **自定义分镜**:开弹窗,见 9.4。

**页签三 · 生成视频**
- 汇总工作台控制包里所有相关内容,整合成一条视频提示词;
- 这条提示词**既能让 AI 反复重写,也能人工直接改**(与模型章「专家逃生口」同源);
- 下方选**画幅比例**与**模型**(例:快乐马 / Seedance / MiniMax 等,以模型章注册表为准,不在本章写死名单);
- **生成出来的视频也有版本**,与图片版本同一套语义。

### 9.4 自定义分镜弹窗(五区)

| 区位 | 内容 |
|---|---|
| 左 | 每个分镜的**内容 + 提示词**,固定高度;**支持新增分镜** |
| 中 | 由「分镜内容 + 分镜提示词」生成的分镜图 |
| 右 | 选中分镜图的放大 |
| 最右 | 该分镜图的**版本列**;主图和版本图**都能点进导演台**,在导演台调整后生成新的图 |
| 底 | 所有分镜图的**时间轴预览** |

**关闭弹窗后**:本次生成的所有分镜图在「参考图」页签里合并为一张宫格图,作为一条记录留下。

### 9.5 版本语义(与资产章统一)

- **改提示词后重新生成 = 产生新版本**,不是覆盖原图(资产章同款口径,见 `assets.md` 版本节);
- 视频与图片共用一套版本语义:主版本指针 + 历史版本可回看;
- 版本可加**备注**,可填可不填(来源:丽芬评论 `1872107511`)。

### 9.6 【待产品负责人拍板】本期做到哪一层

丽芬原话:「上面的这些生产需要确认一下版本的迭代,是否是在本期完成」。四层递进,越往下越贵:

| 层 | 内容 | 判断 |
|---|---|---|
| L1 | 顶部分镜切换条 + 剧情片段可编辑 + 重新生成派生物 | 成本低,直接解掉她的问题二 |
| L2 | 三页签骨架 + 工作台页签(现有控制包平移) | 主要是版式活,不新增能力 |
| L3 | 参考图页签:图像处理链 + 9/25 宫格 | **2026-08-06 更正:不缺模型,缺接线。** 实测查清 Seedream 5.0 Pro 支持交互编辑(框选/坐标写进提示词),走的是我们已在调的同一个接口;卡点是后端参数白名单显式拒收 mask 类键、前端没有入口。详见 `models.md` §六。**成本从"接新供应商"降为"改白名单 + 建入口"** |
| L4 | 自定义分镜弹窗 + 生成视频页签的模型选择与视频版本 | 最大一块,牵动生成链与计价 |

**建议**:L1+L2 本期做(问题解掉、结构立住),L3/L4 按模型接入进度排。**这条不定,原型不动 P-04b 的主结构。**

## 十、生成结果的"选用"(2026-08-06 产品负责人拍板)

> **来源**:补下周一验收范围时,原型上「选用这张」这个按钮的语义此前从未定义过——同一个按钮,开发可以理解成"设为主图"、"存进资产库"或"标个星",三种做法的数据模型完全不同。**产品负责人 2026-08-06 拍板:选用 = 设为这个镜头的定稿。**

### 10.1 定稿是什么

一个镜头生成了四张图,用户挑一张点「选用」,**这张就是这个镜头的定稿**:

- **其余的不删**,作为历史版本留着,随时能翻回去、能改判;
- **下游一律默认用定稿**:拼片、导出、拿去生视频、给剪辑交接,取的都是定稿这一版;
- **改判就是重新点一次**——选另一张为定稿,旧定稿退回历史版本。不需要先取消再设置。

**视频同一套语义**:一个镜头生成了几条视频,挑一条设为定稿,下游默认取它。

### 10.2 和"存进资产库"是两回事,别混

| 动作 | 意思 | 作用范围 |
|---|---|---|
| **设为定稿** | **这个镜头**用这一张 | 仅当前镜头 |
| **存进资产库** | 以后**别的镜头**也能拿它当参考 | 整个项目乃至通用库 |

两个动作可以对同一张图先后做,互不冲突。**界面上要分得开**——一张图既是本镜定稿、又已入资产库,这两件事要能同时看出来。

### 10.3 没选之前呢

- 没人点过选用时,**默认最新生成的那一张是定稿**——不要让用户为了往下走而被迫先点一次;
- 但"系统默认的"和"人挑过的"要能区分:人挑过的要有痕迹,免得后面有人以为这是随便来的。
