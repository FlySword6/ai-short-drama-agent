## 一、三法则(全站,前后端同责)

1. **业务语言**:用户可见文本零技术词——厂商名、HTTP 码、英文错误串、内部状态机名、字段名、路径,出现即缺陷。程序判断走 code,人看的走 message,两层永不混用。
2. **片场口吻**:说导演听得懂的话,句式=「[哪件事]没成:[原因大白话][,下一步]」。范例:「生成图片没排上:积分不够——还剩 460 点,这单要 600 点。充值或先用低档试试。」反例:「配额校验失败(quota_exceeded)」。
3. **真话原则**:界面只承诺已实现的行为(回收站假承诺为鉴);能力边界写在选项里(R126:每档一句大白话),不静默失效(V-07 为鉴)。

## 二、错误信封字段语义(后端合同)

统一信封 `{ok:false,error:{code,message,retryable,details}}` 维持,字段职责收紧:
- **message**(必填):中文业务话,按三法则句式。任何 throw 路径必须落一个人话 message——直接透传 error.message 的地方都算待修。
- **code**:机器判断用,前端只用于分支逻辑,**永不展示**。
- **details**:默认 null。校验类错误只放 `{fields:["角色名","集数"]}`(中文字段名,供前端标红),**Zod issues 原始结构不再出信封**——这是 82.7% 路由的共性修法:parseRequest 包一层 issues→中文 fields 翻译(字段名词表见 §四)。
- **retryable**:驱动前端「重试」按钮显隐,语义=「原样重发有意义」。

## 三、三条旁路的收口(sol 实装映射)

1. **助手 SSE**:`{"type":"error","message":…}` 的 message 过 publicMessage 映射后再发;运行时原文只进服务端日志。
2. **异步任务字段**:`failure_reason/error_code/phase` 是审计资产,保留;新增 **`display_reason`**(中文业务话)——前端一律只显 display_reason,旧字段不再直接上屏。生成/上传/音频三链同改。
3. **媒体流 416/错误字节**:后端保持流语义,前端媒体组件统一兜底文案「这段素材暂时读不出来,刷新试试;还不行就重新生成」。

### 七之三、有争议,待拍板(6 条)

不在本表定名,拍板后补入七之一。详情与证据行见盘点报告第三节栏二。

1. **档位 还是 参数选项** — 模型章第 28 行要求「面向用户一律说参数选项」,生产章第 33 行要求「档位是计价单位」这句全站一致,两条直接对撞;界面上至少 6 处用户可见文案在说「档位」。

3. **场 和 段落 是不是一回事** — 代码当成一回事,需求文档没说清。
4. **素材库 和 资产库** — 词表 D 已判「素材库指资产库时作废」,但代码里还有 33 处在用,其中 21 处指的是供应商那个素材库(按 D24 属专名例外,不该改),剩下的要改。

6. **备戏** — 三处口径三个层级。
