# 目标形态与两阶段路线

> 立于 2026-07-28,DC 拍板「两条都要,你来分阶段」。
> 这份文件回答的是**「我们要成为什么」**;`version-plan.md` 回答的是「现在做什么」。
> **版本计划的每一档都必须能从这里推导出来**——推导不出来的卡,要么这里错了,要么那张卡是自嗨。

## 〇、第一性(DC 2026-08-04 定盘)

> **「我们平台最主要的核心是能充分方便高效地发挥各个模型的优势和能力。其他都是次要的。模型才是核心,才是重点。」**

三个词各有所指,缺一即偏:**充分**=各家模型的独特能力(参考生成/长镜头/图像编辑/文字渲染/音色……)要暴露给用户,不是接上能跑就完;**方便**=用户不需要懂供应商与参数字典,选对模型干对活的成本趋近零;**高效**=从想法到产物的路径最短,钱花在刀刃上。界面、流程、看板、治理——一切都是为这条服务的手段,冲突时让位。12 人时目标是它在阶段一的度量化身。

## 一、两阶段目标

### 阶段一(现在 → v0.3.0):专业剧组的生产工具

总目标(2026-07-24 立,继续有效):

> **短剧剧组(编导/抽卡师/音频/剪辑)在 12 人时内做出一集能上线的短剧。**
>
> (2026-08-11 订正岗位词:立目标时写的是「导演/美术/剪辑」,
> `prd-spine.md` §三之 2 是产品负责人 2026-08-06 明确确认的裁决——真实四岗是
> 编导、抽卡师即提示词工程师、音频、剪辑,明写推翻三角色。**只改岗位叫法,12 人时那条目标本身不动。**)
> 每个界面、每个功能的存在理由,必须回答:它把哪个生产环节的人时降下来了。
> 回答不了的,就是我们的自嗨。

这个目标的好处是**它可度量、可证伪**。配套验收机制是全流程剧本「一集戏的一天」
(`docs/design/full-flow-screenplay.md`):建项目→导剧本→拆分镜→备参考→做参考图→
回栏→标就绪→生成粗剪→审核→交付。**每档发版前真栈走一遍,任何断点 = P0,不清零不发版。**

### 阶段二(v0.4+):创作平台

服务面从专业剧组扩到个人创作者与新用户。形态信号(DC 2026-07-28 给的一批灵感):
自由画布创作、团队协作与席位、Agent/Skills 分发、自动剪辑 Agent、资产长期沉淀。

**阶段二不是阶段一的替代,是它的外延。** 分阶段的意义在于:阶段一的每一块地基,
都要按「将来要承载阶段二」的标准打,但**不为阶段二提前建界面**。

### 阶段一的核心杠杆(2026-07-29 夜 DC 定桩)

DC 原话:「我们的重点是**通过智能资产库低成本增强视频参考控制效果,进而提高抽卡通过率**。」

操作化(Fable 拟,DC 复核):12 人时目标里最大的时间与积分黑洞是**抽卡失败**——
生成不过关就重抽,烧积分也烧人时。降失败率的杠杆是一个自我强化的飞轮:

> **资产库(沉淀角色/场景/道具/光影/色卡的身份与风格)
> → 参考控制包(把资产变成生成约束,V-15:工作台控制包是唯一参考真源)
> → 生成(约束越完备,通过率越高、单条可用片段的积分成本越低)
> → 回流(通过的产物一键沉淀回资产库成为新资产;失败的沉淀否决原因,R70)**

三条推论,排包与设计都按它过:
1. **资产库的价值不在「存」,在「被引用」**——资产的健康度指标是引用次数与参与生成的通过率,不是数量;
2. **总目标指标 = 抽卡通过率**(等价口径:每条可用片段的积分成本 / 一次通过率),看板与埋点围绕它建;
3. **界面表达**:资产中心按「拿来控制什么」组织(角色一致性/场景/道具/光影/色卡/运镜),
   工作台展示「参考控制包完备度」并与预估通过率关联,失败态引导「补哪类参考」而不是「再抽一次」。

与既有真源的勾稽:五层工程论的 context 层(§六)正是这条杠杆的工程面;
V-17/V-18(抽象参考:光影/色卡)、V-19(未过审资产不进付费生成=钱的安全)、
R84(视频语义检索)全部服务此杠杆。

## 二、共用底座(两个阶段都要,所以现在就要打对)

这三件是分阶段的关键——它们既服务 12 人时,又是创作平台的地基。**优先级最高。**

| 底座 | 阶段一的用途 | 阶段二的用途 | 现状 |
| --- | --- | --- | --- |
| **对象关系**(每个对象回答:我从哪来 / 我被谁用 / 下一步干什么) | 剧组不迷路,减少来回找东西的人时 | 画布的节点与连线就是它的可视化 | 病根未除(见下) |
| **资产即记忆**(角色/场景/风格跨项目沉淀,可检索、可复用、可审) | 备戏环节人时的大头 | 创作者的个人资产库、团队共享库 | 分类错、开发环境看不到 |
| **生成链**(报价→确认→消费→归属→成本) | 花钱可控、算得清账 | 席位与积分体系的底层 | 已较扎实(S57/S67/S84 在做) |

## 三、四条病根(2026-07-24 诊断,至今第一条仍是根)

1. **以数据模型为中心组织界面,不是以生产流为中心。** 用户脑子里的顺序是「备戏→拍→审→交」,
   我们的界面是数据库表的 CRUD 投影。**资产不是「一行记录」,是「这场戏的一把刀」。**
2. **实现了「能力」,没实现「完成感」。** API 通、测试绿就算交付,但用户要的是走得通:
   做了→看得到→回到该在的地方→知道下一步。**走得通才是完成态,API 只是半成品。**
3. **把选择权错当成体验。** 平台定位是降低用户对 context 的管控负担——把默认做对,
   自定义做成逃生门,而不是把每个决定摆到用户面前。
4. **工程视角泄漏到用户空间。** 债务台账属于 repo;用户空间只有两种状态:能用,
   或者用用户语言说「即将上线」。

**2026-07-28 实证:病根 1 一条同时解释了当天暴露的三个问题**——资产类型把「动物」
与「角色」并列(数据库枚举思维,片场里没人这么分)、通用资产库界面看着是空的
(用户要的是「这场戏能用的资产」,我们给的是一张全表)、工作台大片空白
(按数据结构排,不是按人干活的顺序排)。**修病根 1 的杠杆高于加任何新功能面。**

## 四、排包原则(从上面推导,即刻生效)

1. **走通优先于新功能**(DC 2026-07-28 复核确认仍作数):断头补完之前不开新功能面,
   上线流程除外。已开的设计语言包收尾即可,画布挂起等对象关系理顺。
2. **每个任务包必须回答一句**:它把「一集戏的一天」里**哪一步**的人时降下来了?
   回答不了就不派。这一句写进任务包抬头。
3. **每档发版前跑一次全流程**,断点 = P0。
4. **默认智能、选择兜底**:先问「平台能不能替用户把这个决定做对」,能就做成默认+可改。
5. **底座按阶段二的标准打,界面按阶段一的需求做。** 例:画布引擎归一(ADR-0001)是底座
   决策,现在定;画布界面本身排在对象关系之后。

## 六、产品原则:生成能力按五层做(2026-07-29 DC 定,ADR-0003)

DC 原话两次:
> 「生图生视频你当做一个 context engineering 就行,我们平台就是要**简化人脑对于 context 的思考难度和管控难度**,尽量让使用者舒服、高效。」(07-24)
> 「生图生视频生音频都是生成式模型……在 LLM 这里依次发展了 prompt → context → harness → loop → graph engineering。多模态生成的工程和产品原则,可以借鉴 LLM coding 的最新实践和思想。」(07-29)

**五层**:prompt(一次说清楚)→ context(带什么材料)→ harness(出来的对不对)→ loop(不对怎么收敛)→ graph(多步怎么编排)。
**每张生成类卡必须说清自己在哪一层。**

**三条不照搬(判据,违反即打回)**:
1. **多模态没有编译器**——harness 分「机器判据」(一致性/色板/画幅/音画对齐/标识完整/未过审混入)与「人判」(美感戏感节奏)两层;
   产品的活是**把可算的自动挡掉,让人只看不可算的**,不是加个审核按钮。
2. **迭代经济学反过来**——LLM 试十次是常规,视频试十次是烧钱;loop 靠**廉价代理**(低分辨率先出运镜构图,确认后上贵模型),
   每个生成动作都要能回答「这一步的代理是什么」,答不上就是抽卡。
3. **context 是选择不是堆砌**——参考图收得下的数量有限,核心动作是压缩取舍;
   「简化人脑对 context 的管控」的技术含义是**替人先选好并说明为什么**,不是让人少填。

**当前自评**:context 最成熟,prompt 有设计缺实现,**harness 与 loop 接近空白**,graph 在建(画布)。
**空白两层正对应总目标里最贵的人时——抽卡。杠杆在这里。**
