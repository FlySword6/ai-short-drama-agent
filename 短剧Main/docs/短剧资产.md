# 短剧资产智能体阶段汇报

汇报日期：2026-07-10

## 一、汇报结论

短剧资产智能体已经完成第一阶段可演示原型。

它现在可以把已有的 Excel 资产表、图片素材和结构化数据统一入库，并支持用自然语言检索角色、场景、服装、道具等资产。系统已经从“技术验证 Demo”推进到“可以围绕短剧制作场景试用的资产管理原型”。

下一步重点不是继续堆技术，而是围绕真实制作流程做三件事：补全资产数据、稳定检索效果、接入分镜需求，让系统真正帮助团队更快找到可复用资产。

## 二、为什么要做

短剧制作过程中，资产复用价值很高，但目前存在几个明显问题：

| 现状问题 | 影响 |
|---|---|
| 角色、场景、服装、道具分散在 Excel、图片文件夹和人工整理文档里 | 找资产主要靠人记忆和人工翻表 |
| 图片和资产字段没有统一结构 | 同一个角色或同类素材很难复用 |
| 只能按文件名或表格字段查找 | “找一个反派气质强的中年男性角色”这类需求很难直接检索 |
| 历史素材沉淀多，但缺少智能检索入口 | 资产复用效率低，重复制作成本高 |

所以这个项目的目标不是做一个聊天机器人，而是做一个面向短剧制作流程的“资产智能检索和复用入口”。

## 三、当前已经完成的能力

### 1. 资产可以统一入库

目前系统已经支持三类资产来源：

| 资产来源 | 当前能力 | 业务意义 |
|---|---|---|
| Excel 资产表 | 上传后自动解析资产字段和图片 | 兼容现有资产整理方式，不要求业务立刻换流程 |
| 图片素材 | 上传图片后自动识别资产信息并入库 | 可以处理“只有图、没有表”的素材 |
| 结构化数据 | 支持外部系统直接提交资产数据 | 方便后续接入标注系统、制作系统或其他 Agent |

入库后，系统会保存资产名称、类型、简介、外观描述、图片地址、项目来源等信息，形成统一资产库。

### 2. 支持自然语言找资产

现在已经可以用接近业务表达的方式检索资产，例如：

```text
找仙侠男主相关的角色素材
找一个年纪偏大的长辈角色
找反派气质比较强的男性角色
找穿古装长袍的角色
```

系统返回结果时会展示：

- 资产名称
- 资产类型
- 简要描述
- 主图
- 匹配分数
- 入库耗时信息

这意味着业务人员不需要知道资产表字段怎么写，也不需要知道文件夹在哪里，只要描述需求，就能找到候选资产。

### 3. 图片入库已接入演示页面

当前前端已经支持直接上传图片。图片上传后，系统会自动识别：

- 这张图更像角色、场景、服装还是道具
- 图中主体是什么
- 适合什么短剧场景使用
- 外观、服装、风格等描述

同时图片会上传到对象存储，资产库中会保存可访问的主图地址。

### 4. 初步形成效果评估方法

现在已经开始建立固定测试问题和检索结果记录，用来判断每次优化后效果有没有变好。

后续会继续补充评测集，形成更稳定的指标，例如：

- Top 1 是否命中
- Top 3 是否有可用结果
- Top 5 可用率
- 描述型问题的命中质量

这可以避免系统只靠主观感受判断好坏。

## 四、当前可现场演示的内容

建议现场演示控制在 3 到 5 分钟，重点展示“业务能看懂的结果”。

### 演示 1：上传图片自动入库

演示步骤：

1. 选择一张素材图片。
2. 点击“开始入库”。
3. 展示系统自动生成的资产名称、类型、描述和主图。
4. 强调：只有图片也能沉淀成可检索资产。

建议讲法：

> 以前只有图片时，需要人工命名、归类、写描述。现在系统可以先自动完成第一版资产识别，后续人工只需要审核和修正。

### 演示 2：上传 Excel 批量入库

演示步骤：

1. 上传一份角色或场景 Excel。
2. 展示系统批量解析结果。
3. 展示资产和图片已经进入统一资产库。

建议讲法：

> 这一步主要解决历史资产表的迁移问题。我们不要求业务方重新整理格式，而是尽量兼容已有 Excel。

### 演示 3：自然语言检索资产

建议提前固定几条稳定问题：

## 六、业务价值

### 1. 提升资产复用效率

制作团队可以更快找到已有角色、场景、服装和道具，减少重复制作。

### 2. 降低历史素材整理成本

历史 Excel 和图片文件夹可以逐步进入统一资产库，不需要一次性人工重做。

### 3. 支撑后续制作智能化

当资产库和分镜数据打通后，可以进一步做到：

- 根据分镜推荐角色
- 根据镜头需求推荐场景
- 根据服装描述推荐已有造型
- 根据项目风格推荐可复用资产

### 4. 为资产管理沉淀数据基础

后续可以继续扩展审核状态、复用范围、项目来源、版权信息、素材质量标签等字段，形成更完整的资产中台能力。

## 七、当前限制

| 当前限制 | 说明 | 后续处理 |
|---|---|---|
| 检索效果还需要更多样本验证 | 目前演示样本可以跑通，但还需要更系统评测 | 补充 50-100 条固定测试问题 |
| 向量文本颗粒度还比较粗 | 目前更偏整段资产描述向量化，细节属性命中不够精确 | 按名称、身份、外观、服装、发型、风格、剧情用途等属性拆成子文本向量 |
| 图片识别速度受模型影响 | 图片入库主要耗时在视觉模型调用 | 固定更合适的视觉模型，并记录耗时 |
| 负向条件还不够完善 | 例如“不要男性”“不要现代”还需要更强过滤 | 增加过滤和降权规则 |
| 分镜还未完全接入资产推荐 | 当前重点还是资产入库和检索 | 下一阶段接入分镜需求 |
| 结果还需要人工审核机制 | 自动识别可能存在描述偏差 | 增加审核、修正和确认流程 |

## 八、下一步计划

### 第一阶段：让演示稳定

| 任务 | 目标 |
|---|---|
| 固定 5-10 条演示问题 | 保证现场展示稳定 |
| 整理演示截图 | 方便汇报材料使用 |
| 明确图片模型配置 | 避免图片识别误用字段提取模型 |
| 记录每次入库耗时 | 方便判断慢在哪里 |

### 第二阶段：让效果可评估

| 任务 | 目标 |
|---|---|
| 扩充评测问题 | 覆盖角色、场景、服装、道具、负样本 |
| 输出评测报告 | 每次优化都能看到效果变化 |
| 补充人工标注 | 明确哪些结果算命中 |
| 细化向量文本 | 把资产描述按多个属性拆成子文本向量，提升细节检索命中率 |
| 建立父子块召回 | 检索先命中子文本向量，再回数据库召回完整资产信息 |
| 优化排序逻辑 | 提升 Top 3 / Top 5 可用率 |
