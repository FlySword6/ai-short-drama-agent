**真源节点**(单写者=Fable,唯一现役答案):
- orchestration.md(R 表+日志+DAG 快照)——系统事实流水
- version-plan.md(版本卡与排期)/ dc-verdicts.md(裁决台账)
- dc-feedback-ledger.md(需求评审台账,180 条五尺账)
- PRD v2 各章(冻结一章生效一章)/ Figma 05(视觉与交互唯一真源)

**闸门节点**(全自动,红=不过):术语门禁(commit 前)→ npm test 三数(合流)→ E2E+体验门(发版)→ 变异验证(验收抽验)→ 顾问必咨(六情形裁决前)→ 授权闸(高影响动作,DC 点名/飞书)。

**资源节点(v3 新增,第五类)**:8000 端口/dev PG/E2E 窗口/kimi·sol 会话/各 worktree 写权——共享且会被并发争抢的运行时对象。账=orchestration「资源注册簿」常驻节(只登记慢变四列:资源/互斥类型/现查命令/让渡规则;**持有人一律现查不登记**——表与 ps/lsof 可能不一致的格删掉);判据命令=handover ⑤ 系与 §1。**派发与发针前先按注册簿现查资源**,冲突=排队不并发。会话是消耗性资源:满载即按轮替剧本换代(sol 05:56 先例=统筹代笔冷启动三指针)。

**通道节点**:kimi=全长 id resume(串行,真响应判活)/sol=codex exec resume/worker 上行=收件箱(/tmp/fable-inbox-*+outputs「Fable 亲启」,10min 轮询)/DC 介入=**orchestration「待 DC」节(台账真源,先写)+飞书推送(送达通道,后发)**——飞书故障时台账仍是全量账/团队=issue #10(人类 PR 经 sol 值守→Fable 落账)/作业面=plane/e2e 报告→统筹定性。

## 二、边(工序主链与回路)

```
DC 输入 → 【输入闸】→ 台账评审(五尺) → 真源 → plane → goal 派发
                                    ↓                        ↓
                              (判否/缓→复核节)          施工(worker)
                                                            ↓
发版 ← 合流(门禁) ← 验收(动线级+变异) ← DONE tag ← 自验(E2E)
  ↓                      ↓红                ↓红
线上实测+e2e 报告    回滚整批           打回(过顾问)
```
失败回路全部有向:门禁红→回滚;验收红→打回(顾问);发版红→不报成功只报卡点;通道假送达→handover ⑤c 判据重发。
**边约束(v3 新增,三类事故的公共病根一般化)**:**异步动作引用的对象必须钉死不可变引用,或发出前一刻现查**——后台合流锚 tag/commit 禁分支名(分支会被续推)、发针前验上针已退(会话上可能有活 run)、共享库迁移前盘活连接(库被活进程连着)。今夜三类事故(未验收件搭车/幽灵叙事复刻/047 打爆兄弟线)同此一构。
**跨接缝标准边(v3 升格)**:跨仓/跨主线消费的**新合同**必经「形状稿先批」(sol 三例实证零复议;纯内部实现不强制,防速度减半)。

## 三、稳态机制(本文新增的核心)

### 1. DC 输入闸(避免「犯糊涂影响稳态」的正门)
判定顺序三问:**要我回答吗→改在途工序吗→改规则吗**;细分七类七路,**默认不直接改在途工序**:
| 类 | 判 | 路 |
|---|---|---|
| 拍板/授权/执行令 | 回答选项、飞书回音、主动令(发版/停手/转向/凭据策略) | 直接生效,落 R/V 号 |
| 新需求/玩法 | 「琢磨琢磨」「怎么用上」类 | 进台账评审(五尺)→排队;当轮只回方案不动工序 |
| 纠偏/不满 | 「怎么还是旧的」「太丑」类 | 立卷+快速对账:在途状态有 R 号依据→给证据不动工序;无依据=统筹失误→按叫停处理 |
| 机制/规矩变更 | 改的是我们怎么干活,不是产品 | 落 ground-rules/handover 自进化+立 R 号+当轮回报改了什么 |
| 问询/对账 | 「清晰吗」「到哪了」类 | 答三窗口口径(版本+可验+待拍板/DAG),不动工序 |
| 资源/信息 | key/白名单/账号类 | 即收即用,回音一条 |
| 情绪/自省 | 「我犯糊涂」类 | 记语境;**藏令检查**:句含祈使/因果指令词(「别…」「要…」「才…的」)或与同消息他句构成授权→改道对应类,回话里复述提取出的指令供 DC 一眼否认 |

**复合消息规则**:逐句分类,一条消息可落多类各走各路(R147 三连、R152 三件为范)。**兜底行**:分不进的当轮复述给 DC 确认,不许硬塞。
**矛盾检测边**:新输入与既有 R/V 撞→当场指出+给收敛建议,不默默执行最新一条(R149);裁决台账「状态会变,原话不变」。
**入在途判据(四种)**:生产事故/发版指令/DC 明说「现在就要」/**DC 叫停或转向在途工序(停手即时生效,重排成本显式报 DC)**。其余一律排下一窗口,并告知排到哪。

### 2. 在途工序保护
- 施工块原子性:一个块(如 Figma 七步/重构块 1)进行中,新需求不拆入,除非过入在途判据;中断要算显式成本(改锚/重验收)并报 DC。
- **执行方自组织协调(v3 升格,定位=第二道防线)**:并行 run 相遇时的占位通告/让位/作废声明/如实报备(kimi 今晨三例)是值得保留的涌现——但**统筹侧验退仍是第一道防线,自组织不减免 ⑤e 责任,违者照记事故**(三例自组织全部发生在统筹违规或漏检在先的场景)。
- 单写区/串行通道/验活判据:见 handover §2⑤/⑤c/§4(操作层唯一真身,此处不复写)。
- **旁路边(合法,配回流)**:DC 可直连 kimi/sol 会话(R146 常备通道)——直令内容回流输入闸补立 R 号;worker worktree 出现非派发产出先验身份再定性(2026-08-02 凌晨有身份不明施工先例);「身份不明产出」第三次出现→向 DC 申请直连会话只读可见性。

### 3. 可观测与可恢复
- DAG 快照:orchestration 常驻节,每轮巡检刷新;DC 三窗口=对话汇报(版本+可验+待拍板)/plane/#10。
- **环境水位读回(v3 新增,动作不是表)**:8000 三元组=码水位(dist 对应 commit)+env 指纹(读哪份 .env)+库水位(迁移号)——服务换代后必读回验证(health/login/新路由三项,08:24 实践升格);巡检轮抽核三元组一致(码≥库、env=集成区);「配置开对地方、进程跑错地方」只有读回防得住,静态登记防不住。
- 全系统可从真源冷启:handover §1-§6+本文=重建手册;真源全量清单以 handover §4 表为唯一账(本文不再列副本)。
- 心跳=推进器不只是监视器(阶段性形态见 handover §2,含失效条件,不在本文固化)。

### 4. 规则自愈
- 同类事故第三次→固化为守卫或纪律条(已成惯例:push 水位/验活判据/迁移领号)。
- dc-ground-rules 自进化节=规矩层的新陈代谢;本文=结构层,handover=操作层,互不重复。

# v4(2026-08-03 晚,R177:八轴分工重构——DC:「别按人类这种划分方式了」+「我需要稳态开发和自进化正向优化」)

## 4.0 为什么重构:5173 质量事故的体系诊断

DC 判定「现在的体系开发出的 5173 版本不行」。根因不在某个 worker,在体系四环:
1. **goal 写成 task**——压制了 agent 智能,worker 照单施工不思考用户(已立判据,规矩 2);
2. **taste 闸在事后**——IA 断裂(tab 乱序/无集切换)靠 DC 走查才暴露,统筹的产品 taste 责任前置不足;

4. **分工按人类职能(前端/后端)**——没按 agent 真实能力轴匹配任务。
v4 针对这四环改。

## 4.2 路由判据(任务→worker,按轴匹配不按职能)

1. **risk_boundary 一票否决**:任务触及的系统超出 worker 风险边界=不路由,升级到有权者。安全>成本>速度。
2. **context_scope 防污染**:需要「无既往包袱的独立眼睛」(复审/对照/审计)→Opus(零污染);需要全图(跨仓/跨版本裁决)→Fable;单仓深耕→驻场主线(kimi/sol)。
3. **capability 匹配**:审美与 IA→Fable 裁+DC 终审;严谨长链(迁移/合规/凭据面)→sol;界面手感与快迭代→kimi;机械例行→sonnet。
4. **cost 阶梯(细化)**:sonnet(采集)→Luna-max(执行器/脚本/回执/文档工程类独立包)→kimi/Sol-max(驻场主线重活)→Opus(独立复审)→Fable(裁决/taste)。先问低档够不够,不够再上;Fable 例行绝不烧。
5. **gate 不可下放**:验收/合流/发版签永远 Fable;付费生产/发布/预算永远 DC。worker 自报永远要抽验(防幻觉五条)。
6. 新 worker(未来加人/加模型)入列=先补八轴画像再路由,没画像不派单。

## 4.3 稳态三闸(治 5173 病根)

- **闸一·goal 出门检**:界面类 goal 必附「用户流动线判据」(起点→终点每步用户看到什么,引用原型帧/PRD 节);缺动线判据的 goal 不许发。goal=目标+判据+边界,how 归 agent。
- **闸二·合流走查**:合流任何界面改动前,Fable 用浏览器把改动页的用户动线亲走一遍(五分钟级,taste 责任的前置形态);走不通=不合流,当场退回。
- **闸三·发版走查**:发版前 Fable 全流程走一遍(选题→剧本→资产→生产→交付),DC 抽查;走查产出直接进靶单。
三闸对应三个时机:派单前/合流前/发版前——taste 从「事后挨批」改为「三道在线闸」。

## 4.4 自进化回路(正向优化的机制位,全部已有,此处收敛成图)

```
        ↑                                                                    ↓

```

- 进化的验收:每条机制修订要答得出「治哪次教训」;答不出=摆设,删(与规矩自查同判据)。

> 本节加的是**权限轴**(谁有权定什么)。两轴叠加:派单看八轴,裁决看批阅点清单(真身=delivery-workflow「四」,此处只声明节点与边)。

## 5.1 角色节点更新(常委编制)

DC(主席:方向/终拍板/用人/高影响授权)→ Fable(常委会秘书长兼纪委,**只在四类点出现**:主持裁决会/守真源/taste 终审/巡视抽查)→ 四条线:产品设计线(opus 档)/工程线(codex 三档+kimi)/巡视线(sonnet 档,**不隶属任何施工线**)/文书情报线(pi+公司网关)。
编制真身与组织图=delivery-workflow「一、编制」。v4 表中 gate_authority 列按此修订:线内日常验收签=复验人(双首长制),taste 终审/合流签/发版触发=秘书长,高影响=DC。

## 5.2 新增边(五条)

| 边 | 方向 | 载体 | 约束 |
|---|---|---|---|
| 条子边 | 线→秘书长 | 扫描表④节(急件可单投,同格式) | 证据只收命令输出或文件路径;无证据退回补证 |
| 扫描表边 | 文书线汇总→秘书长 | `outputs/cabinet-scans/scan-YYYYMMDD.md` | 每工作日一份;七节不许删,空节写「无」 |
| 巡视直达边 | 巡视线→DC+Fable | `outputs/inspection-reports/` | **不经施工线转手**;至少每日一巡+每次部署后一巡 |
| 抽查边 | 秘书长→任意线已验项 | 扫描表③节抽样复跑 | 不定期;**失实=该轮全部重验**,失实方记档 |
| 双首长约束 | 施工边×复验边 | 派单时指定 | 同一交付包的施工端点与复验端点必须是不同会话/模型;自报不作数 |

## 5.3 输入闸增补(裁决分流)

v3 的 DC 输入闸七类七路不变。新增 **worker 侧裁决分流**:线内冒出的待定项先过批阅点清单三段判定(先 DC 段→再上会段→都不触=线内自决),线内自决项**不上行**——这是「裁决权按条线切开」在图上的形态:上行边只走真需要上行的流量,秘书长节点不再是全量裁决的汇点。

## 5.4 失败回路增补

- 抽查失实→该轮全部重验(重验流量回到复验边,不回施工边);
- 打回条子→退回提交线补证或改选项,不改批阅点归属(归属争议本身=新条子);
- 巡视发现 `[漏项]`→当场补卡+记入观测「巡视发现率」;连续漏项=请示报告制失效信号,升级 DC。
