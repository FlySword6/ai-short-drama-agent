# 拆解质量评测基准

回答一个问题:**换了模型、换了实现之后,拆解到底变好了还是变坏了。**
凭感觉说「跑通了」不算数,这里给的是同一批剧本、同一套参照答案、同一条命令算出来的数。

## 一条命令

```bash
BREAKDOWN_EVAL_DATA_ROOT=<剧本正文目录> \
  npx tsx scripts/eval/breakdown/run-eval.mts \
  --out outputs/breakdown-eval-report-<日期>.md
```

会依次做三件事:按配置连跑 → 与金标对照打分 → 写出报告。
**每一次运行都是真实模型调用,花真钱。** 先用 `--episodes ep-idb-13 --repeats 1` 试算再放量。

常用开关:

| 开关 | 作用 |
|---|---|
| `--phase run` / `--phase score` | 只连跑 / 只用已有产物重新打分(打分不花钱,可以随便重算) |
| `--episodes a,b` `--models a,b` `--repeats N` | 缩小范围 |
| `--skip-existing` | 断点续跑,已有产物不重新付费 |
| `--runs-dir DIR` | 原始产物放哪(默认 `eval/breakdown/runs/`,不入库) |

## 目录

| 位置 | 是什么 |
|---|---|
| `eval-config.json` | 跑哪些集、比哪些模型、连跑几次、单价与单价出处 |
| `gold/asset/` | 参照答案:这一集要备哪些角色/场景/道具 |
| `gold/scene/` | 参照答案:分几场、每场几个镜头(口径见 `gold/scene/RUBRIC.md`) |
| `gold/continuity/` | 参照答案:哪些实体跨镜复用、哪里需要新变体 |
| `scripts/eval/breakdown/harness/` | 打分与报告的实现,`metrics.test.ts` 钉住口径 |
| `scripts/eval/breakdown/*.py` | 从 PDF/DOCX 抽正文、校验金标锚点(一次性数据准备,用 pdfplumber) |

## 剧本正文为什么不在仓库里

正文是版权件。仓库只存金标,金标里存**正文的 sha256 + 行号锚点 + 引文片段**——
既能证明标注确实对着这一版正文做的,又不把整本剧本复制进代码库。
正文对不上 sha256 时校验脚本直接报错,不会拿旧正文去对新金标。

## 指标口径

| 指标 | 怎么算 |
|---|---|
| 稳定性 | 同一集连跑 N 次的成功率;成功那几次之间场数/镜数/角色数的标准差与变异系数;角色集合两两 Jaccard 的均值 |
| 准确率 | 拆出来的角色/场景/道具里,金标里真有的占比 |
| 召回率 | 金标里的角色/场景/道具,被拆出来的占比 |
| 耗时与成本 | 端到端耗时、输入/输出 token;**只有查得到公开单价的模型才折算成钱**,查不到就只报 token |

两条判分规矩,写在这里免得以后有人凑数:

- 金标里标了 `disputed`(两种读法都立得住)的条目,**既不算命中也不算误报**,不进分母;
- 金标里标了 `excluded`(明确判定不该当资产)的条目被拆出来,**算误报并单独点名**——
  这类错最能说明模型在编。

## 金标是怎么来的、可信到什么程度

- 标注人是 `claude-opus-5`,**只读逐集正文**,全程没有调用平台拆解功能、没有看过任何模型的拆解输出;
- 每一条都带行号锚点与引文,`scripts/eval/breakdown/verify_gold_*.py` 会回查正文:
  引文对不上行号、或正文 sha256 变了,就报错;
- **目前是单标注员草稿**:场边界这一层争议小(有场次标记行兜底),镜头数这一层争议大。
  要当最终真值,还需要第二份独立标注 + 分歧裁定,以及一轮抽样人工校验。
  这两件事没做,报告里按欠账列出来,不冒充已完成。
