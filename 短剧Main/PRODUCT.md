# 产品合同

## 产品定位

这不是一个把模型接口包起来的“生成工具”，而是一套 AI 短剧生产系统。

人是主编、导演和责任主体：制定规则、做关键决定、监督过程并对结果负责。AI 是可以被调度的剧组：理解上下文、准备草稿、检索素材、操作工具、执行低风险工作，并把需要人判断的事项送到面前。

V0.1.1 的目的不是覆盖完整制片流程，而是先形成一个真实可用的生产底座：资产入库检索、3D 导演台、多模型人工生成、Pi 智能工作区和结果沉淀在同一个项目中顺畅协作。

## 用户与角色

- 导演/主编：确定表达、选择版本、处理冲突、判定交付。
- 美术/资产人员：准备角色、场景、道具、服装、动作和镜头参考。
- 抽卡/生成人员：根据草稿和参考执行图片、视频生成，筛选候选。
- 制片/项目负责人：分配责任、查看进度、成本和风险。
- 平台管理者：账号、角色、模型、预算和安全配置。

账号的角色、项目成员关系和当前责任决定用户看到的入口。不同角色不是同一个大后台的不同按钮权限，而是不同的工作首页、待办和默认上下文。

## 企业成员登录

v0.4.0 增加单企业企业微信自建应用的内部成员登录。企业微信只证明外部成员身份；平台账号状态、平台角色、项目成员关系、`users.ui_mode`、会话和审计责任仍以本系统 PostgreSQL 为唯一事实源。

- 外部身份固定为当前 CorpID 下的企业微信 `userid`，只接受应用可见范围内的内部成员。
- 首次登录可以即时创建平台账号，但权限固定为 `member`、`ui_mode=full`、无项目成员关系；企业微信资料不足以生成可理解显示名时拒绝开户，转人工预绑定。
- 已有平台账号不按手机号、邮箱、姓名或显示名自动合并；身份冲突由管理员人工处理。
- 企业微信登录复用现有 Bearer session、单活策略和 `GET /auth/me` 语义，不增加 JWT、refresh token、Lite 专用会话或第二套账号体系。
- Full 与 Lite 使用同一登录入口；登录后只按服务端 `users.ui_mode` 进入对应界面，外部身份不能提升平台角色或项目权限。

## 产品原则

1. **先给草稿**：系统尽量不让人面对空白输入框。AI 基于项目、资产、镜头和历史选择先准备内容，人负责修改和批准。
2. **前台心流，后台剧组**：长任务、解析、索引和状态整理在后台运行；前台只在需要输入或判断时打断人。
3. **决定集中**：人的主入口是“等我处理”的判定队列，而不是堆满统计数字的仪表盘。
4. **一次点击**：默认选择和高频反馈尽量一次点击完成。只有修改内容确实有利于用户时才要求输入文字。
5. **人担责，AI 可自动做**：是否自动化取决于风险、成本和可恢复性，不取决于 AI 能不能调用工具。
6. **品味会沉淀**：选择、修改和打回形成项目偏好，但不强迫人填写理由；系统从行为中学习，需要纠正时才收集文字。
7. **克制和渐进呈现**：主页面只显示当前角色、当前阶段和当前决定需要的内容；高级参数、历史和管理能力按需展开。

## V0.1.1 核心旅程

1. 登录并进入与角色匹配的工作首页。
2. 打开项目，看到当前生产状态、自己的待办和最重要的下一步。
3. 上传图片、Excel 或已有素材。系统解析、入库并建立可检索资产。
4. 使用筛选或自然语言检索，把角色、场景、道具、动作、镜头参考加入项目。
5. 在 3D 导演台中组合资产、机位、构图和运动意图，保存场景与快照。
6. Pi 智能工作区理解当前项目和导演台，可以检索资产、执行安全操作、准备结构化图片/视频草稿。
7. 人检查草稿、参考、模型和参数，点击一次生成；每次点击只授权一个付费任务。
8. 任务在后台运行，刷新后仍可恢复。结果自动转存并进入候选版本。
9. 人完成选版、打回或交付判定；系统记录责任和决策。

## 视频生产口径

生视频唯一主路径是全能参考：镜头提示词与已确认的角色、场景、道具和参考视频一起进入模型，并按参考身份明确标注，不将定稿图静默改作首帧或丢弃后退成纯文字。术语和拍板依据见 context 仓 `CONTEXT.md` §1 的「全能参考」「提示词四段结构」「资产原件保真」词条；本仓只实现该口径，不复制知识仓原文。

## 本版本必须交付

- 资产的图片/Excel 入库、解析、版本、项目引用和混合检索。
- Milvus 不可用时仍能完成正式入库和 PostgreSQL 基础检索。
- 3D 导演台的对象、镜头、场景保存、快照与项目素材引用。
- GPT Image 2、Gemini 图像能力、Seedream 5 Pro、Seedance 2.0、HappyHorse 1.1 的统一适配入口；实际供应商 model ID 必须运行时核实。
- 图片和视频的人工提交、后台任务、刷新恢复、结果转存和失败处理。
- 嵌入式 Pi Agent Core，使用与页面相同的资产、导演台、项目和生成准备服务。
- 全站深色生产界面和新登录页。
- 角色化入口、服务端权限、责任记录、后台成本统计与预算保护。
- 单企业企业微信内部成员登录流程，包含防重放授权事务、外部身份映射、现有会话签发、Full/Lite 进入和普通登录回归保护。
- 火山 VKE 独立 `shortdrama-prod` namespace：单个模块化单体应用以 VCI `Deployment` 运行，
  通过 HTTPS ALB `Ingress` 对外服务，私网直连 RDS PostgreSQL；生产密钥由 KMS
  initContainer 注入内存卷。Docker Compose 仅用于本地开发和 dev/test。

## 本版本明确不做

- 不允许 Agent 自动生图、生视频、自动重试或夜间批量生产。
- Seedance 全能参考通路解禁(DC 拍板 2026-07-22,决策台账 D 记录):2.0 已支持全能
  参考(多路图片/视频参考),2.5 为增强而非解锁;产品按全能参考输入格式规范设计。
  30–180 秒长时长能力随模型能力档配置化接入,不再作为排除项。
- 不建设微服务、多 Agent 运行时或通用工作流平台。
- 不完成剪辑、配音、音乐、翻译、投放和完整企业治理。
- 不让前台逐次处理复杂估价；成本在后台记录和控制。
- 企业微信登录首期不做多企业 SaaS、第三方应用授权、外部联系人、通讯录/部门同步、自动账号合并、身份绑定/解绑页面或通用身份供应商框架。

## AI 自动化边界

V0.1.1 可自动执行：资产解析与索引、搜索改写、草稿生成、参考匹配、任务状态同步、低风险一致性预检、失败归类和待办整理。

必须由人执行：付费生成提交、主版本选择、预算例外、交付判定、发布和责任人变更。

未来夜间 Agent 优先做便宜、可回滚、可抽检的准备工作，不用低成本模型替代生产质量判断。

## 成功标准

- 新用户不依赖开发人员，能完成资产入库、检索、导演台准备、一次人工生成和结果查看。
- 用户随时知道自己正在做什么、下一步是什么、哪些事项在后台运行。
- 付费任务不会因重复点击、刷新、Agent 重放而重复创建。
- 业务事实可追责，Milvus、模型或 Pi 暂时不可用不会破坏正式数据。
- 产品表现为克制、智能、个性化的生产工作区，而不是传统后台或模型参数面板。
