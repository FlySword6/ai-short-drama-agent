## 数据库升级怎么做的(重要,下次照做)

产品负责人当时选的是「给应用账号加权限」。**但查下来已经有一个专门的迁移账号 `shortdrama_migrator`**,凭据就在工作区 `.env`。用它跑完三个迁移,**没动任何账号权限**——应用账号不该有改表结构的权限,那道安全门保住了。

做法:在容器里用迁移账号的身份跑应用自带的迁移程序。

    kubectl -n shortdrama exec <pod> -- env \
      POSTGRES_USER=$POSTGRES_MIGRATOR_USER \
      POSTGRES_PASSWORD=$POSTGRES_MIGRATOR_PASSWORD \
      node dist/db/migrate.js

**不要用 psql 直接跑迁移文件**——文件里是 `{{schema}}` 模板占位符,psql 会报语法错误。
