## 一、先说结论:改什么、不改什么

你审计里那句 **「这版原型把『配齐』做成了展示,没做成机制」** 是这一单的总纲。

**这一单只做一件事:把状态标签变成状态机。** 不重画、不改风格、不动那些你自己夸过的好细节(镜头时长有零头、三视图不入生成参考、排队第2·已自动保存——这些留着)。

**明确不做**:图/视频两段式是否恢复、「整段一次生成」是否保留——**这两条是产品路线,不是画错,等产品负责人拍板,你别自己定**。在原型上留一条注记说明「此处待拍板」即可。

## 二、四条硬伤,逐条给修法

### 1. 「已锁定 7/8 就位」自己打架(最要紧)

**现象**:标着「已锁定」(=可以开拍)又标着「7/8」(=还差一件),而「开拍·240积分」按钮是亮的 filled teal。差的那件是「动作参考·拔刀连招」,标了「待补」却没有任何出口。

**为什么必须改**:这正是我们去 YY 审计时点名要消灭的「让人点了才失败」。

**修法**:
- **8/8 之前,开拍按钮不许是 filled teal**。改成次级样式(描边或灰底),旁边一行小字写清差什么:「还差 1 件:动作参考·拔刀连招」;
- **「已锁定」这个词只在 8/8 时出现**。7/8 时顶部标签改成「备料中 7/8」;
- **「待补」要有出口**:那一项上加一个可点的动作,至少两个去处——「去资产中心找」和「派给美术」。**派活是协作节点,不是灰字**;
- 允许强行开拍(产品原则是软引导不硬闸),但**必须是显式的二次确认**:点次级按钮 → 弹窗说明「还差 1 件参考,通过率会低,确认要开拍吗」→ 确认才走。

### 2. 同一个片段三个名字

**现象**:导航条「雨中追逐」/ 列表「1-3-雨巷-v1」/ 工作台标题「雨中追逐」/ 剧本片段「1-3 巷口雨夜」。而同屏右下角脚注还定义了命名规则「集-片段-场景-版本」。**规则和实现在同一屏里对不上。**

**修法**:全屏统一成一套。建议主显示用人看得懂的名字(「雨中追逐」),需要精确定位的地方用规则编号作副标题(「1-3 巷口雨夜 · v1」)。**同一个东西在一屏里只能有一个主名。**

### 3. 编译稿的引用断链

**现象**:左栏参考包叫「图1-2 / 图3」,右栏编译稿叫「图片1 / 图片2 / 图片3」,两套编号;而且引用只到编号,**没指回资产中心的 CH-005**。

**修法**:
- 两栏用同一套编号,不许一边「图1」一边「图片1」;
- 编译稿里的引用**可点,点了跳到资产中心对应条目**;
- 你发现的那条很准:编译稿正文写了「面部参考…妆造参考…」,**这是锁脸/锁衣语义,说明设计者懂**,但参考包里每项只有一个「已就位」。**把锁定语义提到参考包每一项上**——每项能标明它锁的是什么(脸/衣/景),而不是只有一个「已就位」。

### 4. 状态标签要有状态机

这是总纲的具体化:凡是「已就位 / 已锁定 / 待补 / v3 主版本」这类标签,**每一个都要回答四问**:

1. 它现在是什么状态?
2. 差的那件是什么?
3. 谁去补?
4. 补完谁确认?

**答不出来的标签,要么补上出口,要么删掉**——留着就是假信息。

## 三、这一单的完成判据

1. 生产页上**不存在**「已锁定」和「7/8」同时出现的情况;
2. 未配齐时,开拍按钮**不是** filled teal,且旁边写明差什么;
3. 「待补」的每一项都有可点的出口(至少「去找」和「派活」二选一);
4. 一屏之内同一个片段只有一个主名;
5. 编译稿的引用编号和参考包一致,且可点跳转;
6. 每个状态标签都答得出上面四问,答不出的已删或已补出口;
7. 图/视频两段式与「整段一次生成」两条**留注记待拍板**,不擅自定。
