# 后端目的地只能来自发行版内置的受信端点清单

`shortdrama-cli` 是 agent 驱动的：用户对 Agent Harness 说话，harness 替他组命令。这意味着一段被注入的文本就足以让 CLI 跑 `--api-base https://attacker/…`，把用户的 bearer token 送到攻击者手上。2026-08-12 决定：后端目的地不再接受调用方提供的 URL——命令行参数、环境变量、本地会话文件一律不算数——只能是发行版里写死并经评审的**受信端点**清单中的一条。用户能选的只有环境名（`prod` / `test` / `dev`），默认 `prod`。

## Considered Options

- **保留 `--api-base`，加约束**（强制 HTTPS + 域名白名单正则）。挡不住"域名对但路径被劫"这类；而且正则白名单同样是代码，不如直接把地址列出来。
- **一个发行版对一个环境**。听起来更简单，但测的二进制和发出去的二进制不是同一个——这正是"测试站落后 dev 九天"那类问题的同一个形状。而且用户下错版本时看到的报错是"连不上"，不是"你下错了"。`gh`、`aws`、`stripe` 都不这么做。
- **内置清单（选中）**。一个二进制伺候所有环境，登录时选一次环境，之后粘住。这是 `gh auth login --hostname` 的形状：默认 `github.com`，企业用户传 `--hostname`，登完就不用再说了。

## Consequences

- 换站点要发一次版。站点地址的变动频率远低于发版频率，这个代价可接受。
- 清单是代码不是配置，改它要过 code review。往清单里加地址的批准权归产品负责人（2026-08-12 定）。
- 会话按环境分开存，因此凭据天然不跨环境使用：连 `dev` 时手上不会有 `prod` 的 token。这取代了"连本机地址一律不许带 token"这类禁令——那条禁令会让本地跑不了真实鉴权流程，而登录恰恰是最需要真实验证的地方。
- 今天 `prod` 和 `test` 都跑在明文 HTTP 上（`http://101.126.6.208/`、`http://shortdrama-main-test.col.com/`），所以清单必须允许一条被显式标注为 HTTP 才填得进去。作为交换，CLI 每次连 HTTP 受信端点都往 stderr 打一行警告（不进 JSON 信封），让这件事不会沉默固化。两个环境上了 TLS 之后，标注和警告一起删掉。
