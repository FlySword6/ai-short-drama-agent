# Story Studio — AI 短剧智能生产 Agent 工作台

项目角色：AI 应用工程实践 / 开源项目本地化与工程验证

GitHub：https://github.com/FlySword6/ai-short-drama-agent

## 技术栈

TypeScript、Node.js、NestJS、Fastify、Pi Agent Core、PostgreSQL、TypeBox/Ajv、React、Vite、Three.js、FFmpeg/ffprobe、Docker Compose。

## 项目简介

面向中文短剧创作场景，构建覆盖剧本拆解、资产准备、分镜设计、镜头生成、技术复核与成片交付的本地 AI 制片工作台。系统通过持久化 DAG 协调文本、生图和生视频模型，支持人工检查点、预算控制、暂停恢复及镜头级局部返修，处理多阶段生成中的状态丢失、重复提交和无关重做问题。

## 核心技术与实践

1. **生产工作流编排：** 基于 TypeScript 任务状态机组织 10 阶段生产 DAG，在分镜采用后动态展开镜头级子任务；支持全自动、关键节点确认、共同导演 3 种模式，通过依赖与质量门禁控制阶段推进。
2. **任务持久化与恢复：** 使用 PostgreSQL 保存运行、任务、尝试、候选及人工决定，结合稳定请求 ID、CAS 版本控制和事务 Outbox 处理重复创建、并发覆盖与事件一致性；外部提交结果不明时查询原供应商任务，阻止自动重复付费。
3. **结构化生成与原文追溯：** 使用 TypeBox/Ajv 校验模型输出，建立不可变原文版本、Unicode 码点引用和候选采用机制；小说拆解采用“提取—查漏—复核—局部修复”流程，对实体引用、对白覆盖与顺序进行程序检查。
4. **模型与资产协同：** 按拆解、通用文本、生图、生视频 4 类用途管理模型连接；复用人物、场景和道具资产，为镜头绑定有序参考图片，并将规则式 3D 白模的机位、运镜和人物站位转换为提示词约束。
5. **预算与局部返修：** 以整数微单位记录费用，通过预留、记账和释放机制控制运行预算；技术检查失败后，仅失效受影响镜头及其下游结果，保留无关镜头和历史产物，限制自动返修次数。
6. **媒体处理与本地验证：** 镜头视频经受控下载、SHA-256 和 ffprobe 校验后进入本地媒体库，由 FFmpeg 按分镜顺序合片；完成前后端及数据库本地部署、构建和测试复核，定位 Windows 权限、路径及换行兼容问题。

## 项目成果

- 系统形成覆盖 10 个生产阶段、3 种自动化模式、每镜 1–4 个候选的生产编排能力，支持任务暂停、重启恢复、人工确认与局部重试。
- 项目已有的 3 章小说固定样本评测中，具体物件检出由 16/30 提升至 27/30，检出率由 53.3% 提升至 90%，提高约 36.7 个百分点；705 条原文引用通过坐标及字面一致性校验。
- 本地复核完成前后端构建，86 项前端测试全部通过；识别后端跨平台测试兼容问题，为后续 Windows 环境适配提供依据。

## 数据来源与面试口径

- 模型评测来自[三章小说评测记录](小说拆解评测-2026-10-23.md)，属于仓库已有结果，并非本次重新调用付费模型获得的数据。
- 36.7 个百分点指固定具体物件清单的检出率差值，不是整体准确率；地点检出由 14/17 降为 12/17，不能声称所有维度均改善。
- 新规则首次提取已达到 26/30，查漏与局部修复后为 27/30，不能将全部收益归因于多轮循环。
- 705 条引用一致只表示坐标和字面内容匹配，不代表语义全部正确。
- 当前自动检查验证文件与媒体指标；人物、剧情、表演和连续性仍需人工观看。完整真实付费视频链路尚未在本机验收。
- 个人贡献按实际参与范围描述；上述核心技术包含原项目已有实现，实际负责开发的模块才使用“负责设计与实现”等表述。
- 2026-10-26 的本地基线：前端 86 项通过；后端 392 项中 378 项通过、13 项失败、1 项跳过。失败涉及跨平台权限、符号链接、路径、桌面桥测试和换行；当次 PostgreSQL 未运行，数据库集成测试未重跑。
