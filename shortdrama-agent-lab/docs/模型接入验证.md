## 两次真实调用

由本项目 HTTP 接口 → 已有本机代理 → 公司模型链路执行。命令为 `npm run models:smoke -- --allow-paid`；恰好两次请求，无自动重试，无换模型。

两次均指定 `gpt-5.6-terra`、`reasoningEffort:low`、`maxOutputTokens:4096`。只发送合成数据，不包含项目代码、剧本、用户图片或历史聊天。

| 测试 | 本地时间 | 结果 | HTTP | 耗时 | 上游报告输入/输出/总 token |
|---|---|---|---:|---:|---|
| 文本：17＋25 | 18:52:45 | 正确回答 42，completed | 200 | 3733 ms | 19 / 5 / 24 |
| 图片：程序生成的 64×64 红色 PNG | 18:52:48 | 正确识别红色，completed | 200 | 3607 ms | 23 / 5 / 28 |

上游报告的模型标识均为 `gpt-5.6-terra`，两次报告 reasoningTokens 均为 0。数字是返回的 usage，不是独立计量或费用账单；项目不保存原始供应商响应。模型名不能独立证明实际底层权重身份。

## 一次剧本拆解探索性调用

用户于 2026-09-30 明确要求使用模型试拆现有《斗破苍穹》赴约练习剧本。本次只提交 **1 次** 请求：`gpt-5.6-terra`、`medium`、`maxOutputTokens=4096`；没有自动重试、换模型、媒体生成、项目写入或候选采用。

- 输入：仓内 `examples/斗破苍穹-赴约-练习剧本.txt`（404 字节的助手重写练习文本）。
- 返回：HTTP 200、`completed`、`finishReason=stop`；上游报告输入/输出/总 token 为 `525 / 1979 / 2504`，其中 reasoning token 为 `561`，耗时约 `18.9` 秒。
- 结果形状：模型按一次性提示返回了合法 JSON，包含 2 人物、1 地点、2 道具、1 场、6 个建议镜头和 3 段对白。
- 程序外的只读核对：28 个 `sourceQuotes` 都能在原练习文本中精确找到；3 段原文对白均由正确说话人完整返回一次，没有额外对白。
- 质量问题：第 5 镜出现“先……再切至……”，第 6 镜出现“交替特写……最后停在……”，各自实际包含多个剪辑镜头，不符合本项目“一行一个连续镜头”的正式规则；总设计时长为 24 秒，也未接受目标时长约束。

这只是验证本机模型适配器能够产出可审阅的拆解候选，**不是**已经实现的剧本拆解能力。此次提示词是试跑用的一次性约束；项目仍未实现正式 `SourceRef` 偏移校验、候选版本、结构校验器、连续镜头规则、Run/Task 记录、人工采用或按场重做。
