# 首个里程碑：剧本事实与候选分镜

状态：本地可运行的文字生产切片。需要 Docker PostgreSQL、本机模型代理和用户在网页逐次确认可能计费的调用。代码与假模型/数据库集成测试已通过；真实付费模型输出尚未进行质量验收。

## 操作顺序

1. 运行 `npm run db:up`、`npm run db:migrate`、`npm run dev`；另开终端运行 `npm --prefix web run dev`。
2. 打开 [真实项目](http://127.0.0.1:5173/#/production)，创建项目并保存一集中文剧本。
3. 创建 draft Run。此时没有模型调用。勾选付费确认并启动事实拆解后，Pi Agent Core 执行单轮提取，本机模型代理返回 JSON；原文证据别名被还原并校验，结果保存为候选计划。
4. 运行程序检查。检查梗概、场次、人物、对白覆盖与重复、说话人、原文归属等。阻断问题会列出原文引用；只有通过检查且仍对应当前剧本的候选可以采用。程序检查不能判断剧情语义是否准确，采用前需人工核对。
5. 采用事实后，勾选另一项付费确认，生成候选分镜。Pi Agent Core 对已采用的事实计划设计连续镜头。程序验证镜头场次、每场顺序、原文引用逐字一致和对白恰好覆盖一次。景别、运镜、时长与画面描述全部标为 `designSuggestion`。人工核对后采用分镜。

所有采用使用项目当前指针的版本比较。保存新剧本版本会清除当前事实与分镜指针；采用另一版事实会清除当前分镜指针。历史候选和尝试记录保留。

## 接口与数据

- `POST /api/projects`、`POST /api/projects/:id/script-versions`：本地保存项目与剧本版本。
- `POST /api/projects/:id/breakdown-runs`：仅创建 draft。
- `POST /api/breakdown-runs/:id/execute`：请求体必须为 `{"allowPaid":true}`；单次运行，无自动重试，保存 Attempt/ModelCall 与候选计划。
- `POST /api/plan-revisions/:id/checks`：纯程序检查，不调用模型；`GET /api/plan-revisions/:id/checks/:checkId/issues` 查看问题。
- `POST /api/projects/:id/adoptions`：须提供 `planRevisionId`、`checkId`、`expectedActivePlanRevisionId`。
- `POST /api/projects/:id/storyboards`：请求体必须为 `{"allowPaid":true}`；依据已采用事实设计候选分镜，记录尝试与模型用量。
- `POST /api/projects/:id/storyboards/:revisionId/adoptions`：须提供 `expectedActiveStoryboardRevisionId`。

本地网页通过 Vite 代理访问后端；后端仍只监听 `127.0.0.1`，写请求要求 `X-Shortdrama-Call: 1`，仅接受本地开发网页的 Origin。浏览器不保存模型凭据。

## 范围与后续

本切片尚不能编辑真实候选、按场重做、集中追问剧情歧义、自动修复模型坏输出、跨进程恢复运行，也没有独立资产库、白模自动摆场、生图、配音、视频、剪辑或成片。`storyboard_revisions` 是独立的候选分镜版本，未合并进旧样例的 `PlanRevision.scenes[].shots`。这些能力需要在真实样例验收后继续设计，不应把当前流程称为全自动短剧生产。

验证：`npm test`（离线）、`npm run test:db`（本地 PostgreSQL）、`npm --prefix web test`、`npm --prefix web run build`。数据库集成测试使用假模型传输，不调用付费模型。
