# 本地开发：Docker PostgreSQL

数据库由 Docker Compose 管理；NestJS 后端与 React 网页仍在本机 Node.js 中运行。

## 首次准备

打开 Docker Desktop。在项目根目录（包含 `compose.yaml` 的 `shortdrama-agent-lab/`）执行：

```sh
npm ci
npm run db:setup
npm run db:up
npm run db:migrate
npm run test:db
```

`db:setup` 为缺失项生成随机本地密码和 `DATABASE_URL`，保留已有模型配置；重复运行不会换密码。`.env` 仅当前用户可读写，并已被 Git 忽略。已有外部数据库连接时不会覆盖，配置不一致会报错。无需把密码写进代码或前端。

`db:up` 等待容器健康；`db:migrate` 显式执行 SQL 迁移，HTTP 后端不会自动建表。当前迁移还包含事实检查与采用记录、分镜尝试/候选/采用记录，以及项目来源链接字段（006）。

## 每次开发

```sh
npm run db:up
npm run dev
```

后端默认监听 `http://127.0.0.1:8788`。出现新 SQL 迁移时，在启动后端前先运行 `npm run db:migrate`。修改 `.env`、首次完成迁移或修改后端源码后，停止并重新执行 `npm run dev`，让后端重新构建并读取配置。

另开终端启动网页：

```sh
npm --prefix web ci
npm --prefix web run dev
```

网页默认在 `http://127.0.0.1:5173`。「真实项目」通过本地 `/api` 代理接入 PostgreSQL 与文本 Agent；旧的示例工作区仍使用 localStorage，白模使用 IndexedDB。真实付费模型输出质量尚未实测，后台恢复和媒体自动生产仍待开发。

只读检查后端：

```sh
curl --fail http://127.0.0.1:8788/healthz
```

`healthz` 只表示 HTTP 服务已启动；数据库真实读写以 `npm run test:db` 和持久化 API 验证为准。当前可用 API 与门禁见[首个里程碑实现](首个里程碑实现.md)。

## Navicat 连接

创建 PostgreSQL 连接，填写以下默认值；如修改过 `.env`，使用其中对应值：

| 字段 | 值 |
|---|---|
| 连接名称 | Shortdrama Local（自定义） |
| 主机 | `127.0.0.1` |
| 端口 | `5432`（`POSTGRES_PORT`） |
| 初始数据库 | `shortdrama_agent`（`POSTGRES_DB`） |
| 用户名 | `shortdrama`（`POSTGRES_USER`） |
| 密码 | 从本地 `.env` 的 `POSTGRES_PASSWORD` 复制，去掉包裹引号 |
| SSL / SSH | 本机开发不启用 |

本机账号是该开发实例的初始化管理账号。容器只发布到 `127.0.0.1`，不会对局域网开放 5432。

## 管理与保存

结束开发时，先在后端终端按 Ctrl+C，再停止数据库；重新启动时先 `db:up`，再启动后端。

```sh
npm run db:status  # 查看容器状态与端口
npm run db:logs    # 最近 100 行数据库日志
npm run db:psql    # 进入数据库命令行；用 \q 退出
npm run db:down    # 停止并移除本项目容器与网络，保留数据卷
npm run db:up      # 重建容器，继续读取原数据卷
```

数据卷为 `shortdrama-agent-lab_postgres_data`，PostgreSQL 17 数据目录挂载到 `/var/lib/postgresql/data`。停止容器、重启 Docker 或普通 `db:down` 不会删除数据；不要加 `-v` 或删除这个数据卷，除非明确要清空数据库。数据卷持久化不是备份。

数据库首次初始化后，单独修改 `.env` 的 `POSTGRES_PASSWORD` 不会修改库内密码；需要在数据库中修改密码并同步 `DATABASE_URL`。端口冲突时，在 `.env` 中同步调整 `POSTGRES_PORT` 与 `DATABASE_URL` 的端口，再运行 `db:up` 并重启后端。大版本升级不能直接替换镜像标签，需另做备份与迁移。

## Docker Hub 网络不可用时

Compose 默认使用 `postgres:17-alpine`。本机本次无法连接 Docker Hub，因此 `.env` 的 `POSTGRES_IMAGE` 使用了 Docker 官方镜像在 AWS ECR Public 的分发入口，并固定下载成功的 digest：

```text
public.ecr.aws/docker/library/postgres:17-alpine@sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24
```

这是下载容器镜像，数据库依然只在本机运行，不创建 AWS 数据库或云资源。其他机器可使用默认入口，或将 `POSTGRES_IMAGE` 设为 `public.ecr.aws/docker/library/postgres:17-alpine` 后拉取。来源：[Docker PostgreSQL 官方说明](https://hub.docker.com/_/postgres)、[AWS 关于 Docker 官方镜像分发的说明](https://aws.amazon.com/blogs/containers/docker-official-images-now-available-on-amazon-elastic-container-registry-public/)。
