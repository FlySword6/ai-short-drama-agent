# OHAO · STORY STUDIO

用户于 2026-10-22 要求参考 Liblib 的信息组织与浏览体验重构界面。当前工作台采用中性黑灰底色、荧绿强调、紧凑卡片与分组侧栏；保留短剧流程和已有编辑能力。

采用 React＋TypeScript＋Vite，路由使用 hash。界面品牌为 **OHAO / STORY STUDIO**（2026-10-22 用户确认，取自「欧皓」）；既有 `frame:*` 浏览器存储键与内部协议保持兼容。一级导航为「首页、项目、资产、插件」；自动成片、小说拆解、剧本拆解、分镜工作台和 3D 导演台位于「创作工具」，九步流程作为创作指南保留。

## 本地运行

```sh
cd shortdrama-agent-lab/web
npm install
npm run dev
```

打开 http://127.0.0.1:5173/ 。仅监听本机，尚未部署为公网网站。

```sh
npm test
npm run build
npm run preview
```

构建同时执行 TypeScript 检查，预览地址为 http://127.0.0.1:4173/ 。

## 当前可用

- 「自动成片」为独立 `#/automation` 页面：首页快捷工具和侧栏都可进入。输入描述、选择 9:16 / 16:9、5 / 10 / 15 秒、720p / 1080p 与是否生成声音，逐次明确授权 API 额度后创建一个视频任务。页面展示后端返回的五节点进度，每轮读取结束后 4 秒继续轮询，保留历史记录；不模拟供应商百分比。当前输出为独立视频片段，尚未串接小说、资产、分镜与整集剪辑。

- 「小说逐章拆解」为独立 `#/novel` 页面：保留纯小说原文，按章提取和校对人物、地点、道具、对白/引文；原文定位、待确认、增删、依据修正与新版本保存，不自动改编。需要后端及迁移 008；免费引号初稿不是 AI 拆解。
- 首页采用点阵新建入口、八个快捷工具、最近项目、五张特色功能卡和创作参考图库的简洁布局。最近项目复用项目目录的只读数据与指定 ID 跳转；创作参考支持分类与搜索，使用「赴约」同图裁切和手工白模截图，点击进入示例参考或 3D 工作区。`public/assets/director-preview.png` 复制自本项目 `docs/media/director.png`，仅作白模截图预览。保留页面导航、快速查找（⌘/Ctrl K）和手机导航。「新建项目」先选择小说导入、剧本项目或编辑样例，再进入相应工作区。
- 「项目」目录采用紧凑工具栏与留白卡片布局，首卡「开始创作」打开新建选择；项目封面下仅展示名称和日期，无封面时使用灰色占位。目录只读请求现有剧本项目与小说目录，区分真实数据和本地练习；支持关键词搜索、类型筛选、网格/列表切换，真实条目按创建时间排序。两类后端目录独立显示加载、失败与重试状态，单侧失败不会隐藏另一侧或浏览器练习；打开条目定位对应 ID，目录本身不创建项目、不调用模型。
- 「资产」采用顶部紧凑工具栏、右侧「个人资产库 / 示例参考」导航与留白卡片；手机上分类移至顶部。「新建」打开已有素材链接登记弹窗，关闭或切换页签保留未登记输入，再次打开可继续。个人资产只显示灰色占位，详情中显式点击才打开外部素材；示例区提供轻量卡片、分类与需求筛选，完整原文依据和来源保留在详情中。
- 「插件与工具」为内置工具目录，支持搜索与「全部 / 已可用 / 规划中」筛选。小说拆解、剧本拆解、示例分镜、3D 导演台、JSON 草稿导出与自动成片分别打开既有入口；独立图像工具、配音和剪辑卡片仍标为规划中并禁用。目前没有第三方插件安装系统，打开工具不会自动生成内容。
- 「真实项目」接入本地 NestJS 和 PostgreSQL：建项目（可附 HTTPS 来源链接）、存剧本版本、创建 Run、显式调用事实拆解 Agent、查看校验问题、采用事实、生成并采用候选分镜。来源链接仅作出处，不自动抓取正文。网页经 Vite `/api` 代理连本地后端。
- 「真实项目」的拆解校对展示人物、场景（地点）、道具的原文依据；可修改已有实体的名称、别名和说明，保存为新候选，重新检查后单独采用。实体 ID 和原文引用保持不变，旧版本保留只读。
- 粘贴剧本、UTF-8 TXT 上传/拖入（1 MB 内）、本地保存。
- 从现有手写数据样例展示 4 个镜头，选择镜头、编辑画面设计/景别/运镜/时长，对照只读原文与对白。
- 选定镜头的修改不更改其他镜头；手工修改有标记，恢复原设计时解除标记。
- 保存后刷新恢复，导出带格式标识的前端编辑草稿 JSON。
- 「资产库」登记已有素材的类型、名称、说明及 HTTPS 链接；小说已确认并保存的人物、场景、道具可选择同类登记或标记待补。待补项先展示结构化 `AssetVisualBrief`，每次显式额度授权只调用设置中的生图 API 生成一张候选，可逐次生成多个；成果进入 `awaitingReview`，只有人工接受后才正式关联，拒绝候选保留历史。引用随章节版本保存，修改事实后需重新核对。需要迁移 009–013；不自动加载远程媒体。
- 「资产」入口以「资产目录 / 示例参考」两个页签保留正式登记与练习内容。页签切换不卸载登记表单，未提交输入继续保留；离开资产页仍检查未保存内容。素材登记与小说关联是独立增量，本次 UI 重构保留其入口和边界。
- 示例参考支持文字搜索、人物/场景/道具分类，以及「视觉参考 / 资产需求」切换、详情与原文依据。3 张参考是同一示意图的裁切，5 项需求来自手写计划，剑与重尺仍是需求，尚无独立素材；示例不会自动登记到真实资产目录。
- 保留原有九步流程；白模步骤能进入完整 3D 导演台。
- 复用原仓的人偶（8 种体型、20 种姿势、关节微调）、几何物体、群众阵列、GLB 上传、位置/旋转/缩放、机位/焦段、光照、画幅与构图线。
- 白模场景保存/恢复、JSON 导入导出；PNG 截图、机位宫格、深度图与 3/5/8 秒 WebM 运镜预览和导出。
- 导出图片和视频先预览，再点击下载；需要支持 WebGL 与 MediaRecorder 的浏览器。
- 尊重系统减少动态效果设置，键盘焦点、模态框和移动布局。

## 数据与能力边界

「真实项目」与「小说逐章拆解」是后端持久化页面，执行模型时由后端调用设置中选定的“拆解”连接，可能计费；每次调用必须勾选确认。原 Codewiz 模型入口已移除，不自动回退。三章小说已真实提取落库并核对精确引用，但不保证语义准确率；旧剧本协议仍有失败记录，详见[实测](../docs/模型接入验证.md)。人工资产登记和引用保存不触发模型；小说待补项的「生成候选图片」会为每个新 `intentId` 单独确认额度并调用所选“生图”连接，生成后等待人工接受或拒绝。

模型完整接口和密钥只保存在主工程本机后端，不放入浏览器或 `VITE_` 变量。缺少对应用途配置时仍可校对已有拆解，相关生成操作会被拒绝；切换模型后新任务使用新选择，旧 Run、候选与生成任务记录保留。当前已接文本调用，以及小说资产的结构化视觉简报、单图候选、多个候选留存、人工接受/拒绝和结构化溯源；接受后才写章节关联。Seedance 已连接独立「自动成片」任务页面，支持持久任务与状态读取；尚未绑定分镜或完整成片流程。具体配置见[独立模型配置](../docs/独立模型配置.md)。

实体校对、保存和程序检查不调用模型。请先在主工程目录运行 `npm run db:migrate` 应用 `007_entity_edit_revisions.sql`，然后重启后端。校对保存到 PostgreSQL 的不可变候选，修改文本标为用户来源、修改字段有记录；保存本身不替换已采用事实，也不沿用旧版检查结论。

「真实项目」只有当前剧本的最新候选可编辑与采用；基准或已采用版本发生变化时会提示刷新核对。历史版本可查看，但本轮没有恢复入口。该剧本页面不支持实体增删合并，不修改原文引用、场次、对白、说话人或梗概，也没有上传/绑定参考资产。`manualLocks` 记录本轮人工修改，不代表已经实现跨新 Run 自动继承或按场重做保护；重新提取后的新候选需重新核对。

小说页面可增删条目、修正引用与说话人，每章单独保留不可变历史。原文按码点保存，textarea 的 LF 与 UTF-16 选区通过双向映射支持 CRLF/CR 和 emoji；原文不被规范化改写。保存无模型调用，旧基准冲突时保留未保存草稿但不得覆盖最新版本。具体边界见[小说逐章拆解](../docs/小说逐章拆解.md)。

`src/model.ts` 从既有 v0.1 样例读取展示数据；不修改原始样例。编辑内容存入当前浏览器 localStorage 的 `frame:ui-draft:v1`，再次保存前一份内容另存于 `:previous`。这不是已经实现的生产计划版本系统、数据库或完整项目备份。

导出格式为 `shortdrama-ui-draft/1`，不冒充已采用的 `PlanRevision` 或成片项目。更换剧本后，旧分镜明确标为“赴约”的独立参考，不当作新剧本的拆解结果。当前参考样例约 19 秒，不承担 1–2 分钟整集验收。

白模使用 IndexedDB `frame-director-v1` 的 `scenes` 仓保存当前场景，含内嵌的本地 GLB（单文件 25 MB 内）与全景图（8 MB 内）；JSON 导入最大 80 MB。清理网站数据会删除本浏览器场景，请导出留存。初始练习是手工摆放的设计建议；不是 Agent 自动摆场结果。

密钥不放在浏览器。已接入的程序校验只检查结构、来源、图片容器与任务状态，不等于语义或视觉质检；人工接受候选也不产生质检通过结论。生图提交结果不明时不自动重试，候选流程不改编剧本、不接分镜或 3D；独立视频片段已接任务持久化与轮询；完整预算管理、角色配音、多镜头剪辑与整集成片按后续里程碑接入。外部链接登记仍未验证可达性、授权或长期有效性，见[小说资产引用](../docs/小说资产引用.md)。

## 自动成片交互边界

页面只在用户勾选额度授权并点击「一键创建视频」后发送创建 POST，默认 9:16、5 秒、720p、声音关闭。模型未配置或后端不可达时提示进入 `#/settings/models`；不影响其他工作区。描述与设置修改、模型连接版本改变都会清除授权。

创建前把新的 `clientRequestId` 暂存到当前标签页 sessionStorage。明确 HTTP 拒绝允许修改后重新授权；响应丢失或超时时只读取任务列表寻找同一标识，不自动重发。列表成功且无匹配项时解除等待，允许用户再次明确创建；列表失败继续保持待核对。服务端 `unknown` 记录保留「核对已有任务」入口与可能已计费提示，不会自动重新发送原请求，也不永久阻止用户另行授权新任务。

成功结果只提供用户点击打开的 HTTPS 链接，不自动加载、播放、下载远程视频；供应商链接可能过期，界面不声称视频已进入本地媒体库。未提交输入有离页保护；已保存的任务离开页面后继续执行，返回页面读取历史。轮询卸载时取消，HTTP 读取失败保留已有记录。

2026-10-23 前端验证：`npm test` 79 项通过（含自动成片的参数、节点、请求恢复、未知状态、结果链接、SSR 与导航保护）；`npm run build` 和前端范围 `git diff --check` 通过，仍有 Vite 大包提示。该轮验证只用纯函数、SSR 和模拟请求，没有向真实后端创建任务或调用付费模型；浏览器与真实供应商生成不在这条验证记录中。
