# FRAME · 短剧电影工作台

用户于 2026-09-27 确认：整体前端改造、保留短剧流程，采用深色＋暖橙的电影工作台风格。

采用 React＋TypeScript＋Vite。路由使用 hash，内含创作首页、真实项目、剧本/分镜示例、视觉参考、九步制作流程、白模机位和设置说明。

## 本地运行

```sh
cd shortdrama-agent-lab/web
npm install
npm run dev
```

打开 http://127.0.0.1:5173/ 。仅监听本机，尚未部署为公网网站。

```sh
npm test
npm run build
npm run preview
```

构建同时执行 TypeScript 检查，预览地址为 http://127.0.0.1:4173/ 。

## 当前可用

- 首页入口、页面导航、快速查找（⌘/Ctrl K）、手机导航；侧栏和顶栏有「新建项目」，进入真实项目页的创建表单。
- 「真实项目」接入本地 NestJS 和 PostgreSQL：建项目（可附 HTTPS 来源链接）、存剧本版本、创建 Run、显式调用事实拆解 Agent、查看校验问题、采用事实、生成并采用候选分镜。来源链接仅作出处，不自动抓取正文。网页经 Vite `/api` 代理连本地后端。
- 粘贴剧本、UTF-8 TXT 上传/拖入（1 MB 内）、本地保存。
- 从现有手写数据样例展示 4 个镜头，选择镜头、编辑画面设计/景别/运镜/时长，对照只读原文与对白。
- 选定镜头的修改不更改其他镜头；手工修改有标记，恢复原设计时解除标记。
- 保存后刷新恢复，导出带格式标识的前端编辑草稿 JSON。
- 参考资产分类、预览；明确它们是同一张示意图的裁切。
- 保留原有九步流程；白模步骤能进入完整 3D 导演台。
- 复用原仓的人偶（8 种体型、20 种姿势、关节微调）、几何物体、群众阵列、GLB 上传、位置/旋转/缩放、机位/焦段、光照、画幅与构图线。
- 白模场景保存/恢复、JSON 导入导出；PNG 截图、机位宫格、深度图与 3/5/8 秒 WebM 运镜预览和导出。
- 导出图片和视频先预览，再点击下载；需要支持 WebGL 与 MediaRecorder 的浏览器。
- 尊重系统减少动态效果设置，键盘焦点、模态框和移动布局。

## 数据与能力边界

「真实项目」是后端持久化页面，执行 Agent 时会调用本机模型代理，可能计费；每次调用必须勾选确认。实际模型生成质量尚未实测。其他剧本、分镜和资产页是前端示例，不会触发模型调用。

`src/model.ts` 从既有 v0.1 样例读取展示数据；不修改原始样例。编辑内容存入当前浏览器 localStorage 的 `frame:ui-draft:v1`，再次保存前一份内容另存于 `:previous`。这不是已经实现的生产计划版本系统、数据库或完整项目备份。

导出格式为 `shortdrama-ui-draft/1`，不冒充已采用的 `PlanRevision` 或成片项目。更换剧本后，旧分镜明确标为“赴约”的独立参考，不当作新剧本的拆解结果。当前参考样例约 19 秒，不承担 1–2 分钟整集验收。

白模使用 IndexedDB `frame-director-v1` 的 `scenes` 仓保存当前场景，含内嵌的本地 GLB（单文件 25 MB 内）与全景图（8 MB 内）；JSON 导入最大 80 MB。清理网站数据会删除本浏览器场景，请导出留存。初始练习是手工摆放的设计建议；不是 Agent 自动摆场结果。

密钥不放在浏览器。已接入的程序校验只检查结构、来源和对白覆盖，不等于语义质检；任务恢复、独立资产库、预算、媒体生成与成片按后续里程碑接入。
