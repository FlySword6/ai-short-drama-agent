## 角色规则

后端必须同时检查平台角色和当前项目成员关系，不能只看其中一个。

| 平台/项目情况 | 生成结论 |
| --- | --- |
| 项目负责人 | 可以发起报价；仍需额度、页面确认和一次性提交 |
| 项目编辑 | 可以发起报价；仍需额度、页面确认和一次性提交 |
| 项目只读成员 | `deny: project_role_forbidden` |
| 不属于项目 | `deny: project_access_denied` |
| 管理员但不属于项目 | 默认不能生成；“管理全局配置”不等于跨项目生成 |
| 运营或普通成员 | 只有同时具备项目负责人/编辑身份时才可发起生成 |
| Agent 或后台服务 | 只能代表一个已验证用户执行已提交任务，不能自行成为原始批准人 |

如果以后业务明确允许管理员跨项目操作，必须新增独立的、可审计的“代操作”权限，不得悄悄把管理员当作全局绕过开关。

## 三项仍待业务/平台确认的门禁

### G-01：能力目录和额度

董言（或正式指定的替代责任人）需登记并批准：

- 每个 `quality` / `fast` 档位对应的 Ark 模型和版本；
- Agent 文本推理允许使用的 Ark 模型和预算；
- 图片/视频允许的规格；
- 单次输出数量和最大估算成本；
- 用户日额度、项目日预算；
- 用户/项目的 TOS 日对象数与写入字节额度；
- 超额审批人和超额后的状态机；
- 能力目录版本、启用时间和回滚版本。

未完成时的强制配置：

```yaml
paid_generation:
  enabled: false
text_inference:
  enabled: false
asset_storage:
  enabled: false
  user_daily_object_count: 0
  project_daily_object_count: 0
  user_daily_bytes: 0
  project_daily_bytes: 0
quota:
  user_daily: 0
  project_daily: 0
  text_user_daily_tokens: 0
  text_project_daily_tokens: 0
```

验收证据：批准记录、能力目录配置、Schema 校验结果，以及“未配置目录时媒体生成和 `model.send` 的 Provider 调用均为 0”的自动化测试。

### G-02：云网络责任人和生效证明

需要明确云平台/运维责任人，并提供：

- Agent 工作负载无法直连 Ark、TOS 和任意公网的测试；
- Agent 只能访问平台后端必要内部地址的规则；
- Provider Worker 只能访问已批准 Ark 目标、不能访问 TOS/任意公网的规则；
- Asset Worker 使用独立最小权限凭据，只能访问批准 TOS endpoint/bucket，不能访问 Ark/其他 bucket 的规则；
- ALB 来源限制、VKE/VCI 安全组或网络策略、RDS 白名单的配置证据；
- 允许目标成功、未允许目标失败的连通测试和出口日志。

安全组通常只能证明 IP/端口级限制，不能证明 HTTP method/path 限制。若生产承诺精确 method/path，必须额外提供 L7 出口代理或等价服务网格的验证证据。

### G-03：审计查看范围和保存期限

需要最终确认：

- 哪些平台角色可以查看安全审计；
- 项目成员可以查看哪些本项目业务账本字段；
- 业务账本和安全审计分别保存多久；
- 到期删除、法律保留、导出和事故调查流程；
- 审计配置由谁维护、谁能修改。

未确认时可以开发最小日志和脱敏测试，但不能声称日志治理已经通过生产验收。

## 可以立即实施的工作

下列工作不依赖上述三项待确认内容的具体数值：

1. Agent 生产配置拒绝直连 Ark/TOS，移除或隔离 `model_api_key`、AK/SK 和任意 `ARK_BASE_URL`。
2. 禁用自动批准、`reviewer="director"` 安全授权和裸 Prompt 生图。
3. CLI 禁止生产直连 Agent Gateway，阻止会话 Token 发往任意 `api-base`，禁止 argv 密码/Token。
4. 定义并测试平台会话、项目角色、报价、确认、提交和幂等契约。
5. 建立假 Provider、固定时钟和并发测试，证明拒绝路径真实云调用为 0。
6. 先在 Agent 和 CLI 两仓库分别部署独立的 CI Security Action，并保持共同边界一致；main
   已有 Draft PR #148 的 P0 候选，但仍必须接入适合控制面/数据库迁移/并发风险的仓库检查。

这些工作可以合并和部署到开发/测试环境；真实付费 Provider 仍必须保持关闭。

## 完整生产开启门禁不止三项

“三项”只表示回执中仍待确认的业务/平台决定。真实云能力还必须同时满足：

- `06-current-security-findings.md` 中 S-001 凭据事件已经关闭；
- main 后端的状态机、原子事务、Generation Gateway 和 Asset Worker 已实现并验证；
- Agent、CLI、main 三个代码仓库的安全 CI 已成为分支和 Release 门禁；
- 假 Provider、并发、网络绕过、输出脱敏和资产对象授权测试通过。

因此，不能在仅回答完三项问题后直接上线。

## 不能只在两个仓库内完成的工作

以下能力属于平台 `main` 后端，Agent/CLI 两个仓库无法代替：

- 从服务端会话解析 `app.users.id`；
- 查询平台角色和项目成员关系；
- 保存 quote、confirmation、submission、job、额度和成本账本；
- 原子消费确认、预留额度和实现幂等；
- 运行 Provider Worker / Generation Gateway 和独立 Asset Worker；
- 保存业务账本和安全审计。

`main` 仓库路径现已确认，且 P0 fail-closed 候选已进入 Draft PR #148；它并不等同于
完整生产控制面。Gateway、用户×项目×周期额度账本、私有 TOS/对象授权、云出口和 staging
证据仍需按本文件的契约继续完成。

## 变更规则

任何人要改变以上决定，应提交包含以下内容的新决策记录：

- 变更原因和责任人；
- 影响的仓库、接口和策略版本；
- 数据迁移及兼容方案；
- 新的拒绝/并发/网络测试证据；
- 回滚条件。

不能通过环境变量、Prompt、CLI 参数或临时白名单绕过本文件中的生产门禁。
