## S-001：已跟踪并已推送的非占位凭据

**等级：P0 / 应按已经泄露处理**

核验结果：

- `test-agent/agentkit.yaml` 当前仍存在非占位 `runtime_apikey`；
- 本地提交 `4eb5fba` 中曾出现非占位的：
  - `VOLCENGINE_ACCESS_KEY`
  - `VOLCENGINE_SECRET_KEY`
  - `TOOL_MCP_ROUTER_API_KEY`
  - `runtime_apikey`
- 该提交包含在远端跟踪分支 `origin/dev` 和 `origin/integration/v011` 中，因此不能按“只在本机出现”处理；
- 根 `.gitignore` 已声明 `agentkit.yaml` 应忽略，但该文件此前已经被 Git 跟踪，所以 `.gitignore` 不会自动停止跟踪；
- 同一配置还暴露 runtime、pipeline、registry、endpoint 等资源定位信息。即使密钥轮换，资源地图也应按内部配置管理。

## 必须按此顺序处置

### 1. 立即撤销和轮换

由对应系统的凭据所有者撤销/轮换以上四类凭据。不能等 Git 历史清理完成后再轮换，因为历史已经到达远端分支。

轮换完成的证据至少包括：

- 旧凭据失效时间；
- 新凭据创建时间、权限范围和责任人；
- AgentKit runtime/API key 的旧值已撤销；
- MCP Router 旧 key 已撤销；
- 火山云 AK/SK 已停用，而不是只新建一套。

### 2. 核查滥用

从最早推送时间开始，检查：

- 火山云 IAM/控制台登录和 API 调用审计；
- Ark、TOS、VikingDB、AgentKit 的调用量与异常来源；
- MCP Router 调用日志；
- 账单、额度突增、异常模型/资源创建；
- GitHub 仓库访问、Fork、Actions 日志和制品。

发现异常时应保留 request ID、时间、来源和账单证据，不要把敏感原始返回复制到普通聊天或 Issue。

### 3. 清理当前文件

在旧凭据已撤销后：

- 从受跟踪的 `test-agent/agentkit.yaml` 移除所有真实凭据；
- 只保留无敏感值的模板，例如 `agentkit.example.yaml`；
- 真实部署配置由 Secret Store、部署系统或本地忽略文件生成；
- 用 `git ls-files test-agent/agentkit.yaml` 验证它是否仍被跟踪；
- 用秘密扫描器扫描当前树和构建产物。

本设计阶段没有直接改动该配置，避免把“删掉当前字符串”错误当成完整事故处置。

### 4. 协调清理 Git 历史

凭据轮换后，由仓库负责人协调：

- 选择 `git filter-repo` 或平台认可的历史清理流程；
- 覆盖所有分支、Tag、PR 引用和 Release 制品；
- 通知协作者重新克隆或按统一步骤修复本地仓库；
- 必要时联系 GitHub 支持清除缓存视图；
- 历史清理后重新运行全历史秘密扫描。

历史重写会影响所有协作者，不能由单个开发者在未协调的情况下强推。

### 5. 防止复发

Agent 仓库 CI 和本地提交钩子至少应做到：

- PR diff 和受保护分支的秘密扫描；
- 定期全历史扫描；
- 检查 `agentkit.yaml`、`.env`、私钥、Token 和高熵字符串；
- 禁止构建制品、日志、测试快照包含凭据；
- 生产 Secret 不提供给 Fork PR；
- 受保护分支把安全检查设为 required。

**等级：P1**

- pipeline、registry、endpoint；

## 关闭条件

S-001 只有在以下条件全部满足后才能关闭：

1. 四类旧凭据均已撤销/轮换；
2. 调用、账单和资源变更核查完成；
3. 当前分支不再跟踪真实部署凭据；
4. 远端分支、Tag、PR/制品的历史清理已协调完成；
5. 全历史秘密扫描通过；
6. Agent 仓库的 PR/全历史秘密扫描已经设为合并门禁；生产开启还需满足 Agent/CLI/main 三仓 CI 要求。

任何单独一项，例如“已经删除一行”“已经加入 `.gitignore`”或“已经写了 Guard”，都不能把该事件标记为已解决。
