# AGENTS.md — 漫剧资产管理 Agent

## 项目概述

`short_drama_asset_agent` 是基于火山引擎 AgentKit / VeADK 构建的漫剧资产管理 Agent，提供知识库问答、长期记忆、资产入库、剧本拆解和 Skills 编排能力。部署于火山云华北 2（北京）地域。

## 架构

```
用户请求
    │
    ▼
AssetAwareRunProcessor（消息预处理）
    ├── 记忆类问题       → 注入 load_memory 提示
    ├── Skill 清单查询   → 注入当前 Skill 挂载状态
    ├── 外部能力调用     → 注入 execute_skills / mcp_router 路由提示
    ├── 资产入库         → 注入 mcp_router 入库路由提示
    └── 常规问题         → 知识库预检索 + 图片 URL 注入
    │
    ▼
root_agent（doubao-seed-2-0-pro）
    │
    ├── load_knowledgebase（AssetMetadataFirstLoad — 元数据优先排序）
    ├── load_memory（VikingDB 长期记忆）
    ├── script_breakdown（Sub-Agent，结构化输出：角色/场景/道具/分镜）
    ├── execute_skills（官方 Skills Sandbox，需要 AGENTKIT_TOOL_ID）
    └── mcp_router（外部 MCP 能力路由；知识入库也走这里）
```

### 工具挂载优先级

工具在 `factory.py:create_root_agent()` 中按以下顺序挂载到 `root_agent.tools`：

1. `AssetMetadataFirstLoadKnowledgebaseTool` — 替换默认 load_knowledgebase
2. `script_breakdown` (AgentTool) — 剧本拆解 Sub-Agent
3. `execute_skills` — 官方 Skills Sandbox（若有 AGENTKIT_TOOL_ID）
4. `mcp_router` — 外部 MCP 路由（含知识入库 skill 编排）

顺序影响模型函数调用选择：位置越前优先级越高。

## 运行时补丁说明

`runtime_patches.py` 在 `agent.py` 启动时通过 `apply_runtime_patches()` 调用，依次应用以下 Monkey Patch：

1. **json_schema 降级** — Ark 模型不支持 `response_format.type=json_schema`，自动转为 `json_object` + system prompt 约束
2. **推理内容提取** — 将模型返回的 `reasoning_content` 映射为 `thought=True` 的 Part
3. **请求日志安全序列化** — 防止循环引用导致 LiteLLM 日志崩溃
4. **Trace 安全序列化** — 防止 ADK telemetry 因循环 Content 崩溃
5. **LiteLlm 序列化** — 排除 `llm_client` 字段防止 dev metadata endpoint 报错
6. **Runner 空事件过滤** — 跳过运行时产生的 None event
7. **SQLite session 并发重试** — ADK Web 多请求时自动刷新 stale session 后重试
8. **ADK 附件默认保存** — 上传文件默认持久化为 artifact

## 关键设计决策

### 路由规则（必须遵守）

- **用户身份/偏好/历史** → `load_memory`，不查知识库
- **漫剧作品/角色/剧情/资产/标签** → 知识库
- **外部 skill / 工具调用** → `execute_skills` 优先，`mcp_router` 兜底
- **资产入库** → `mcp_router`（走 skill 编排中的入库工具，不走本地 `ingest_asset_to_knowledgebase`）
- **剧本拆解** → `script_breakdown` Sub-Agent（不先查知识库，除非用户要求结合已有资料）
- **不确定时** → 先 `load_memory`，再无结果查知识库

### 记忆库

- 使用 VikingDB 作为长期记忆后端（**不用 Mem0**，知识 ISSUE #5）
- `RaceTolerantVikingDBLTMBackend` 处理并发启动时 collection 创建竞争
- 通过 `after_agent_callback` 增量保存新事件到 LTM

### A2A 协议

- 同时支持 `message/stream`（SSE 流式）和 `message/send`（非流式）
- 通过自定义 `_convert_a2a_request_to_streaming_run_request` 按请求方法切换 Runner streaming_mode
- 兼容端点：`/list-apps`、`/apps/{app_name}`。`/debug/tools` 已移除；诊断只允许通过本地受控命令或日志完成。
